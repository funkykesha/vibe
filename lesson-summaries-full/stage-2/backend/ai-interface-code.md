## О чём урок
Урок показывает, как с помощью больших языковых моделей быстро писать надёжный backend-API на Node.js + Express, соответствующий отраслевым стандартам. Объясняется роль API как «официанта» между фронтендом и базой данных, а также как качественными промптами заставить AI генерировать не «воду», а рабочий код, документацию и тесты.

## Ключевые темы
- Зачем нужен API: разделение фронтенда и бэкенда, аналогия с рестораном (меню — фронтенд, склад — БД, официант — API).
- Структура проекта Node.js: routes, controllers, services, middlewares, `.env`, `server.js`, `docs/`.
- Инициализация проекта через промпт вместо ручного `npm init`.
- Написание CRUD-интерфейсов с подключением к Supabase: важность передачи AI полной схемы (Schema) и ограничений.
- Автоматическая генерация документации OpenAPI/Swagger по готовому коду.
- Тестирование: генерация коллекций Postman/Apifox и unit-тестов на Jest.

## Главные выводы
- БЯМ не боятся сложных требований, но боятся размытых: чем конкретнее контекст (поля, ограничения, структура), тем качественнее код.
- Многослойная архитектура (разделение ответственности) даёт чистый код вместо «спагетти».
- Лучшие практики обязательны даже с AI: RESTful-именование путей (URL — существительные, действие — через HTTP-метод), корректные коды статусов (200/201, 400, 401/403, 404, 500), и никогда не доверять вводу пользователя — валидация всегда на бэкенде.
- Разработчик становится не «машинисткой», а системным архитектором, делегируя рутину (документацию, тесты) AI.

## Инструменты и технологии
- Node.js, Express, Supabase SDK (`@supabase/supabase-js`)
- OpenAPI / Swagger
- Postman, Apifox, Jest
- Большие языковые модели (Claude Code, Trae, Cursor)
