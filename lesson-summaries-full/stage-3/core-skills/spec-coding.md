## О чём урок
Урок знакомит с парадигмой Spec Coding (разработка через спецификации), основанной на докладе Шона Грова (OpenAI) «The New Code». Главный тезис: код — это «потеря при проекции намерения», а настоящим «новым кодом» становится спецификация. Показано, как применять Spec-Driven Development в Claude Code через CLAUDE.md, каталог rules/ и команду `/plan`.

## Ключевые темы
- «The New Code» Шона Грова: код — лоссовая проекция намерения; суть программирования — коммуникация; кто пишет спецификацию, тот и программист; у спецификаций есть свой тулчейн (композиция, тесты, линтинг).
- Философия «всё есть Markdown»: CLAUDE.md, rules/, specs/, AGENTS.md — спецификация сама по себе является кодом.
- Vibe Coding vs Spec Coding: импровизация и прототипы против полной спецификации и продакшена; они не противопоставлены, а дополняют друг друга.
- Трёхуровневая структура спецификации: функциональная (What), архитектурная (How), языко-специфичная (реализация).
- Практика в Claude Code: CLAUDE.md как «живая спецификация», каталог rules/ для модульности, цикл `/plan` (Specify → Plan → Tasks → Implement), связка с Superpowers (TDD, code-review), версионирование спецификаций в Git.

## Главные выводы
- Спецификация — единственный источник истины (source of truth), а сгенерированный AI код — лишь черновая реализация; проверка обязательна.
- Способность писать спецификацию = способность программировать; навыки коммуникации важнее знания синтаксиса.
- Исполняемые спецификации не «гниют»: AI генерирует код прямо из них, поэтому устаревшая спецификация сразу даёт ломаную реализацию.
- Рекомендуемая стратегия — постепенный переход: Vibe-исследование → извлечение спецификации → Spec-перестройка продакшен-версии.

## Инструменты и технологии
- Claude Code: CLAUDE.md, .claude/rules/, specs/, AGENTS.md, /plan
- GitHub Spec Kit (Specify → Plan → Tasks → Implement), Superpowers
- Git-версионирование спецификаций, OpenAI Model Spec, Codex
