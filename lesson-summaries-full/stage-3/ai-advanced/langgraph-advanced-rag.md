## О чём урок
Урок разбирает, как спроектировать клиентский Agent коммерческого уровня с помощью подхода LangGraph. Акцент сделан не на коде, а на бизнес-логике: обработке исключений, эскалации на оператора, проектировании данных и границах вывода в продакшн. Ключевая идея: цель корпоративного Agent — не "ответить побольше", а "автоматизировать там, где можно, переспросить при неопределённости и передать оператору при высоком риске".

## Ключевые темы
- Бизнес-сторона: сначала решить, что система должна делать — какие вопросы частые, какие легко автоматизировать по правилам, какие слишком рискованны, какие требуют обращения к бизнес-системам.
- Поддержка как процесс смены состояний, а не чат-бот: распознавание типа проблемы, извлечение ключевых полей, проверка полноты информации, маршрутизация между базой знаний и бизнес-системой.
- Многоуровневая маршрутизация (как в Zendesk, Intercom, Salesforce): высокочастотные низкорисковые задачи, задачи с дозапросом информации, задачи с запросом к системе и задачи с обязательной эскалацией на оператора.
- Технические модули: классификация интента, извлечение полей, дозапрос информации, запрос к базе знаний, запрос к бизнес-системам, оценка риска, передача оператору.
- Данные и мониторинг трёх уровней: входные, бизнес-данные и операционные метрики (доля автоматического решения, доля эскалаций, время первого ответа, удовлетворённость).
- Обработка типичных badcase: ответ при неполной информации, имитация результата при таймауте, продолжение автоответов при явном недовольстве клиента.

## Главные выводы
- LangGraph подходит для поддержки, потому что поддержка по своей сути — задача смены состояний, а не "красивого общения".
- При неполной информации система должна остановиться и переспросить; вопросы по документам и по реальным данным нужно обрабатывать раздельно; высокорисковые вопросы нельзя "додумывать".
- Корпоративный уровень требует: чётких границ сервиса, механизма передачи оператору без повтора истории, аудита маршрутизации, постепенного выката с откатом и операционных метрик.
- Рекомендуемый порядок внедрения: начать с одного частого низкорискового сценария, писать сначала реальные пользовательские реплики, затем состояния и маршрутизацию, и только потом — сложную оркестрацию.

## Инструменты и технологии
- LangGraph, LangChain, LangSmith.
- Mermaid-диаграммы потоков и маршрутизации.
- Псевдокод на TypeScript для описания состояния (CustomerServiceState) и функций маршрутизации.
- Системы и платформы поддержки: Zendesk, Intercom, Salesforce, Front, Gorgias; кейсы Klarna, Minimal, Podium.
- Промпты для разбора задач, дозапроса информации и оценки риска/эскалации.
