## Why

Сейчас мануальные проверки часто требуют уточнений и ручного выбора следующих шагов. Нужен предсказуемый стандартный флоу, который всегда показывается пользователю и минимизирует дополнительные вопросы.

## What Changes

- Ввести единый "manual test flow" с фиксированными шагами: подготовка, запуск, валидация, expected outcomes, recovery.
- Всегда показывать этот флоу перед/после релевантных изменений, чтобы пользователь не собирал команды вручную.
- Добавить ветки auto-guidance для типовых исходов (успех, таймаут, daemon offline, launchctl fail) без запроса лишних уточнений.
- Добавить явный блок "что прислать назад", чтобы следующий шаг был детерминирован.

## Capabilities

### New Capabilities
- `guided-manual-test-flow`: стандартизованный always-on сценарий мануальных тестов с ожидаемыми результатами и fallback-действиями.

### Modified Capabilities
- `headless-daemon-mode`: расширение operational UX требованиями к обязательному manual-test guidance без лишних вопросов.

## Impact

- Affected artifacts/code:
  - `docs/` (runbook/manual test guide)
  - CLI UX messages (где уместно): ссылки на единый flow/next steps
  - возможно `MenuAgent`/`InstallCommand` подсказки для согласованности терминологии
- Affected behavior:
  - пользователь всегда получает один и тот же пошаговый сценарий проверки
  - меньше неопределенности и "что делать дальше?"
- Validation:
  - проверка полноты флоу на типовых сценариях (happy path + failure branches)
  - проверка, что флоу действительно выдаётся всегда в нужных точках.
