# Claude Code мобильная удалённая разработка

## Введение

Представьте эти сценарии: вы в метро по дороге на работу и вдруг вспомнили отличное решение для исправления бага; вы получили срочное сообщение об ошибке на production во время кофе-брейка; вы гуляете с девушкой и вам интересно как выглядит AI-построенный проект.

В традиционном режиме разработки эти сценарии означают что нужно найти место открыть компьютер, или жалко отложить дело. Но в эру AI-assisted программирования правила изменились. Claude Code позволяет нам упаковать развитие в карман, оставаться продуктивными в любом месте.

Летом 2025 года с распространением Claude Code разработчики начали исследовать разные способы "мобильного кодирования". От простого локального запуска Termux, до сложной SSH + Tailscale удалённой связи, до специальных Happy Coder приложений, постепенно сформировалась полная мобильная экосистема разработки.

Основной вопрос этого раздела: как позволить Claude Code следовать вашему смартфону, стать действительно "портативным помощником разработки в кармане".

> 💡 **Обзор обратной связи сообщества**
>
> На основе практики использования участников, сравнение опыта различных методов:
>
> **Happy Coder (Способ второй)**
> - ⚠️ Проблемы с стабильностью подключения: часто обрывы, контекст теряется после разрыва
> - ⚠️ Функция ограничена: невозможно использовать команды `/`
> - ⚠️ Вопросы безопасности: полагается на официальный relay сервер, некоторые опасаются за безопасность данных
>
> **HAPI (Способ третий)**
> - ✅ Может быть самостоятельно развёрнут сервер: поддержка развёртывания на собственном VPS
> - ✅ Использование с Tailscale даёт лучший опыт: компьютер запускает `hapi server`, смартфон подключается через Tailscale IP
> - ✅ Подключение относительно стабильнее, подходит для длительного использования
>
> **Claude Remote Control (официальный способ)**
> - ✅ Официальный продукт, исходная интеграция с Claude Code
> - ✅ Поддержка полного доступа к локальному окружению (MCP, инструменты, конфиг проекта)
> - ⚠️ Требует подписку Max (поддержка Pro скоро появится)
> - ⚠️ Полагается на облако Anthropic для подключения
>
> **Рекомендация**: если требуется высокая стабильность подключения, или волнует безопасность при использовании third-party relay, рекомендуется выбрать **HAPI + Tailscale** или **официальный Remote Control** способ.

## Основной принцип: архитектура мобильной разработки

Прежде чем представлять различные способы, разберёмся с сутью проблемы.

### Почему мобильная разработка это проблема?

Традиционная IDE (как VS Code, IntelliJ) требуют полное окружение операционной системы, мощный CPU, много памяти и хранилища. Хотя производительность смартфона растёт, но по опыту разработки всё ещё имеет природные ограничения:

**Ограничение ввода**: виртуальная клавиатура неэффективна для ввода кода, сложный синтаксис легко ошибиться

**Ограничение экрана**: маленький экран сложно одновременно видеть код, терминал и браузер

**Ограничение окружения**: смартфон не может запустить полный набор инструментов разработки (компилятор, БД, отладчик)

**Ограничение подключения**: мобильная сеть нестабильна, SSH подключение легко обрывается

### Основная идея: thin-client архитектура

Все способы мобильной разработки имеют одну основную идею: смартфон это только "пульт управления", реальная работа разработки проводится в другом месте.

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│    ┌─────────────┐              ┌─────────────┐             │
│    │   смартфон  │              │  хост/облако│             │
│    │ (управление)│   ────────►  │ (выполнение)│             │
│    │             │   команда/   │             │             │
│    │  • вводить  │   результат  │  • запуск   │             │
│    │  • смотреть │              │    CLI      │             │
│    │  • проверка │              │  • запуск   │             │
│    │  изменений  │              │    кода     │             │
│    │             │              │  • доступ   │             │
│    │             │              │    файлам   │             │
│    └─────────────┘              └─────────────┘             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

Эта архитектура позволяет смартфону отвечать только за "взаимодействие человека с машиной", отдать тяжёлую вычислительную работу на хост или облако.

## Способ первый: официальный iOS App

В октябре 2025 года Anthropic официально запустила Claude Code мобильную версию в iOS приложении, это самый простой способ мобильной разработки.

### Географические ограничения

⚠️ **Важное замечание**: Claude App в материке Китая **невозможно использовать напрямую**.

Если вы в Китае, рекомендуется прямо использовать **Happy Coder** (Способ второй), он может работать нормально через конфиг локального API relay сервера.

Если вы имеете заморскую Apple ID, можно переключить регион для скачивания Claude App.

### Принцип работы

```
┌─────────────┐                    ┌─────────────────┐
│  iOS App    │ ──────────────────► │  Anthropic облако│
│  (смартфон) │   HTTPS + OAuth     │  Claude Code    │
└─────────────┘                    └────────┬────────┘
                                           │
                                           ▼
                                   ┌───────────────┐
                                   │   GitHub API  │
                                   └───────────────┘
```

Ваше мобильное приложение только отправляет команды, все выполнение кода происходит в облачной песочнице Anthropic, результаты синхронизируются через GitHub.

### Базовое использование

**Предварительные условия**:

- iPhone iOS 15 или выше
- Подписка Claude Pro/Team/Enterprise (бесплатная версия не поддерживается)
- Аккаунт GitHub

**Шаги использования**:

1. Скачать Claude App из App Store
2. Вход в аккаунт Anthropic
3. В приложении найти вкладку "Code"
4. Через OAuth подключить свой GitHub репозиторий
5. Начать создавать задачи

### Плюсы и минусы

Преимущество это нулевая конфигурация, гладкий опыт, push уведомления. Недостатки это только iOS, в основном поддержка GitHub, функция относительно ограничена (не может получить доступ к локальной файловой системе), в Китае недоступно.

## Способ второй: Happy Coder

Happy Coder это open source мобильный и веб-клиент, разработанный для Claude Code и Codex, поддерживает end-to-end шифрование, позволяет контролировать AI помощник программирования из любого места.

### Принцип работы

```
┌─────────────┐              ┌─────────────┐              ┌─────────────┐
│  Happy App  │   ────────►  │ Happy Server │   ◄────────   │happy-coder  │
│(мобил/Web)  │ зашифр WS    │ (relay сервер)│  WebSocket   │  (компьютер)│
└─────────────┘              └─────────────┘              └──────┬──────┘
                                                               │
                                                               ▼
                                                        ┌─────────────┐
                                                        │Claude Code  │
                                                        │    CLI      │
                                                        └─────────────┘
```

На компьютере запусти `happy` вместо `claude` чтобы запустить AI помощник программирования. Когда нужно управлять со смартфона, сессия автоматически переключится в удалённый режим. На компьютере нажми любую клавишу можно переключиться назад в локальное управление.

### Установка и использование

**Шаг 1: Скачать приложение**

| Платформа | Ссылка |
|------|------|
| iOS | [App Store](https://apps.apple.com/us/app/happy-claude-code-client/id6748571505) |
| Android | [Google Play](https://play.google.com/store/apps/details?id=com.ex3ndr.happy) |
| Web | [app.happy.engineering](https://app.happy.engineering) |

**Шаг 2: Установить CLI на компьютер**

```bash
npm install -g happy-coder
```

**Шаг 3: Запустить и спаривать**

```bash
# В директории проекта запустить
cd ~/my-project
happy

# Отобразится код паров
```

**Шаг 4: Смартфон отсканировать код**

Открыть Happy App, отсканировать QR-код показанный на компьютере. После успешного спаривания можешь управлять Claude Code со смартфона.

**Шаг 5: Использование**

```bash
# Запустить Claude Code
happy

# Или запустить Codex
happy codex
```

### Справочные ссылки

- [GitHub проект](https://github.com/slopus/happy) - исходный код
- [Сайт документации](https://happy.engineering/docs) - документация использования
- [Discord сообщество](https://discord.gg/fX9WBAhyfD) - обсуждение сообщества

### Плюсы и минусы

Преимущество это простая конфигурация, кроссплатформенная поддержка, end-to-end шифрование, open source可审计. Недостатки это нужно полагаться на relay сервер third-party, мобильное приложение нужно самому проверить работоспособность.

## Способ третий: HAPI

HAPI это альтернатива Happy Coder, использует local-first философию дизайна, поддерживает беспрепятственное переключение между устройствами и несколько AI моделей.

### Принцип работы

```
┌─────────────┐              ┌─────────────┐              ┌─────────────┐
│  HAPI App   │   ────────►  │ HAPI Server │   ◄────────   │    hapi    │
│(мобил/PWA/  │  WireGuard   │(самостоят.  │  WireGuard   │(компьютер) │
│ Telegram)   │   + TLS      │  relay)     │   + TLS      │            │
└─────────────┘              └─────────────┘              └──────┬──────┘
                                                               │
                                                               ▼
                                                        ┌─────────────┐
                                                        │Claude Code  │
                                                        │/ Codex /    │
                                                        │Gemini и т.д.│
                                                        └─────────────┘
```

HAPI использует WireGuard вместе с TLS реализацию end-to-end шифрования, вся коммуникация через зашифрованный relay сервер. Ты можешь развёртывать собственный relay сервер, полностью контролировать поток данных.

### Основные особенности

- **Беспрепятственное переключение**: беспрепятственное переключение управления между компьютером и смартфоном, любую клавишу нажимаешь можешь переключиться назад в локальное управление
- **Native-first**: использует родную технологию упакования мобильного приложения, обеспечивает гладкое взаимодействие
- **AFK Approval**: когда вышел из офиса, смартфон может получить запросы на одобрение, не нужно прерывать рабочий процесс
- **Multi-model поддержка**: поддерживает Claude Code, Codex, Gemini, OpenCode и другие AI помощники программирования
- **Anytime Anywhere терминал**: через PWA, Telegram Mini App и другие способы доступа
- **Голосовое управление**: поддерживает голосовой ввод команд, освобождает руки

### Установка и использование

**Шаг 1: Запустить relay сервер**

```bash
# На вашем сервере запустить (или используйте npx прямо запустить)
npx @twsxtd/hapi hub --relay
```

**Шаг 2: Установить CLI на компьютер**

```bash
# В директории проекта запустить
cd ~/my-project
npx @twsxtd/hapi

# Или глобально установить
npm install -g @twsxtd/hapi
hapi
```

**Шаг 3: Спаривание устройств**

Следуй подсказкам в терминале, открыть HAPI App на смартфоне и отсканировать QR-код завершить спаривание.

**Шаг 4: Способы доступа**

| Способ доступа | Описание |
|---------|------|
| Web PWA | Открыть в браузере, поддержка установки на рабочий стол |
| Telegram Mini App | Используй внутри Telegram напрямую |
| Мобильное приложение | Родной опыт приложения (если выпущено) |

### Различие Happy Coder с HAPI

| Особенность | Happy Coder | HAPI |
|------|-------------|------|
| Философия дизайна | Облако-first | Local-first |
| Способ шифрования | WebSocket + E2E | WireGuard + TLS |
| Поддержка multi-model | Claude Code, Codex | Claude, Codex, Gemini, OpenCode |
| Способы доступа | iOS/Android/Web | PWA, Telegram, больше |
| Голосовое управление | ❌ | ✅ Поддержка |
| AFK Approval | ❌ | ✅ Поддержка |
| Самостоятельный relay | ⚠️ нужно ручное развёртывание | ✅ готово к использованию |

## Способ четвёртый: SSH + Tailscale + Tmux

Это наиболее подходящий способ для профессиональных разработчиков, через SSH удалённое подключение к компьютеру разработки, совместно с Tmux сохранение сессии.

### Принцип работы

```
┌─────────────┐              ┌─────────────┐              ┌─────────────┐
│   смартфон  │   ────────►  │  Tailscale  │   ◄────────   │   компьютер│
│(SSH client) │   VPN P2P    │ relay/nat-  │   VPN P2P    │(dev машина) │
└─────────────┘              └─────────────┘              └──────┬──────┘
                                                               │
                                                               ▼
                                                        ┌─────────────┐
                                                        │    Tmux     │
                                                        │ (сохранение │
                                                        │  сессии)    │
                                                        └─────────────┘
```

Tailscale создаёт peer-to-peer VPN сеть, позволяет тебе в любой сетевой обстановке прямо доступ к компьютеру дома. Tmux гарантирует что даже если SSH оборвётся, Claude Code всё ещё работает в фоне.

### Почему нужен Tailscale?

**Проблемы традиционного SSH подключения**:

```
Смартфон (4G) ──XX──> роутер NAT ──XX──> компьютер дома
              (не проходит)         (закрыта внутренняя сеть)
```

Твой компьютер во внутренней сети, смартфон во внешней сети не может прямой доступ. Традиционное решение это конфигурация port forwarding и динамический DNS, процесс сложный и имеет риск безопасности.

**Решение Tailscale**:

```
Смартфон (4G) ──► Tailscale relay ──◄── Компьютер дома
            (автоматическое nat-punchthrough или relay)
```

Tailscale использует nat-punchthrough технология, если punchthrough не получается будет автоматически использовать relay сервер, вся коммуникация зашифрована.

### Полные шаги конфигурации

**Шаг 1: На компьютере установить Tailscale**

```bash
# macOS
brew install --cask tailscale

# Или скачать инсталлер
# https://tailscale.com/download
```

**Шаг 2: Вход и получение IP**

```bash
# Запустить Tailscale
sudo tailscale up

# Посмотреть Tailscale IP
tailscale ip -4
# Вывод пример: 100.x.x.x
```

**Шаг 3: На смартфоне установить Tailscale**

Из App Store или Google Play скачать Tailscale, вход с тем же аккаунтом.

**Шаг 4: Установить и конфигурировать Tmux**

```bash
# macOS
brew install tmux

# Создать файл конфигурации ~/.tmux.conf
cat > ~/.tmux.conf << 'EOF'
# Включить поддержку мыши
set -g mouse on

# Установить режим терминала по умолчанию 256 цветов
set -g default-terminal "screen-256color"

# Изменить связующую клавишу на Ctrl+A (опционально)
unbind C-b
set -g prefix C-a

# Упрощённые горячие клавиши разделения панели
bind v split-window -h
bind h split-window
```

**Шаг 5: Создать persistent сессию**

```bash
# Создать сессию по имени "claude"
tmux new -s claude

# В этой сессии запустить Claude Code
cd ~/my-project
claude

# Отделить сессию (не закрывать)
# Нажмите Ctrl+B потом D
```

**Шаг 6: Смартфон SSH клиент подключение**

Рекомендуемые SSH клиенты:

| Клиент | Платформа | Особенность |
|--------|------|------|
| Blink Shell | iOS | Поддержка MOSH, подходит для нестабильной сети |
| Termius | iOS/Android | Кроссплатформенный, красивый интерфейс |
| a-Shell | iOS | Бесплатный, лёгкий |

Конфигурация подключения:

```
Host: 100.x.x.x (твой Tailscale IP)
Port: 22
Username: имя пользователя компьютера
```

После подключения присоедини к Tmux сессии:

```bash
tmux attach -t claude
```

### Продвинутые приёмы

**Предотвращение сна компьютера**:

```bash
# macOS
caffeinate -dimsu &

# Или установить в системные параметры > энергия > предотвращение автосна
```

**Использование MOSH для нестабильной сети**:

MOSH (Mobile Shell) это SSH замена оптимизированная для мобильной сети, поддержка переключение сети без потери сессии.

```bash
# На компьютере установить
brew install mosh

# На смартфоне использовать MOSH подключение
# Blink Shell исходная поддержка MOSH
```

**Скрипт одного клика подключение**:

В SSH клиенте установить команду запуска:

```bash
tmux attach -t claude || tmux new -s claude
```

Таким образом после подключения автоматически присоедини к существующей сессии или создай новую.

### Плюсы и минусы

Преимущество это полная функциональность, опыт совпадает с настольным, поддержка всех инструментов разработки. Недостатки это конфигурация относительно сложная, требует компьютер постоянно включён.

## Способ пятый: Termux локальный запуск

Если ты Android пользователь, можешь запустить Claude Code прямо на смартфоне без подключения к внешним устройствам.

### Принцип работы

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│                    ┌─────────────┐                          │
│                    │   Termux    │                          │
│                    │(Linux окру.) │                         │
```

## Способ шестой: Claude Code UI

Claude Code UI (также зовётся CloudCLI) это open source проект, предоставляет веб-интерфейс для Claude Code, поддержка доступа через мобильный браузер.

### Принцип работы

```
┌─────────────┐              ┌─────────────┐              ┌─────────────┐
│ мобильный   │   ────────►  │ Веб сервер  │   ◄────────   │Claude Code  │
│ браузер     │   HTTP/HTTPS │(localhost)  │   вызов      │    CLI      │
└─────────────┘              └─────────────┘              └─────────────┘
```

На компьютере запустить веб сервер, смартфон через браузер доступ. Это требует внутренней сети пробива или локальной сети доступ.

### Установка и использование

**Шаг 1: Установка**

```bash
# Один клик запуск (рекомендуется)
npx @siteboon/claude-code-ui

# Или глобально установить
npm install -g @siteboon/claude-code-ui
claude-code-ui
```

**Шаг 2: Доступ к интерфейсу**

Сервер запускается по умолчанию на `http://localhost:3001`

**Шаг 3: Смартфон доступ**

Способ A - локальной сети доступ (в одной WiFi):

```bash
# При запуске привязать все интерфейсы
claude-code-ui --host 0.0.0.0

# Смартфон доступ
http://локальный_IP_компьютера:3001
```

Способ B - использовать ngrok внутренней сети пробива:

```bash
# Установить ngrok
brew install ngrok

# Запустить туннель
ngrok http 3001

# Смартфон доступ по URL ngrok
```

### Функция

- Адаптивный дизайн, поддержка мобильного
- Встроенный интерфейс чата
- Обозреватель файлов
- Git интерфейс операций
- Управление сессиями

### Плюсы и минусы

Преимущество это есть графический интерфейс, полная функциональность. Недостатки это требует внутренней сети пробива (除了 локальной сети), конфигурация относительно сложная.

## Способ седьмой: облачное окружение разработки

Если у тебя нет компьютера всегда включённого, можешь использовать облачное окружение разработки, Claude Code запускается на облачном сервере.

### Принцип работы

```
┌─────────────┐              ┌─────────────┐              ┌─────────────┐
│  смартфон   │   ────────►  │ облачный    │   ─────────► │Claude Code  │
│(браузер/App)│   HTTPS      │ контейнер   │               │    CLI      │
└─────────────┘              └─────────────┘              └─────────────┘
```

Облачный контейнер имеет предустановленный Claude Code, ты через браузер или приложение смартфона доступ.

### Использование Sealos DevBox

**Шаг 1: Создание окружения**

Посетить [Sealos DevBox](https://sealos.io/devbox), выбрать Claude Code шаблон создать окружение.

**Шаг 2: Запуск окружения разработки**

Примерно 30-60 секунд позже окружение готово, ты получишь веб терминал.

**Шаг 3: Конфигурировать Claude API**

```bash
export ANTHROPIC_API_KEY="your-api-key"
```

**Шаг 4: Подключение Happy App**

```bash
# Установить happy-coder (уже предустановлен)
npm install -g happy-coder

# Генерировать код спаривания
happy
```

Смартфон отсканировать код потом можешь использовать.

### Сравнение облачных методов

| Платформа | Claude Code | Оптимизация мобилей | Время запуска | Цена |

| Gitpod | ⚠️ Ручная | ⚠️ Браузер | ~1-2мин | Бесплатно+по часам |
| Replit | ❌ | ✅ Родное App | Мгновенно | Бесплатно+подписка |

### Плюсы и минусы

Преимущество это не нужен локальный компьютер, окружение совпадает, расширяемо. Недостатки это требует оплата, полагается на сеть, код в облаке.

## Сравнение методов и выбор

Различные методы имеют свои особенности, подходят для разных сценариев.

### Таблица сравнения

| Метод | Сложность | Нужна внутренняя сеть пробива | Стоимость | Применимый сценарий |
|------|------|-------------|------|----------|
| iOS официальное приложение | Простой | ❌ | $20/месяц | Быстрая проверка, простые задачи |
| Happy Coder | Средний | ❌ | Бесплатно | Дневное использование, удобство |
| HAPI | Средний | ❌ | Бесплатно | Multi-model поддержка, local-first |
| SSH + Tailscale | Сложный | ❌ | Бесплатно | Профессиональная разработка, полная функциональность |
| Termux | Средний | ❌ | Бесплатно | Android локальная разработка |
| Claude Code UI | Средний | ✅ Нужна | Бесплатно | Требуется веб интерфейс |
| Облако DevBox | Простой | ❌ | По количеству | Нет локального компьютера |

### Руководство по выбору

**Если в Китае**: рекомендуется использовать **Happy Coder**, может работать нормально через конфиг локального API relay сервера.

**Если приоритет удобство**: Happy Coder самый беззаботный, отсканировать и использовать.

**Если нужна поддержка multi-model**: HAPI поддержка несколько AI помощников программирования, подходит для разработчиков нуждающихся в переключении между разными моделями.

**Если постоянно включённый компьютер**: SSH + Tailscale лучший выбор, опыт совпадает с настольным.

**Если iPhone пользователь (не в Китае)**: официальное приложение самый простой способ начать.

**Если только Android смартфон**: Termux позволяет полностью разработка на смартфоне.

**Если нет компьютера**: облако DevBox идеальный выбор.

## Безопасность и приватность

Мобильная разработка включает передачу кода через сеть, требует особое внимание к безопасности.

### Риск relay сервера

При использовании Happy Coder, HAPI и других требующих relay услуг, рассмотри следующие вопросы:

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  Relay сервер может видеть что?                             │
│                                                             │
│  • Данные до шифрования (если end-to-end не правильно)     │
│  • Метаданные (когда подключаться, как долго)              │
│  • API ключи (если конфигурация не правильная)             │
│                                                             │
│  Relay сервер может делать что?                             │
│                                                             │
│  • Записывать содержание твоего кода                        │
│  • Воровать API ключи                                       │
│  • Вводить вредоносные команды                             │
│  • Использовать твой компьютер как узел атаки на других    │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Лучшие практики безопасности

**1. Классификация кода по чувствительности**

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  Открытый проект/учебный код ──► любой метод подходит      │
│                                                             │
│  Приватный проект ──► рекомендуется SSH+Tailscale или      │
│                      самостоятельный relay                 │
│                                                             │
│  Коммерческий код ──► только SSH+Tailscale, запретить      │
│                      все relay third-party                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**2. Управление ключами**

```bash
# ❌ Не hardcode ключи в коде
const apiKey = "sk-ant-xxxxx"

# ✅ Используй переменные окружения
const apiKey = process.env.ANTHROPIC_API_KEY

# ✅ Используй .env файл (добавить в .gitignore)
ANTHROPIC_API_KEY=sk-ant-xxxxx
```

**3. Используй песочницу**

Claude Code поддержка песочница режим, ограничить доступ:

```bash
claude --sandbox /path/to/project
```

**4. Самостоятельный relay**

Если используешь Happy Coder, можешь разместить собственный relay сервер:

```bash
# Клонировать проект (включаёт серверный код)
git clone https://github.com/slopus/happy.git
cd happy

# Развернуть серверный код на твой VPS
# Подробные шаги см. документацию проекта
```

**5. Используй Headscale**

Headscale это open source реализация Tailscale, может самостоятельно разместить relay сервер:

```bash
# Docker один клик развёртывание
docker run -d \
  --name headscale \
  -v /srv/headscale:/etc/headscale \
  -p 3478:3478/udp \
  -p 8080:8080 \
  headscale/headscale:latest
```

## Часто задаваемые вопросы

### Нужна ли внутренняя сеть пробива?

Большинство современных методов **не нужна** внутренняя сеть пробива:

| Метод | Принцип |
|------|------|
| Happy Coder | Relay модель, обе стороны инициативно подключаются к серверу |
| HAPI | Relay модель, WireGuard + TLS |
| Tailscale | NAT punchthrough или relay |
| iOS App | Облако выполнение |
| Claude Code UI | Нужна (пассивный входящий трафик) |

### Почему relay модель не нужна пробива?

```
Активный исходящий (NAT позволяет):
Компьютер ──► relay сервер ✓

Активный входящий (NAT блокирует):
Внешний ──► компьютер ✗

Умность relay модели:
Обе стороны инициативно подключаются к relay серверу, оба не нужны входящие!
```

### Влияет ли мобильная разработка на батарею?

Различные методы потребление энергии разное:

| Метод | Потребление | Причина |
|------|--------|------|
| SSH терминал | Низкое | Только текст отображение |
| iOS App | Среднее | Облако выполнение, смартфон только контроль |
| Termux | Высокое | Локальный запуск CLI |
| Браузер | Среднее | Веб интерфейс рендеринг |

Рекомендуется длительное использование подключи зарядное устройство.

### Сетевой разрыв что будет?

| Метод | Влияние разрыва сети |
|------|-------------|
| SSH + Tmux | Claude продолжает работать, переподключение потом можешь восстановиться |
| Happy Coder | Автоматическое переподключение |
| HAPI | Автоматическое переподключение |
| iOS App | Облако продолжает, App уведомит о разрыве |
| Termux | Сессия прерывается |

### Может ли быть на смартфоне компиляция больших проектов?

Не рекомендуется. Смартфон CPU и память ограничены, компиляция больших проектов приведёт:

- Смартфон очень горячий
- Батарея быстро расходуется
- Компиляция занимает слишком долго

Рекомендуется компиляцию на удалённом сервере или облаке.

## Итоги

Основная идея Claude Code мобильной разработки: **смартфон это только управляющая сторона, настоящая разработка работа в другом месте**.

Выбор метода зависит от твоих конкретных требований.

Если в Китае, рекомендуется **Happy Coder**, конфиг локального API relay.

Если хочешь максимум беззаботности, используй **Happy Coder**. Отсканировать и использовать, push уведомления, плавное переключение устройств.

Если нужна поддержка multi-model или local-first дизайн, используй **HAPI**. Поддержка несколько AI помощников, может самостоятельный relay.

Если хочешь максимум полный опыт разработки, используй **SSH + Tailscale**. Конфиг немного сложнее, но функциональность наиболее полная, опыт совпадает с настольным.

Если iPhone пользователь (не в Китае), **официальное приложение** самый простой способ начать.

Если только Android смартфон, **Termux** позволяет полностью разработка на смартфоне.

Если нет постоянно включённого компьютера, **облако DevBox** идеальный выбор.

Независимо от выбора метода, обязательно помним безопасность: чувствительный код осторожно с third-party relay, API ключи правильное управление, важные проекты лучше использовать самостоятельный relay.
