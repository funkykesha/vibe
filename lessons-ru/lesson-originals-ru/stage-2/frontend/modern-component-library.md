# Обновление интерфейса с помощью современной библиотеки компонентов

<!-- nav -->
**📚 Версии:** [Кратко](../../../lesson-summaries/stage-2/frontend/modern-component-library.md) · [Расширенно](../../../lesson-summaries-full/stage-2/frontend/modern-component-library.md) · **Полный перевод** · [Оригинал 中文](https://github.com/datawhalechina/easy-vibe/blob/main/docs/zh-cn/stage-2/frontend/modern-component-library/index.md)


В предыдущих уроках вы уже научились использовать дизайн-инструменты для создания макетов, превращать их в код с помощью AI IDE и даже завершили полноценный фронтенд-проект. Но вы наверняка заметили одну закономерную проблему: кнопки, формы и модальные окна, написанные с нуля, пусть и работают, но всегда кажутся чуть хуже «профессионального продукта» — стиль недостаточно единообразен, интерактивные детали не до конца отшлифованы, адаптация под разные экраны отнимает силы.

Именно эту проблему решает **библиотека компонентов**.

Библиотека компонентов — это набор заранее спроектированных и разработанных UI-элементов. Кнопки, поля ввода, выпадающие меню, диалоги, таблицы... все эти элементы интерфейса, которые встречаются в любом продукте снова и снова, уже готовы и проверены тысячами пользователей. Вам остаётся лишь собирать их, как конструктор, и профессиональный интерфейс готов.

## Что вы узнаете

1. Понять, что такое фронтенд-библиотека компонентов и почему современная разработка почти всегда её использует
2. Познакомиться с четырьмя наиболее репрезентативными библиотеками и узнать, для каких сценариев каждая из них подходит лучше всего
3. На трёх практических примерах (лендинг, страница продукта, панель администратора) освоить Vibe Coding с AI IDE + библиотека компонентов
4. Научиться читать документацию библиотеки компонентов, находить нужные компоненты и правильно их использовать

## 1. Зачем нужна библиотека компонентов?

Представьте, что вы делаете ремонт. Можно смастерить стул из досок самому, но обычно проще купить его в IKEA — хорошо спроектирован, качество стабильное, инструкция понятная, пришли домой и собрали.

Библиотека компонентов — это «IKEA» для фронтенд-разработки. Только вместо мебели она предоставляет элементы интерфейса:

| Писать всё самому | Использовать библиотеку компонентов |
| :--- | :--- |
| Нужно самостоятельно прорабатывать стили, поведение и анимации | Готово к использованию: стили и поведение уже отшлифованы |
| Кнопки на разных страницах могут выглядеть по-разному | Глобальный стиль единообразен — согласованность поддерживается автоматически |
| Адаптация под мобильный и планшет требует отдельных усилий | В большинстве библиотек встроена адаптивная поддержка |
| О доступности (Accessibility) легко забыть | Профессиональные библиотеки уже решили вопросы клавиатурной навигации и скрин-ридеров |
| Скорость разработки низкая | Скорость разработки высокая — фокус на бизнес-логике |

Кратко: **библиотека компонентов позволяет тратить время на «что делать», а не на «как нарисовать».**

## 2. Четыре ключевых библиотеки компонентов

Библиотек компонентов существует очень много (полный список — в [Приложении](#приложение-обзор-дополнительных-библиотек-компонентов)), но для начала достаточно познакомиться с этими четырьмя:

| Библиотека | Фреймворк | Краткое описание | Сайт |
| :--- | :--- | :--- | :--- |
| [Ant Design](https://ant.design) | React | Разработана командой Ant Group, де-факто стандарт для корпоративных бэк-офисных систем, охватывает огромный спектр компонентов | ant.design |
| [shadcn/ui](https://ui.shadcn.com) | React | Не устанавливается через npm — код компонентов копируется прямо в проект; основана на Tailwind CSS; максимальная гибкость кастомизации | ui.shadcn.com |
| [HeroUI](https://heroui.com) (бывш. NextUI) | React | Великолепный внешний вид по умолчанию и плавные анимации; отлично подходит для лендингов и продуктовых витрин с высокими требованиями к визуалу | heroui.com |
| [Material UI](https://mui.com) | React | Старейшая React-библиотека, реализует Google Material Design; самая зрелая экосистема | mui.com |

> Пользователи Vue также имеют богатый выбор: [Element Plus](https://element-plus.org) (наиболее популярна в России и СНГ), [Ant Design Vue](https://antdv.com), [Naive UI](https://www.naiveui.com) и другие — подробности в [Приложении](#приложение-обзор-дополнительных-библиотек-компонентов).

Каждая библиотека компонентов сильна в своём сценарии. Ниже мы разберём три реальных сценария разработки и покажем, как вести Vibe Coding с AI IDE + библиотека компонентов.

Чтобы показать разные стили и особенности, в каждом сценарии намеренно используется разная библиотека. Но помните: **это сделано лишь для того, чтобы вы познакомились с несколькими вариантами**. В реальной разработке вполне можно ограничиться одной любимой библиотекой. Если вам нравится shadcn/ui — используйте её и для лендинга, и для продуктовой страницы, и для бэк-офиса. Главное — выбрать ту, которая вам нравится и с которой комфортно работать.

## 3. Практика 1: лендинг на HeroUI

**Сценарий**: вы создали AI-ассистент для писателей и хотите красивый лендинг, чтобы продемонстрировать возможности продукта и привлечь пользователей. Лендингу нужна визуальная выразительность, плавные анимации и хороший вид на мобильных устройствах.

**Почему HeroUI**: стандартные стили HeroUI уже выглядят великолепно, в библиотеке встроены плавные переходы и анимации — она идеально подходит для витринных страниц, ориентированных на пользователя.

## 4. Практика 2: продуктовая страница на shadcn/ui

**Сценарий**: основной интерфейс AI-ассистента для писателей после авторизации — слева список документов, справа редактор, сверху панель инструментов. Это функциональная страница продукта с высокими требованиями к кастомизации UI.

**Почему shadcn/ui**: shadcn/ui кладёт код компонентов прямо в ваш проект, и вы можете изменить любую деталь. Для продуктовых интерфейсов с глубокой кастомизацией модель «вы владеете кодом» — наиболее гибкая.

### 4.1 Создание проекта

```bash
# Создать проект Next.js
npx create-next-app@latest ai-writer-app --typescript --tailwind --app
cd ai-writer-app

# Инициализировать shadcn/ui
npx shadcn@latest init

# Добавить нужные компоненты (не все сразу)
npx shadcn@latest add button card input sidebar sheet dialog
```

Особенность shadcn/ui: каждый раз, когда вы выполняете `add`, исходный код компонента копируется в папку `components/ui/` вашего проекта. Вы можете открыть эти файлы и изменить стили и поведение напрямую.

### 4.2 Генерация продуктового интерфейса с помощью AI IDE

```text
Пожалуйста, сделай главный интерфейс AI-ассистента писателя, используя библиотеку компонентов shadcn/ui:

**Общий макет:**
- Слева — сворачиваемая боковая панель шириной ~280px:
  - вверху кнопка «Новый документ»
  - ниже — список документов, каждый с заголовком и временем последнего редактирования
  - правый клик по документу открывает меню «Переименовать» / «Удалить»
- Справа — главная рабочая область, разделённая на верхнюю и нижнюю части:
  - сверху — панель инструментов: поле редактирования заголовка, счётчик слов, кнопка «AI продолжить», выпадающее меню «Экспорт»
  - снизу — область редактирования: большое текстовое поле, занимающее всё доступное пространство

**Детали взаимодействия:**
- После нажатия «AI продолжить» кнопка показывает состояние загрузки, а внизу редактора появляется текст от AI (посимвольно, как на печатной машинке)
- На мобильных устройствах боковая панель превращается в выезжающий ящик слева
- Текущий выбранный документ должен быть выделен подсветкой
```

### 4.4 Кастомизация стилей компонентов

Преимущество shadcn/ui в том, что вы можете напрямую менять исходный код компонентов. Например, чтобы сделать кнопки с более скруглёнными углами:

```text
Пожалуйста, измени components/ui/button.tsx:
замени скругление углов по умолчанию с rounded-md на rounded-xl
и добавь subtle-эффект тени для варианта primary
```

AI изменит файл компонента в вашем проекте, а не переопределит стили npm-пакета — в этом и состоит преимущество «владения кодом» в shadcn/ui.

## 5. Практика 3: панель администратора на Ant Design

**Сценарий**: после запуска AI-ассистента для писателей понадобится административная панель для просмотра данных пользователей, управления документами и обработки платёжных заказов. Ключевые задачи бэк-офиса — отображение данных и операционная эффективность.

**Почему Ant Design**: Ant Design глубоко проработана для бэк-офисных систем — таблицы, формы, графики и другие бизнес-компоненты работают сразу из коробки; встроено множество корпоративных паттернов взаимодействия (пакетные операции, расширенные фильтры, экспорт данных и т. д.).

- Четыре карточки статистики вверху: всего пользователей, новых сегодня, активных, платящих
- Область поиска и фильтрации: поиск по имени пользователя, выбор диапазона дат регистрации, фильтр по статусу, кнопки «Найти» и «Сбросить»
- Таблица пользователей:

## 6. Как читать документацию: «инструкция» к библиотеке компонентов

При Vibe Coding AI пишет большую часть кода, но когда результат неверен или нужно точно настроить поведение компонента, **чтение документации** — самый быстрый способ разобраться.

Рассмотрим на примере Ant Design. Адрес документации: `https://ant.design/components/overview-cn`

Стандартный порядок работы с документацией:

1. **Сформулировать задачу**: например, «нужна таблица с возможностью выбора строк»
2. **Найти нужное в документации**: поиск по запросу «Table», переход на страницу компонента таблицы
3. **Изучить примеры**: в документации у каждого компонента есть несколько интерактивных примеров — найдите пример «Выбор строк»
4. **Скопировать код**: скопируйте пример в свой проект
5. **Изучить таблицу API**: в нижней части страницы найдите полный список параметров `rowSelection`

> Вы также можете передать ссылку на документацию прямо в AI IDE: «Руководствуясь API rowSelection из https://ant.design/components/table-cn, добавь в таблицу пользователей функцию пакетного выбора». Когда AI получает ссылку на документацию, генерируемый код становится точнее.

Быстрый справочник по документации библиотек компонентов:

| Библиотека | Адрес документации |
| :--- | :--- |
| Ant Design | `https://ant.design/components/overview-cn` |
| shadcn/ui | `https://ui.shadcn.com/docs/components` |
| HeroUI | `https://heroui.com/docs/components` |
| Material UI | `https://mui.com/material-ui/all-components/` |
| Element Plus | `https://element-plus.org/zh-CN/component/overview.html` |

## 7. Итоги

Три практических сценария охватывают наиболее распространённые задачи фронтенд-разработки:

| Сценарий | Рекомендуемая библиотека | Ключевые преимущества |
| :--- | :--- | :--- |
| Лендинг / витринная страница | HeroUI | Красивые стили по умолчанию, плавные анимации, высокая визуальная выразительность |
| Функциональная страница продукта | shadcn/ui | Полный контроль над кодом, максимальная гибкость кастомизации |
| Система администрирования | Ant Design | Богатый набор бизнес-компонентов, таблицы и формы готовы из коробки |

Рабочий процесс Vibe Coding:

1. Выбрать подходящую библиотеку компонентов под сценарий
2. Описать желаемую структуру страницы и поведение в AI IDE
3. AI генерирует первоначальный код, вы смотрите на результат
4. Продолжить итерации и правки на естественном языке
5. При детальных вопросах обращаться к документации библиотеки
