# Как заставить Claude Code работать долго

> Этап 3 · Ключевые навыки

## О чём урок
Традиционные AI-помощники работают в диалоговом режиме: спросил — ответил — остановился. Для реальных задач этого мало: AI часто останавливается «слишком рано», решив, что «вроде готово». Урок объясняет, как заставить Claude Code работать в цикле и продолжать, пока задача действительно не будет выполнена, на примере техники Ralph Wiggum и других методов.

## Ключевые темы
- Корень проблемы: LLM не способен объективно оценить завершённость работы, поэтому нужен внешний контур проверки, а не «ощущение» AI.
- Метод 1 — While True Bash Loop: простейший бесконечный цикл из 5 строк, перезапускающий Claude с одним и тем же PROMPT.md; безопасная версия с лимитом итераций.
- Метод 2 — Ralph Wiggum (официальный плагин): механизм Stop Hook перехватывает выход, проверяет маркер завершения (`--completion-promise`) и заново внедряет промпт; параметр `--max-iterations` как защита.
- Метод 3 — расширенный Ralph: двойное условие выхода, ограничение скорости, умный предохранитель, дашборд.
- Методы 4 и 5: Agent Teams (параллельные агенты) и фоновые задачи (`Ctrl+B`, `/tasks`).
- Механизмы безопасности: жёсткие лимиты, обнаружение «зацикливания», оповещения о стоимости, ручные контрольные точки.

## Главные выводы
- Ключевая идея — не «выполнить за один раз», а «продолжать пытаться, пока действительно не готово».
- Качество промпта решает всё: нужны поэтапные требования, объективные критерии приёмки и уникальный маркер завершения.
- Ralph подходит для задач с чёткими критериями (миграция тестов, рефакторинг, добавление типов) и не подходит для архитектурных, исследовательских и творческих задач.
- Автоматический цикл обязательно должен иметь защиту от бесконечной работы и неконтролируемых расходов API.

## Инструменты и технологии
- Claude Code, Ralph Wiggum plugin, Stop Hook
- Bash-циклы, PROMPT.md, `--max-iterations`, `--completion-promise`
- frankbria/ralph-claude-code (расширенная версия), Agent Teams, фоновые задачи (Ctrl+B, /tasks)
