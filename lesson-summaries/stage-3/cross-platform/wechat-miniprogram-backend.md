# Как создать WeChat-мини-программу с бэкендом

> Этап 3 · Кроссплатформенная разработка

## О чём урок
Урок объясняет, как перейти от «фронтенд-онли» мини-программы к полноценному продукту с серверной частью: с логином, синхронизацией данных, загрузкой файлов, заказами и оплатой. Рекомендуемый путь по умолчанию — WeChat-мини-программа в связке с облачной разработкой (微信云开发 / CloudBase).

## Ключевые темы
- Трёхслойная архитектура: фронтенд (UI), бизнес-логика (заказы, права, оплата), слой данных и ресурсов.
- Что обязательно держать на сервере: ключи и секреты, проверка прав, оформление и подпись платежей, бизнес-правила (цена, склад, баллы), модерация контента.
- Три маршрута: A — облачная разработка (по умолчанию для новичков), B — облачный хостинг / HTTP-сервис (для средней сложности), C — полностью свой бэкенд (только при организационных требованиях).
- Пошаговый SOP с CloudBase: инициализация окружения, простейшая облачная функция (getCurrentUser), перенос записи в БД на сервер, правила безопасности, загрузка файлов в облачное хранилище.
- Платежи и безопасность как обязательные части «лучшей практики».

## Главные выводы
- Фронтенд — это вход, бэкенд — это судья: фронтенд только собирает параметры и показывает результат.
- Любая логика с ключами, правами, суммами или неизменяемыми правилами не должна быть на фронтенде.
- Платежи: оформление и подпись только на сервере, итоговый статус заказа — по серверному коллбэку, а не по всплывающему окну на фронтенде.
- Безопасность по умолчанию: запрет на всё, затем минимально необходимые права; правила безопасности БД и функций обязательны.
- Для новичка важен не «идеальный длинный prompt», а маленькие проверяемые шаги.

## Инструменты и технологии
- WeChat Cloud Development / CloudBase: облачные функции, облачная БД, облачное хранилище, модерация контента.
- wx.cloud.callFunction / wx.cloud.callContainer, getWXContext(), wx.requestPayment.
- Облачный хостинг (云托管) для Express/NestJS/FastAPI, WeChat Pay.
