# Jarvis — архитектура и роадмап

Голосовой диспетчер поверх всех окон на Mac, оркеструющий Codex-агентов,
работающих параллельно в фоне.

**/goal:** голосовой диспетчер, который ведёт список задач и делегирует что
угодно Codex-агентам, работающим параллельно в фоне.

## Принципы

- Overlay-виджет всегда поверх всего, в т.ч. полноэкранных Spaces.
- Голос — основной интерфейс; клик — резервный/управляющий.
- Ассистент сам решает: ответить или делегировать. Инструменты дёргаются по
  необходимости, а не на каждую реплику.
- Делегирование асинхронно: запустил Codex → продолжаем разговор.

## Контейнеры (C4-ish)

| Контейнер | Тех. | Роль |
|-----------|------|------|
| **Overlay-виджет** | Python, PyObjC, NSPanel | Плавающая микро-кнопка + поле ввода поверх всех окон |
| **Ядро диспетчера** | Python | Роутер реплик, состояние звонка, проводка |
| **Голосовой слой** | внешн. (Handy → текст; далее Gemini Live) | Голос ↔ текст; позже — потоковый диалог и tool-use |
| **Codex-оркестратор** | iTerm + AppleScript (итер.1) → Codex App Server (итер.4) | Запуск/ведение сессий агентов |
| **Локальный стор** | JSON | `~/.config/jarvis/` — конфиг, позже статусы задач |

## Поток (итерация 1)

```
клик ──► звонок ──► Handy диктует в поле ──► router.classify
                                              ├─ DELEGATE → codex_launcher (iTerm tab, async)
                                              ├─ ANSWER   → (заглушка; позже — голосовой ответ)
                                              └─ HANGUP   → конец звонка
```

`router.py` — это шов, куда позже встанет LLM-слой с tool-use вместо эвристик.
`voice.py::VoiceProvider` — шов для замены источника голоса.

## Роадмап (7 итераций)

1. **Базовый прототип** — overlay-виджет + запуск Codex CLI по голосу.
   *(текущая итерация)*
2. **Фиксы UX overlay** — перетаскивание мышью; видимость поверх полноэкранных
   окон (collection behavior + screen-saver level).
3. **Дизайн через MCP-генератор** — self-built MCP, генерирующий случайные
   промпты (цвета, эпоха, настроение…) → уникальный стиль каждый прогон; финал —
   «жидкое стекло» в духе Apple, полупрозрачный (`NSVisualEffectView`).
4. **Менеджмент сессий** — статусы задач (в процессе / готово), докидывание
   промптов на лету в живую сессию (перехват без остановки). Переезд с CLI на
   **Codex App Server** → 100% покрытие фич и отображение сессий в десктоп-апке.
5. **Доска задач** — вкладка с задачами, сгруппированными по проектам; передача
   задачи в Codex в один клик.
6. **Уведомления** — на все состояния тасок; нотификация висит на виджете, пока
   не откроешь.
7. **Субагенты-проверяющие** — агенты-разработчики + агенты-тестеры; задача
   закрывается только когда тестеры подтвердили результат.

## Сознательные упрощения итерации 1

- Решение «ответить vs делегировать» — регулярки, не LLM.
- «Ответить» — заглушка (нет голосового ответа): голосовой диалоговый бэкенд
  приходит позже.
- Codex через iTerm AppleScript, без App Server (нет статусов сессий).
- Нет доски задач, уведомлений, субагентов.
- Один звонок за раз; нет персистентного списка задач.

## Ограничения платформы

- AppKit/NSPanel требует реального main-thread NSApplication — UI-слой не
  импортируется и не тестируется в Linux/CI.
- Codex-запуск завязан на iTerm2 (адаптер на другие терминалы — позже).
- Секреты (ключи будущих голосовых бэкендов) только из окружения, не из конфига.
