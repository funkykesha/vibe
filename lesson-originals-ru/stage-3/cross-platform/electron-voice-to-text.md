# Как разработать кроссплатформенную Electron приложение — приложение голос в текст

# Глава 1: Что такое Electron и разработка приложений для рабочего стола

В этом учебнике мы пройдём полный цикл: с нуля используя Electron создать голос-в-текст приложение для рабочего стола, поддержка облачного API и локальной модели два способа распознавания, в конце упаковать в устанавливаемую программу рабочего стола, работающую на Windows, macOS, Linux.

Для этого учебника вам понадобится минимум:

- Компьютер (Windows или Mac, рекомендуется Mac, потому что Apple Silicon работает очень быстро для локальной модели)
- Node.js (версия 18.0 и выше)
- Ваш AI помощник по программированию (Cursor / Trae / Claude Code)
- (Опционально) OpenAI API Key (если использовать облачный режим)
- Микрофон (встроенный на ноутбук можно)

## 1.1 Что такое Electron?

**VS Code, Slack, Discord, Notion**, которые вы используете каждый день, они имеют общую черту: все они созданы с помощью **Electron**.

Electron — это открытая рамка, позволяющая вам использовать **HTML + CSS + JavaScript** (это же технологию создания веб-страницы) для создания программ рабочего стола, совместимых с тремя платформами **Windows, macOS, Linux**. Принцип очень простой — упаковать браузер Chromium и Node.js вместе, ваша веб-страница становится независимым приложением рабочего стола.

**Одна фраза понимание**: Electron = "скрытый браузер Chrome" + способность системы Node.js.

![Архитектура Electron](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-3/cross-platform/electron-voice-to-text/images/image1.png)

## 1.2 Ядро архитектуры Electron

Приложение Electron состоит из двух типов процессов, понимание их — ключ к разработке:

**Главный процесс (Main Process)**

* Как "администратор" приложения
* Отвечает за создание окна, управление жизненным циклом приложения, доступ к способности родной операционной системы
* Работает в среде Node.js, может использовать все модули Node.js
* Во всём приложении только один главный процесс

**Процесс рендеринга (Renderer Process)**

* Как "фасад" приложения
* Это браузер Chromium, отвечает за показ UI
* Каждое окно соответствует процессу рендеринга
* Из соображений безопасности, процесс рендеринга не может напрямую доступить Node.js API

**Скрипт предварительной загрузки (Preload Script)**

* "Мост" между главным процессом и процессом рендеринга
* Через `contextBridge` безопасно откройте определённые API в процессе рендеринга

Они через **IPC (межпроцессное общение)** передавать сообщение, похожее на телефонный разговор: процесс рендеринга скажет "я хочу записать", главный процесс получит и вызовет микрофон системы.

![Архитектура процесса Electron](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-3/cross-platform/electron-voice-to-text/images/image2.png)

## 1.3 Что мы будем делать?

В этом учебнике мы создадим приложение для рабочего стола **голос в текст (Speech-to-Text)**. Функция очень интуитивная:

1. Щелкните кнопку "Начать запись", приложение начинает слушать микрофон
2. После окончания речи щелкните "Стоп", приложение отправляет речь в AI для распознавания
3. Результат распознавания показывается в интерфейсе в форме текста, одна кнопка копировать

**Два режима распознавания доступны:**

| Критерий | Облачный API режим | Локальная модель режим |
|---------|-------------|------------|
| Представитель решение | OpenAI Whisper API | whisper.cpp |
| Требуется ли интернет | Да | Нет |
| Скорость распознавания | Зависит от интернета | Зависит от железа (Apple Silicon очень быстро) |
| Качество распознавания китайского | Отличное | Отличное (large-v3 модель) |
| Стоимость использования | $0.006/минута | Свободно |
| Размер модели | Не требует загрузка | tiny модель 75МБ, large модель 3ГБ |
| Подходящий сценарий | Быстро начать, облегчённое использование | Внимание приватность, офлайн использование, долгосрочное частое использование |

## 1.4 Важное напоминание: Web Speech API в Electron недоступна

Если вы раньше искали "Electron речь распознавание", может быть видели, что кто-то рекомендует использовать встроенный браузер `Web Speech API`. **Обратите внимание: этот план не работает в Electron.**

Google закрыла поддержка речевого API для оболочек браузера, не относящихся к Chrome/Edge. Хотя Electron основан на Chromium, это не сам Chrome, поэтому `window.SpeechRecognition` прямо доложит ошибку.

Это почему нам нужно использовать OpenAI Whisper API или независимое решение типа whisper.cpp.

## 1.5 Дорожная карта этого учебника

Мы будем выполнять следующие шаги завершить весь процесс:

1. **Создание Electron проекта**: используйте Electron Forge построить скелет проекта, понять межпроцессное общение
2. **Реализация функции записи**: в процессе рендеринга захватить микрофон, обработать звуковые данные
3. **Облачное распознавание (План A)**: вызвать OpenAI Whisper API для голос-в-текст
4. **Локальное распознавание (План B)**: использовать whisper.cpp локально запустить модель, без интернета
5. **Упаковка и распределение**: упаковать приложение в устанавливаемую программу рабочего стола

## 2.3 Понимание межпроцессного общения (IPC)

Перед началом написания функции речи, нам нужно понять самую ядро концепцию Electron — **IPC (Inter-Process Communication, межпроцессное общение)**.

Потому что процесс рендеринга (интерфейс UI) и главный процесс (способность системы) изолированы, они через IPC "звоню" для сотрудничества:

```
Процесс рендеринга (UI)                    Главный процесс (система)
    │                                │
    │── "я хочу начать запись" ──────────→    │
    │                                │── вызовет микрофон
    │                                │── обработать звук
    │    ←──── "это результат распознавания" ────────│
    │                                │
    │── показать текст в интерфейс                │
```

В коде, это общение через `preload.js` для моста:

```javascript
// preload.js - безопасно откройте API в процессе рендеринга
const { contextBridge, ipcRenderer } = require('electron')

contextBridge.exposeInMainWorld('electronAPI', {
  // Процесс рендеринга → главный процесс
  sendAudio: (audioData) => ipcRenderer.invoke('transcribe-audio', audioData),
  // Главный процесс → процесс рендеринга
  onResult: (callback) => ipcRenderer.on('transcription-result', callback)
})
```

```javascript
// main.js - главный процесс слушает сообщение
const { ipcMain } = require('electron')

ipcMain.handle('transcribe-audio', async (event, audioData) => {
  // Здесь вызовите Whisper API или whisper.cpp
  const text = await transcribe(audioData)
  return text
})
```

# Глава 3: Реализация функции записи

## 3.1 Захватить микрофон в процессе рендеринга

Браузер (процесс рендеринга Electron) предоставляет `navigator.mediaDevices.getUserMedia` API для доступа микрофону. Попросите AI помочь вам реализовать функцию записи:

```
Пожалуйста помогите мне модифицировать src/index.html и src/renderer.js в проекте, помогите мне реализовать полное функции записи речи + речь распознавание, требование я уже подготовлено:

Дизайн интерфейса:
1. Сделайте большой размер круглую кнопку, по умолчанию показывайте "начать запись"; щелкните потом кнопка становится красной, текст переключается на "остановить запись"
2. Во время записи, кнопка должна иметь простую анимацию пульса, позвольте пользователю интуитивно видеть идёт запись
3. Под кнопкой положите блок текста для показа, используйте для показа распознавания речи вывод текст контента
4. В низу страницы конфигурировать кнопки "Копировать текст" и "Очистить", соответственно реализовать копировать результат распознавание, очистить область результата функции
5. Справа вверху прибавить иконку параметры, щелкните может переключить режим распознавание (облачный режим распознавание / локальный режим распознавание)

Требование логики записи (требует реализацию в renderer.js)
1. Щелкните кнопку записи, вызовите navigator.mediaDevices.getUserMedia получить разрешение микрофона
2. Используйте MediaRecorder реализовать запись аудио, формат записи фиксировано как webm
3. Остановить запись, упаковать записанный аудио Blob объект преобразовать в ArrayBuffer формат
4. Вызовите window.electronAPI.sendAudio метода, отправьте звуковые данные в главный процесс
5. Требует слушать главного процесса возвращаемый результат распознавание, и показать результат в области показа текста
```

Основной код записи:

```javascript
// renderer.js
let mediaRecorder = null
let audioChunks = []

async function startRecording() {
  const stream = await navigator.mediaDevices.getUserMedia({
    audio: {
      channelCount: 1,
      sampleRate: 16000,
      echoCancellation: true,
      noiseSuppression: true
    }
  })

  mediaRecorder = new MediaRecorder(stream, {
    mimeType: 'audio/webm;codecs=opus'
  })

  audioChunks = []
  mediaRecorder.ondataavailable = (e) => audioChunks.push(e.data)

  mediaRecorder.onstop = async () => {
    const audioBlob = new Blob(audioChunks, { type: 'audio/webm' })
    const arrayBuffer = await audioBlob.arrayBuffer()

    // Отправить в главный процесс для распознавания
    const result = await window.electronAPI.sendAudio(arrayBuffer)
    document.getElementById('result').textContent = result
  }

  mediaRecorder.start()
}
```

## 3.2 Обработка разрешения микрофона

Electron по умолчанию будет блокировать запрос разрешения. Нам требуется в главном процессе явно разрешить доступ микрофону:

```
Пожалуйста помогите мне добавить в main.js обработка разрешение микрофона:
1. Используйте session.defaultSession.setPermissionRequestHandler справиться запрос разрешение
2. Когда тип запроса это медиа микрофон разрешение, прямо автоматическое разрешение
3. Если это система macOS, помните в package.json или entitlements добавить описание использования микрофона, гарантируйте разрешение может нормально эффект
```

```javascript
// main.js добавить
const { session } = require('electron')

session.defaultSession.setPermissionRequestHandler(
  (webContents, permission, callback) => {
    if (permission === 'media') {
      callback(true)
    } else {
      callback(false)
    }
  }
)
```

> **Заметьте пользователи macOS**: macOS будет выскочить диалог запроса разрешение микрофона на уровне системы, это нормально, щелкните "разрешить" можно.

# Глава 4: План A — облачное распознавание (OpenAI Whisper API)

Это простейший план, только требует API Key и несколько строк кода.

## 4.1 Получить OpenAI API Key

1. Посетите [OpenAI Platform](https://platform.openai.com/), регистрация и вход
2. Входу в страница API Keys, щелкните **"Create new secret key"**
3. Копировать генерированный Key (начинается с `sk-`), безопасно сохраняйте

> **Справка стоимости**: цена Whisper API **$0.006/минута**, то есть распознавание 1 часа речи только требует $0.36 (примерно 2.5 юаня), очень дешево.

## 4.2 В главном процессе вызовите Whisper API

Попросите AI помочь вам реализовать распознавание речи в главном процессе:

```
Пожалуйста помогите мне в main.js реализовать вызов OpenAI Whisper API речь распознавание:
1. Установить node-fetch (если проект требует), или используйте встроенный Node.js fetch
2. Написать функцию transcribeWithWhisper, параметр передавайте аудио ArrayBuffer
3. Преобразовать переданный ArrayBuffer в Blob или File, потом упаковать в FormData формат
4. Вызовите https://api.openai.com/v1/audio/transcriptions
5. Модель указывайте использовать whisper-1, язык установить на китайский zh
6. После вызова интерфейса завершения, возвращаемый распознавание вывод текст контента
7. API Key читайте из переменной окружение или конфигурационный файл
```

Основной код:

```javascript
// main.js
async function transcribeWithWhisper(audioBuffer, apiKey) {
  const blob = new Blob([audioBuffer], { type: 'audio/webm' })
  const formData = new FormData()
  formData.append('file', blob, 'audio.webm')
  formData.append('model', 'whisper-1')
  formData.append('language', 'zh')

  const response = await fetch(
    'https://api.openai.com/v1/audio/transcriptions',
    {
      method: 'POST',
      headers: { Authorization: `Bearer ${apiKey}` },
      body: formData
    }
  )

  const data = await response.json()
  return data.text
}
```

# Глава 5: План B — локальное распознавание (whisper.cpp)

Если вы не хотите зависить от облачного API, или требует офлайн использование, whisper.cpp — лучший выбор. Это портирование C++ модели OpenAI Whisper, может полностью локально работать, не требует интернет.

## 5.1 Установить Node.js привязка whisper.cpp

Попросите AI помочь вам установка и конфигурация:

```
Пожалуйста помогите мне в проекте установить пакет nodejs-whisper:
npm install nodejs-whisper

После установки завершения, пожалуйста помогите мне загрузить whisper tiny модель (для тестирования, малый размер быстрая скорость).
nodejs-whisper самостоятельно будет автоматическое завершение загрузка модель, не нужно дополнительное справиться.
```

> **Справка выбора модель**:
> * `tiny` (75МБ): скорость быстрая, подходящий тестирование и облегчённое использование, точность обычное
> * `base` (142МБ): баланс скорость и точность
> * `small` (466МБ): качество распознавание китайского видимое улучшение
> * `large-v3-turbo` (1.5ГБ): рекомендуется! Скорость в 5-8 раза large, точность только отличие 1-2%
> * `large-v3` (3ГБ): наивысшая точность, но медленнее скорость, требует хорошее железо

## 5.2 В главном процессе интегрировать whisper.cpp

Попросите AI помочь вам реализовать локальное распознавание функция:

```
Пожалуйста помогите мне в main.js добавить whisper.cpp локальное речь распознавание функция:
Сначала импорт nodejs-whisper пакет, потом написать функцию transcribeWithLocal. Функция получит аудио ArrayBuffer, сначала сохраняет его в временный WAV файл (требует 16kHz, однодорожечный), потом вызовите nodejs-whisper справиться распознавание, распознавание завершения после возвращаемый текст результат, в конце удалить временный файл
```

Основной код:

```javascript
// main.js
const { nodewhisper } = require('nodejs-whisper')
const path = require('path')
const fs = require('fs')
const os = require('os')

async function transcribeWithLocal(audioBuffer) {
  // Сохраняет как временный файл
  const tempPath = path.join(os.tmpdir(), `recording-${Date.now()}.wav`)
  fs.writeFileSync(tempPath, Buffer.from(audioBuffer))

  try {
    const result = await nodewhisper(tempPath, {
      modelName: 'base',
      autoDownloadModelName: 'base',
      whisperOptions: {
        language: 'zh',
        word_timestamps: true
      }
    })
    return result.map(r => r.speech).join('')
  } finally {
    // Очистить временный файл
    fs.unlinkSync(tempPath)
  }
}
```

## 5.3 Apple Silicon пользователей благодеяние

Если вы используйте M1/M2/M3/M4 чип Mac, whisper.cpp автоматическое используйте **Metal GPU ускорение** и **Apple Neural Engine**, скорость распознавание может достичь **быстрее чем реальное время** — то есть сказать, 1 минута речи может только требует несколько секунд завершить распознавание.

Для NVIDIA видеокарта пользователей, whisper.cpp также поддержку **CUDA ускорение**, точно так же может получить хорошое производительности.

## 6.2 Оптимизация размер приложения

Electron приложение "болевая точка" это размер больший (потому что упаковано целое Chromium). Некоторые рекомендация оптимизация:

* Гарантировать только `dependencies` в пакете упаковано, разработка зависимость положить в `devDependencies`
* Используйте Vite tree-shaking уменьшить JS размер
* Если использовать локальная модель, рассмотреть позволить пользователю первый запуск загрузить, вместо упаковка в устанавливаемая программа

| Конфигурация | Оценка размер |
|------|---------|
| Чистый Electron приложение (без модель) | ~150-200 МБ |
| + whisper tiny модель | ~250 МБ |
| + whisper large-v3-turbo модель | ~1.7 ГБ |

## 6.3 Кроссплатформенное внимание

**macOS:**
* Опубликовать на App Store или распределение другой пользователь требует **подпись кода** (Apple Developer ID, $99/год)
* Также требует прохождение Apple **нотариального (Notarization)** процесса
* Разрешение микрофона требует в `Info.plist` объявить `NSMicrophoneUsageDescription`
* Рекомендуется построить Universal Binary поддержку Intel и Apple Silicon одновременно

**Windows:**
* Рекомендуется выполнить подпись кода, иначе Windows SmartScreen выскочит предупреждение безопасность
* Пользователь все ещё может выбрать "всё ещё запустить" использовать неподписанное приложение

**Linux:**
* Не требует подпись кода
* Рекомендуется одновременно предоставить `.deb` и `.AppImage` формат

> **Подсказка**: для личный проект или малый-масштаб распределение, может временно пропустить подпись кода, прямо предоставить упакованный файл дать друзьям использовать.
