# Полное руководство Claude Code Skills

## Введение в Skills

**Claude Code Skills** — это функция, которая позволяет упаковать профессиональные знания, рабочие процессы и лучшие практики в "переиспользуемые наборы навыков".

Представьте себе Skills как "справочник навыков" для Claude — когда вам нужно выполнить определённую задачу, Claude больше не требует, чтобы вы каждый раз повторяли требования. Вместо этого он просто выполняет работу согласно предварительно определённым стандартам навыков.

### Почему нужны Skills?

Без Skills использование Claude Code имеет ряд проблем:

- **Повторяющиеся инструкции**: каждый раз приходится объяснять "код должен соответствовать определённому стилю", "сообщение коммита должно быть написано вот так"
- **Знание не накапливается**: опыт членов команды невозможно поделить
- **Отсутствие единых стандартов**: разные люди используют Claude, результаты могут быть совершенно разными
- **Низкая эффективность**: обычные задачи нужно объяснять с нуля каждый раз

Skills решает эти проблемы, превращая Claude в "опытного членов команды" — он знает规範 вашего проекта, рабочие процессы и лучшие практики.

---

## Почему сейчас нужно учить Skills?

**Skills становятся обязательным навыком для AI-инженеров**:

- **Высокая популярность в сообществе**: связанные репозитории на GitHub быстро набирают звёзды. Например, проект OpenSkills уже получил 7,2k звёзд, Obsidian Skills за 9 дней набрал 6,6k звёзд
- **Официальная поддержка**: Anthropic официально поддерживает репозиторий Skills, Vercel запустил Agent Skills и инструмент find-skills
- **Высокая практическая ценность**: от проверки кода, операций с Git до видеопроизводства и создания презентаций — охватывает множество сценариев. Платформа skills.sh уже имеет 60K+ подписчиков на популярные навыки
- **Повышение производительности**: один раз настроил — многократно использую, Claude становится настоящим "цифровым сотрудником"
- **Признание разработчиками**: рекомендуется многими техническими сообществами, считается ключевым инструментом для повышения эффективности AI-программирования

## Быстрый старт

После понимания ценности Skills давайте сразу приступим к практике! В этом разделе мы установим первый Skill и выполним несколько интересных практических задач, чтобы быстро получить интуитивное понимание.

### Шаг первый: установка find-skills (настоятельно рекомендуется)

Перед началом использования Skills настоятельно рекомендуется сначала установить `find-skills` — это "волшебный поиск навыков" для AI Agent, который уже имеет 60K+ подписчиков.

**Что такое find-skills?**

Проще говоря, find-skills работает как "магазин приложений поиска" для AI Agent. Когда вам нужно выполнить задачу, но локально нет соответствующего Skill, он автоматически поищет и порекомендует наиболее подходящий Skill.

**Установка find-skills**:

```bash
npx skills add vercel-labs/skills@find-skills -g -y
```

После установки вы можете напрямую рассказать Claude о своих потребностях, и он автоматически будет искать соответствующие навыки через find-skills.

**Пример использования**:

```
Мне нужно оптимизировать производительность компонента React, помоги мне найти какие-нибудь применимые навыки
```

Claude будет искать через find-skills, а затем сообщит вам, какие связанные навыки были найдены, вы сможете выбрать для установки.

**Почему рекомендуется сначала установить find-skills?**

Без find-skills:
- Нужно вручную искать связанные навыки на GitHub
- Копировать, устанавливать и настраивать каждый в отдельности
- Повторно отлаживать и адаптировать

С find-skills:
- Одним предложением описываешь потребность
- AI автоматически ищет наиболее подходящие навыки
- Один клик для установки, сразу готово к использованию

**Внимание для пользователей Windows**: официальная версия имеет ограниченную поддержку Windows, сообщество создало версию, адаптированную для Windows, поддерживающую CMD и PowerShell, а также добавившую поддержку поиска на китайском языке.

Скачать версию для Windows: [github.com/tongbei821/customize-skills](https://github.com/tongbei821/customize-skills/blob/main/findskills/SKILL.md)

Шаги установки:
1. Скачайте версию для Windows файла SKILL.md
2. Замените файлы в директории `C:/Users/имя_пользователя/.agents/skills/find-skills`
3. Перезагрузите Claude Code и изменения вступят в силу

### Третий Skill: использование frontend-slides для быстрого создания красивых презентаций

#### Введение

**frontend-slides** — это Skill, который позволяет вам создавать красивые HTML-презентации на естественном языке — даже если вы ничего не знаете о CSS или JavaScript!

Его основная особенность — "показывать, а не рассказывать": когда вы не можете описать желаемый стиль дизайна, он генерирует 3 визуальных предпросмотра на выбор, вместо того чтобы заставлять вас описывать абстрактные требования вроде "синий фон, большой шрифт".

#### Установка frontend-slides

**Способ один: ручная установка**

```bash
# Создайте директорию skill
mkdir -p ~/.claude/skills/frontend-slides

# Загрузите файлы (или скопируйте с GitHub)
# 1. Посетите https://github.com/zarazhangrui/frontend-slides
# 2. Загрузите SKILL.md и STYLE_PRESETS.md
# 3. Поместите их в директорию ~/.claude/skills/frontend-slides/
```

**Способ два: использование find-skills для установки**

```
Помоги мне найти навыки для создания презентаций и слайдшоу
```

Claude будет искать через find-skills и рекомендовать frontend-slides.

#### Сценарии использования

**Сценарий 1: создание презентации с нуля**


Claude будет вас направлять:
1. Спросит содержимое каждого слайда (заголовок, основные идеи, изображения)

## Что такое Skills?

### Основная концепция

**Skills — это "наборы навыков", хранящиеся в файловой системе**, которые содержат:

- **SKILL.md**: файл определения навыка (обязателен)
- **scripts/**: вспомогательные скрипты (опционально)
- **templates/**: шаблоны вывода (опционально)
- **references/**: справочная документация (опционально)

### Skills против подсказок

У вас может быть вопрос: в чём разница между Skills и просто отправкой подсказок Claude?

| Подсказки | Skills |
|--------|--------|
| временные, приходится повторять каждый раз | постоянные, пишешь один раз и многократно используешь |
| находятся в истории диалога, потребляют токены | загружаются по необходимости, экономят токены |
| невозможно поделиться между сессиями | можно поделиться в команде |
| сложно контролировать версии | можно управлять версиями с Git |

### Два типа Skills

**Глобальные Skills (персональные)**:
- место хранения: `~/.claude/skills/`
- область действия: все проекты
- применимые сценарии: персональные универсальные навыки

**Project Skills (командные)**:
- место хранения: `директория_проекта/.claude/skills/`
- область действия: текущий проект
- применимые сценарии: командные, специфичные для проекта нормы

### Как работают Skills

Когда Claude Code запускается, он:

1. сканирует директорию Skills
2. парсит каждый файл SKILL.md
3. извлекает метаданные YAML frontmatter
4. добавляет содержимое навыка в "базу знаний"
5. автоматически совпадает на основе description

## Структура файла SKILL.md

### Базовая структура

Полная директория Skill выглядит так:

```
my-skill/
├── SKILL.md          # обязателен: файл определения навыка
├── scripts/          # опционально: вспомогательные скрипты
├── templates/        # опционально: шаблоны вывода
├── references/       # опционально: справочная документация
└── examples/         # опционально: примеры файлов
```

### Шаблон SKILL.md

Файл SKILL.md состоит из двух частей:

**Первая часть: YAML Frontmatter (метаданные)**

```yaml
---
name: skill-name              # имя навыка, становится /skill-name командой
description: краткое описание # используется для автоматического совпадения Claude
category: development         # категория
tags:                           # теги
  - code
  - automation
---
```

**Вторая часть: содержимое Markdown (инструкции)**

```markdown
# Заголовок навыка

## Сценарии использования
когда использовать этот навык

## Шаги выполнения
1. первый шаг
2. второй шаг

## Моменты внимания
- момент внимания 1
- момент внимания 2
```

### Описание ключевых полей

| Поле | Обязательное | Описание |
|------|------|------|
| `name` | да | имя навыка, можно использовать только строчные буквы, цифры, дефисы |
| `description` | да | описание навыка, чем конкретнее, тем легче Claude автоматически совпадает |
| `category` | нет | тег категории |
| `tags` | нет | больше тегов категории |
| `allowed-tools` | нет | разрешённые инструменты, можно использовать без разрешения |

## Skills против MCP: в чём разница?

Многие начинающие путают Skills и MCP, это два совершенно разных понятия.

### Основное различие

| Аспект | Skills | MCP |
|------|--------|-----|
| **Сущность** | знание и процесс | инструменты и интерфейсы |
| **Что предоставляет** | говорит AI "как делать" | дает AI "что можно использовать" |
| **место хранения** | директория `skills/` | MCP сервер |
| **способ настройки** | файл Markdown | файл конфигурации JSON |
| **способ срабатывания** | `/skill-name` или автоматическое распознавание | автоматическое загружение через конфигурацию |

### Наглядная аналогия

Если сравнить Claude с "сотрудником":

- **MCP** — это "инструменты", которыми вы его оснащаете (отвёртка, компьютер, права доступа)
- **Skills** — это "операционные справочники" для этого сотрудника (как проводить проверку кода, как коммитить код)

### Их отношение

Skills и MCP — это не конкурирующие, а дополняющие друг друга отношения:

```
запрос пользователя → Claude определяет потребность
               ↓
        загружает соответствующие Skills (знает как делать)
               ↓
        использует MCP для вызова инструментов (есть инструменты)
               ↓
        завершает задачу
```

### Пример объяснения

**Сценарий: проверка кода**

- **Skills** определяет: шаги проверки, чек-лист, формат вывода
- **MCP** предоставляет: возможность доступа к GitHub PR, возможность получить diff кода

работа вместе: Skills говорит Claude "как проверять", MCP дает Claude "возможность доступа к коду".

### Рекомендации по выбору

| Ваша потребность | Рекомендуемое решение |
|----------|----------|
| нужно определить рабочий процесс | используй Skills |
| нужен доступ к внешним данным | используй MCP |
| нужны оба | используй вместе |

## Как создать свой Skills

Создание Skills возможно двумя способами: один — прямо попросить Claude его создать, другой — использовать специальный инструмент skill-creator.

### Способ один: прямой запрос к Claude

это самый простой способ, прямо говорите Claude о своих потребностях на естественном языке.

**Пример**:

```
Пожалуйста, создай для меня skill с именем "format-code" со функцией автоматического форматирования кода.

Требования:
1. автоматическое определение типа языка программирования
2. применение соответствующих правил форматирования
3. вывести diff до и после форматирования
```

Claude автоматически:
1. создаст структуру директории
2. сгенерирует файл SKILL.md
3. заполнит YAML frontmatter
4. напишет содержимое навыка

**применимые сценарии**:
- быстрое создание простых навыков
- вы знаете что хотите, но не знакомы с форматом SKILL.md
- хотите быстро итерировать и изменять

### Способ два: использование skill-creator

skill-creator — это специальный инструмент для создания Skills, который будет направлять вас пошагово.

**Установка**:

```bash
npx skills add anthropics/skills@skill-creator -g
```

или установите весь официальный репозиторий skills:

```bash
npx skills add anthropics/skills -g
```

**Использование**:

```
/skill-creator
```

затем следуйте подсказкам:
- имя навыка
- описание функции
- сценарии использования
- шаги выполнения

skill-creator будет:
1. направлять вас в уточнении целей навыка
2. генерировать черновик SKILL.md
3. создавать тестовые случаи
4. запускать оценку и оптимизацию

**применимые сценарии**:
- создание сложных навыков
- нужен стандартизированный процесс создания
- хотите тестировать и проверять навыки

### Сравнение двух способов

| Способ один: прямое создание | Способ два: skill-creator |
|-----------------|---------------------|
| быстро и просто | пошаговое направление |
| подходит для простых навыков | подходит для сложных навыков |
| прямое завершение диалога | стандартизированный процесс |
| гибкие изменения | есть тестирование и проверка |

### умения: как описать хорошее требование

**Хороший пример требования**:

```
создай skill "git-commit", функция автоматическое коммитирование кода.

Шаги выполнения:
1. проверить какие файлы были изменены
2. генерировать сообщение коммита в соответствии со стандартом Conventional Commits
3. выполнить git commit
4. спросить нужен ли push

Моменты внимания:
- перед коммитом проверить не есть ли чувствительной информации
- не коммитить директории dist/node_modules/ и т.д.
```

**Плохой пример требования**:

```
помоги мне написать skill для коммитирования кода
```

это слишком размыто, Claude не знает что конкретно нужно делать.

### Пример 1: Skill проверки кода

создайте директорию и файл:

```bash
mkdir -p ~/.claude/skills/review-pr
```

```bash
cat > ~/.claude/skills/review-pr/SKILL.md << 'EOF'

---

вы опытный рецензент кода.

## процесс проверки

1. **проверка стиля кода**
   - соответствует ли код нормам команды
   - ясны ли имена
   - достаточны ли комментарии

2. **проверка безопасности**
   - есть ли уязвимости безопасности
   - не раскрыта ли чувствительная информация
   - полна ли валидация входных данных

3. **проверка тестов**
   - достаточно ли тестов
   - охватывают ли тестовые случаи пограничные случаи
   - могут ли тесты запускаться

4. **общая оценка**
   - какие сильные стороны
   - что нужно улучшить
   - рекомендация на одобрение слияния

## формат вывода

пожалуйста выведите результаты проверки с чётким структурированным форматом, используя списки.
EOF
```

способ использования:

```
/review-pr
пожалуйста проверь PR текущей ветки
```

### Пример 2: Skill автоматического коммитирования Git

```bash
mkdir -p ~/.claude/skills/git-commit
```

```bash
cat > ~/.claude/skills/git-commit/SKILL.md << 'EOF'
---
name: git-commit
description: автоматически определить изменения, генерировать сообщения коммитов и коммитить код
---

вы опытный пользователь Git.

## процесс выполнения

1. **проверка изменений**
   запустите `git status` чтобы посмотреть изменённые файлы
   запустите `git diff` чтобы посмотреть специфичные изменения

2. **генерирование сообщения коммита**
   анализировать природу изменений
   генерировать сообщение коммита в формате Conventional Commits
   формат: `type(scope): description`

3. **проверка безопасности**
   проверить нет ли чувствительной информации (ключи, пароли, token)
   проверить не включены ли директории которые не должны коммиться

4. **подтверждение перед выполнением**
   показать сообщение коммита для подтверждения
   выполнить `git add` и `git commit`
   спросить нужен ли push

## моменты внимания

- не коммитить node_modules/, dist/, .next/ и т.д.
- перед коммитом запустить тесты чтобы убедиться работает код
- сообщение коммита должно четко описывать содержимое изменений
EOF
```

способ использования:

```
/git-commit
```

## продвинутые умения

### Skills в сочетании с Hooks

Hooks могут автоматически выполнять операции при специфичных событиях, в сочетании с Skills могут реализовать более мощную автоматизацию.

например: автоматическое форматирование кода после сохранения

```json
// .claude/hooks.json
{
  "hooks": {
    "PostToolUse": [{
      "matcher": {
        "tool_name": "Edit"
      },
      "hook": {
        "type": "command",
        "command": "/format-code"  // вызвать format-code skill
      }
    }]
  }
}
```

### Skills в сочетании с Commands

Commands — это простые быстрые команды, Skills — это сложные рабочие процессы. оба могут использоваться вместе.

### командная работа

**Обмен Skills проектов**:

1. поместить Skills в директорию `.claude/skills/`
2. закоммитить в Git репозиторий
3. члены команды после клонирования проекта могут сразу использовать

**контроль версий**:

- Skills можно контролировать версии как код
- каждый коммит может записать изменения Skills
- можно откатиться к старой версии

## часто задаваемые вопросы

### Q1: Skill не был срабатан?

возможные причины:
- формат YAML frontmatter неправильный
- description недостаточно специфичен
- Claude Code не перезагружен

решение:
- проверить правильность формата YAML
- улучшить description, включить специфичные сценарии использования
- перезагрузить Claude Code

### Q2: как правильно написать description?

хороший description должен содержать:
- специфичную функцию навыка
- сценарии использования ("когда пользователь упоминает...")
- триггер ключевые слова

**плохой пример**:
```
description: проверить код
```

**хороший пример**:
```
description: проверить Pull Request код. срабатать когда пользователь упоминает PR, review, проверка кода.
```

### Q3: разница между Skills и Commands?

| Commands | Skills |
|----------|--------|
| простые быстрые команды | полные рабочие процессы |
| одиночный файл `.md` | структура директории (SKILL.md + опциональные файлы) |
| ручное срабатывание | может быть автоматическое срабатывание |
| подходит для простых операций | подходит для сложных процессов |

### Q4: как отлаживать Skill?

1. использовать `/skills` посмотреть распознан ли навык
2. прямой ввод имени навыка ручной триггер
3. проверить правильность содержимого файла SKILL.md
4. посмотреть логи Claude Code

## глубокий анализ: внутренний механизм Claude Skills

дальше мы глубоко поймём принципы работы Claude Skills, так чтобы вы не только могли использовать, но и понимали почему так спроектировано.

### первопринцип: динамическое встроение контекста на основе подсказок

сначала, нужно понять ключевой факт: **Skills не являются исполняемым кодом**.

Skills в сущности это продвинутые инструкции (Prompt), которые "встраиваются" в контекст Claude по необходимости. этот дизайн называется "**Prompt-based Dynamic Context Injection & Meta-Tool Architecture**" (динамическое встраивание контекста на основе подсказок и архитектура мета-инструмента).

```
┌─────────────┐      ┌─────────────┐      ┌──────────────┐
│ запрос пользователя │ ───> │ LLM совпадение │ ───> │ срабатывание Skill │
└─────────────┘      │ описание Skill │      └──────────────┘
                     └─────────────┘              │
                                                 ▼
                                          ┌──────────────┐
                                          │ встроить      │
                                          │ полное        │
                                          │ содержимое    │
                                          │ инструкций    │
                                          └──────────────┘
                                                 │
                                                 ▼
                                          ┌──────────────┐
                                          │ выполнить    │
                                          │ задачу       │
                                          └──────────────┘
```

### архитектура трёхслойной прогрессивной загрузки (оптимизация токенов)

для обработки большого количества Skills без чрезмерного потребления токенов, Claude использует умный трёхслойный механизм загрузки:

| уровень | содержимое | время загрузки | потребление токенов |
|------|------|----------|-----------|
| **уровень 1: метаданные** | YAML frontmatter (name + description) | загрузка Claude | ~30-50 токенов/skill |
| **уровень 2: инструкции** | полное содержимое SKILL.md | срабатывание Skill | ~5,000 токенов |
| **уровень 3: ресурсы** | скрипты, шаблоны, справочные документы | доступ по необходимости через файловую систему | не занимает контекст |

**преимущества этого дизайна**:

- предположим у вас 100 Skills, при запуске потребляется только ~3,000-5,000 токенов (метаданные)
- только срабатанный Skill будет загружать полное содержимое
- файлы ресурсов справочной документации никогда не будут полностью загружены в контекст

**сравнение без Skills**:

```
без Skills: каждый диалог нужно 50,000+ токенов чтобы описать все способности
с Skills: загрузка ~100 токенов/skill + 5,000 токенов загрузка по необходимости
экономия: в среднем сохранить 40,000+ токенов за один раунд диалога
```

### механизм двойного встраивания контекста

когда Skill активируется, система одновременно проводит два изменения:

**1. встраивание контекста диалога**

```javascript
// видимое пользователем (видимое сообщение)
<command-message>The "pdf" skill is loading</command-message>

// AI фактически получает (скрытое метасообщение)
{
  isMeta: true,  // отметка метасообщение, интерфейс пользователя не показывает
  content: `
    # инструкции PDF эксперта анализа

    вы опытный профессионал анализа PDF. рабочий процесс:
    1. использовать pdftotext извлечь текст
    2. анализировать структуру документа
    3. генерировать отчёт резюме
    ...
  `  // полное содержимое SKILL.md, возможно тысячи слов
}
```

**2. изменение контекста выполнения**

кроме встраивания инструкций, Skill может динамически изменять окружение Claude:

| тип изменения | пример | описание |
|---------|------|------|
| **разрешение инструментов** | `allowed-tools: "Bash(pdftotext:*)"` | временно предоставить доступ к специфичным инструментам |
| **переключение модели** | переключиться с Sonnet на Opus | некоторые сложные задачи требуют более сильного рассуждающего способности |
| **изоляция контекста** | создать подпространство сессии | избежать загрязнения основного контекста диалога |

### механизм маршрутизации чистого LLM рассуждения

это очень важное решение дизайна: **Claude Skills не имеет жёсткого кодирования маршрутизации**.

| традиционный метод | Claude Skills |
|---------|--------------|
| ❌ совпадение вектора встраивания | ✅ чистое LLM рассуждение |
| ❌ классификатор | ✅ прямой проход Transformer |
| ❌ регулярное выражение/совпадение ключевого слова | ✅ понимание естественного языка |
| ❌ отдельный алгоритм маршрутизации | ✅ унифицированное решение модели |

**рабочий процесс**:

```
1. все имена Skills и descriptions форматируются в описание инструмента Skill

2. Claude получает:
   - сообщение пользователя
   - список доступных инструментов (включая Skill мета-инструмент)
   - список Skills (name + description)

3. способность естественного языка Claude совпадает намерение пользователя с описанием Skill

4. при успешном совпадении вызывает: command: "skill-name"
```

**почему именно этот дизайн?**

**жёсткое кодирование маршрутизации требует**:
- дополнительной стоимости обслуживания
- невозможности понять сложные семантические отношения
- сложность обработки многоязычности
- не поддержка нечёткого совпадения

**чистое LLM рассуждение**:
- использовать способность понимания языка Claude самого
- автоматически обработать многоязычность, синонимы, нечёткое описание
- без необходимости дополнительного обслуживания
- решение маршрутизации более умно

### основные дизайн инновации

| пункт инновации | традиционный метод | метод Skills | преимущество |
|--------|---------|------------|------|
| **источник способности** | затвердел в весе модели | динамически загружаемая подсказка | расширяемое, обновляемое |
| **эффективность токенов** | все способности постоянно в памяти | загрузка по необходимости | экономить 80%+ токенов |
| **управление знаниями** | разбросано в истории диалога | модульная файловая система | управляемое версией, доступно для обмена |
| **жизненный цикл** | постоянное занятие | использованное удаление | контекст более чист |

**трансформация основной идеи**:

```
      ↓
Skills: AI знает "где найти профессиональное знание"

```

### отношение к стандарту Agent Skills

Claude Skills следует [открытому стандарту Agent Skills](https://agentskills.io/), это значит:

- ✅ кроссплатформенная совместимость: Cursor, Windsurf, Aider и другие инструменты поддерживают
- ✅ унифицированный формат файла: стандартная структура SKILL.md
- ✅ взаимнооперируемость: разные инструменты могут обмениваться Skills

```
определение стандарта Agent Skills:
├── обязательно: файл SKILL.md (metadata + instructions)
├── опционально: scripts/ (исполняемый код)
├── опционально: references/ (базовая документация знаний)
└── опционально: assets/ (шаблоны и ресурсы)
```

### резюме: почему этот дизайн гениален?

1. **развязка способности с моделью**: профессиональные знания больше не зависят от тренировки модели, могут быть обновлены в любое время через файл Markdown

2. **экстремальная эффективность токенов**: трёхслойный механизм загрузки гарантирует загрузку только необходимого содержимого

3. **использование собственных способностей LLM**: совпадение маршрутизации полностью зависит от понимания языка Claude, без необходимости дополнительного алгоритма

4. **дружественное разработчикам**: создание Skill требует только написание Markdown, не требует программирования

5. **составляемость**: Skills могут взаимно ссылаться, комбинировать, формировать сложный рабочий процесс

6. **использованное удаление**: после завершения задачи автоматически очищают, сохранять контекст чистым
