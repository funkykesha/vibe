# Claude Code Superpowers Инженерная разработка

## Введение в Superpowers

**Superpowers** — это открытый фреймворк навыков агента, разработанный Jesse Vincent (ник obra), специально решающий одну ключевую проблему AI программирования: как сделать AI писать код «инженерного уровня», а не код «игрушечного уровня».

Представьте, что обычный AI помощник программирования как «умный стажер» — может написать рабочий код, но может быть без тестов, без документации, без следования лучшим практикам. Superpowers это как дать этому стажеру «опытного инженера наставника», принудить его следовать полному процессу разработки программного обеспечения.

### Почему нужны Superpowers?

До Superpowers, использование Claude Code имело некоторые проблемы:

- **Путаница Vibe Coding**: AI напрямую начинает писать код, нет планирования, это приводит к частым возделкам
- **Отсутствие TDD дисциплины**: AI привык сначала писать код потом дополняйте тесты, или вообще не пишет тесты
- **Требование размыто прямо действует**: Пользователь говорит «сделайте функцию входа», AI начнет писать, в результате не то что хочется
- **Качество кода нестабильно**: Нет механизма проверки кода, качество зависит от «настроения» AI

Superpowers решило эти проблемы, сделав Claude «дисциплинированной командой разработки» — он сначала помогает вам уточнить требование, потом делает план, потом используя TDD способ разработку, наконец проходит проверку кода для гарантии качества.

## Быстрый старт

### Первый шаг: Установите Superpowers

В Claude Code запустите:

```bash
# Добавить marketplace
/plugin marketplace add obra/superpowers-marketplace

# Установить superpowers
/plugin install superpowers@superpowers-marketplace
```

Или ручная клонирование:

```bash
git clone https://github.com/obra/superpowers.git ~/.claude/skills/superpowers
```

### Второй шаг: Опытные первый навык

Давайте используя Superpowers навык **brainstorming** (мозговой штурм) опыта его ценность.

В Claude Code введите:

```
Я делаю функцию входа пользователя
```

**До Superpowers**: Claude напрямую начнет писать код, возможно делать не то что вы хотите.

**После Superpowers**: Claude будет через сократический способ помочь вам уточнить требование:

> Эта функция входа для веб приложения или мобильного приложения?
>
> Какие способы входа нужно поддержать? Пароль электронной почты? Третий стороны вход (Google, GitHub)?
>
> Нужно ли функция «помнить меня»?
>
> Восстановление пароля через электронную почту или SMS?
>
> ...

Эти вопросы принудят вас перед кодированием думать ясно что реально требуется, избежать написание кучи кода который не нужен.

### Третий шаг: Поймите механизм запуска навыка

Superpowers не «волшебный выключатель», это **набор навыков**. Понимать как запускаются навыки важно.

**Три способа запуска навыков**:

1. **Ключевое слово запуск**
   - Когда вы упоминаете «TDD», «тестовая разработка», «сначала писать тест»
   - Навык `test-driven-development` будет активирован

2. **Сценарий запуск**
   - Когда требование размыто, навык `brainstorming` будет активирован
   - Когда есть баг, навык `systematic-debugging` будет активирован

3. **Ручной вызов**
   - Напрямую использовать имя навыка: `/test-driven-development`

#### 💡 Важное понимание: Что если не указывайте TDD?

Это распространенное неверное понимание, давайте уточним:

```
# Случай A: Не упомянуть TDD
"Реализовать калькулятор"
→ Claude может писать тесты, может не писать
→ Зависит от привычки обучения модели

# Случай B: Упомянуть TDD
"Используя TDD способ реализовать калькулятор"
→ Навык test-driven-development будет активирован
→ Принудить следовать процессу RED-GREEN-REFACTOR
```

**Реальная ценность Superpowers**: Не «создать из ничего», а «усилить дисциплину».

- Без навыка TDD: Claude писать тесты это «на настроение»
- С навыком TDD: Claude принудить следовать процессу TDD

### Понимание ценности Superpowers

Через описание выше, вы видите ценность Superpowers ядра:

1. **Требование первым**: Навык `brainstorming` при размытом требовании активно задает вопросы
2. **Дисциплина процесса**: `test-driven-development` принудить TDD цикл красно-зеленую переработку
3. **Разложение задачи**: `writing-plans` большой проект разложить на маленькие задачи
4. **Контроль качества**: `code-review` навык гарантирует качество кода

## Подробное объяснение навыков Superpowers

Superpowers содержит **более 20 комбинируемых навыков**, охватывающий весь цикл разработки программного обеспечения. Давайте категорией понимать их.

### 🧪 Навыки тестирования

#### test-driven-development (Тестовая разработка)

**Как запустить**: Упомянуть «TDD», «тестовая разработка», «сначала писать тест» и подобные ключевые слова.

**Что этот навык делает**: Принудить Claude следовать процессу TDD красно-зеленую переработку, не «думать о написании тестов позже».

**Традиционный способ разработки** (распространенные проблемы):
1. Напрямую писать код
2. Ручное тестирование один раз
3. Найти баг, модифицировать код
4. Повторять... (тесты? позже говорим)

**Способ TDD** (после активирования навыка):
1. 🔴 **RED**: Сначала писать тест который не пройдет
2. 🟢 **GREEN**: Писать минимальный код чтобы тест прошел
3. 🔵 **REFACTOR**: Переработать код, удерживать тест прошедший
4. Повторять

**Пример использования**:

```
Используя TDD способ реализовать модуль аутентификации пользователя
```

Claude будет:
1. Сначала написать тесты (тестировать проверку пароля пользователя, тестировать генерирование токена...)
2. Запустить тесты, подтвердить все не пройдут (RED)
3. Написать минимальный код реализации
4. Запустить тесты, подтвердить пройдут (GREEN)
5. Переработать код, извлечь общую логику
6. Снова запустить тесты, подтвердить все еще пройдут (REFACTOR)

> **Примечание**: Если вы не упомянуть «TDD», Claude также может писать тесты. Ценность этого навыка это **усилить дисциплину процесса**, гарантировать тесты не будут «забыли».

### 🐛 Навыки отладки

#### systematic-debugging (Систематическая отладка)

Когда есть баг, человеческие разработчики часто пробуют разные способы исправления случайно. Superpowers принудить использовать четырехэтапный анализ основной причины:

**Этап 1: Повторить проблему**
- Подтвердить баг может повторяться стабильно
- Записать шаги повторения

**Этап 2: Изолировать основную причину**
- Через двоичный поиск сузить диапазон
- Добавить логирование определить проблемный код

**Этап 3: Проверить предположение**
- Выдвинуть предположение основной причины
- Дизайн проверенный эксперимент

**Этап 4: Исправить и проверить**
- Выполнить исправление
- Подтвердить баг решен
- Добавить регрессионный тест

#### verification-before-completion (Проверка перед завершением)

Этот навык предотвращает Claude «почти готово» прекратить работу. Это требует Claude перед заявлением задача завершена:

1. Запустить все тесты
2. Ручное тестирование ключевых функции
3. Проверить качество кода (lint)
4. Подтвердить документация обновлена

### 🤝 Навыки сотрудничества

#### brainstorming (Мозговой штурм)

Это один из самых интересных навыков Superpowers. Он используя сократический способ помочь вам уточнить требование.

**Работный способ**: Когда вы выдвинуть размытое требование, Claude не будет напрямую действовать, а будет задать вам вопросы:

```
Вы: Сделайте блог систему

Claude:
- Этот блог главным образом для кого? Технические читатели или публика?
- Нужно ли поддержать Markdown редактирование?
- Нужно ли функция комментариев?
- Нужна ли функция поиска?
- Один автор или несколько авторов?
- ...
```

Эти вопросы принудят вас думать какие функции реально нужны, избежать разработить кучи ненужного.

#### writing-plans (Написание планов)

Этот навык разложить большую задачу на 2-5 минутные маленькие задачи которые могут быть завершены.

**Пример**:

```
Используя writing-plans планировать разработку TODO API
```

Claude будет сгенерировать детальный план:

```markdown
# План реализации

## Задача 1: Дизайн database schema (прогноз 5 минут)
- Создать todos таблица
- Определить поля: id, title, completed, createdAt

## Задача 2: Создать Express маршруты (прогноз 10 минут)
- POST /todos - создать задача
- GET /todos - получить список
- GET /todos/:id - получить один
- PUT /todos/:id - обновить
- DELETE /todos/:id - удалить

## Задача 3: Добавить входную валидацию (прогноз 10 минут)
- Название не может быть пусто
- completed должна быть bool

## Задача 4: Написать тесты (прогноз 15 минут)
- Для каждого endpoint написать тесты
- Охватить граничные случаи

## Задача 5: Запустить сервер и проверить (прогноз 5 минут)
- Запустить тесты
- Ручное тестирование API

Критерии приема:
- Все тесты проходят
- curl тест каждый endpoint работает нормально
```

#### executing-plans (Выполнение планов)

Этот навык пакетно выполнить плановые задачи, и пауза на каждый контрольный пункт для подтверждения.

**Пример использования**:

```
Выполнить план выше, каждая завершенная задача пауза
```

Claude будет:
1. Завершить задача 1, потом паузировать: `✅ Database schema завершена, продолжить?`
2. После вашего подтверждения завершить задача 2, снова паузировать
3. И так далее

Это позволяет вам на каждом этапе проверить направление правильное ли, избежать пробежать далеко перед обнаружением ошибок.

## Полный рабочий процесс Superpowers

Реальная власть Superpowers это комбинирование несколько навыков в полный процесс разработки.

### Стандартный процесс разработки

```
1. Brainstorming (Мозговой штурм)
   ↓ Через вопросы уточнить реальное требование

2. Design Document (Документ дизайна)
   ↓ Разделить дизайн, ждать подтверждение

3. Writing Plans (Написание планов)
   ↓ Разложить на 2-5 минутные маленькие задачи

4. Subagent Development (Разработка подагента)
   ↓ Каждая задача запустить независимый подагент
   ↓ Двухэтапная проверка: соответствие спецификации + качество кода

5. TDD (Тестовая разработка)
   ↓ Принудить RED-GREEN-REFACTOR

6. Code Review (Проверка кода)
   ↓ Контроль качества

7. Завершение
```

### Реальный пример: Построение системы аутентификации пользователя с Superpowers

Давайте через полный пример опытить процесс рабочего потока Superpowers.

#### Шаг один: Brainstorming уточнить требование

```
Мне нужна система аутентификации пользователя
```

Claude будет задать вам:
- Веб приложение или мобильное?
- Какие способы входа поддержать?
- Нужно ли восстановление пароля?
- Нужна ли функция «помнить меня»?
- ...

#### Шаг два: Сгенерировать документ дизайна

После подтверждения требований, Claude сгенерирует документ дизайна:

```markdown
# Дизайн системы аутентификации пользователя

## Требования функции
1. Регистрация пользователя (электронная почта + пароль)
2. Вход пользователя
3. Восстановление пароля (через почту)
4. Помнить меня (JWT + Refresh Token)

## Технологический выбор
- Бэкенд: Node.js + Express
- База данных: SQLite
- Аутентификация: JWT
- Кодирование: bcrypt

## Дизайн API
- POST /api/auth/register
- POST /api/auth/login
- POST /api/auth/refresh
- POST /api/auth/reset-password
```

#### Шаг три: Написать план реализации

```
Использовать writing-plans делать план реализации
```

Claude сгенерирует детальный список задач, каждая задача 2-5 минут может быть завершена.

#### Шаг четыре: Выполнить разработку

```
Используя TDD способ выполнить план выше
```

Claude будет:
1. Сначала писать тесты
2. Подтвердить тесты не пройдут (RED)
3. Писать код реализации
4. Подтвердить тесты пройдут (GREEN)
5. Переработать код (REFACTOR)

#### Шаг пять: Проверка кода

После завершения автоматически запустить проверку кода, проверить:
- Качество кода
- Безопасность (SQL инъекция, XSS и т.д.)
- Охват тестов
- Полнота документации

## Superpowers vs прямое использование Claude Code

| Измерение | Прямое использование Claude Code | Использование Superpowers |
|-----------|--------------------------------|---------------------------|
| **Уточнение требований** | AI напрямую начинает писать код | Сократический способ уточнить требование |
| **Процесс разработки** | Случайное свободное воспроизведение AI | Принудить TDD красно-зеленую переработку |
| **Управление задачей** | Один раз все | Разложить на маленькие задачи, с контрольными пункты |
| **Качество кода** | Зависит от суждение AI | Принудить проверка кода |
| **Предсказуемость** | Результат нестабилен | Процесс повторяемо |
| **Применимый сценарий** | Простая задача, проверка прототипа | Сложный проект, продакшн код |

### Образное сравнение

Если сравнить Claude Code с «умным стажером»:

- **Прямое использование**: Скажите стажеру «сделайте функцию входа», он напрямую начнет писать, возможно делать не то что вы хотите
- **Использование Superpowers**: Дайте стажеру опытного наставника, наставник спросит четко требование, делать план, проверить качество кода

## Лучшие практики

### 1. Ясно понять ключевые слова запуска

Навыки Superpowers запущены через ключевые слова, понимать общие слова запуска:

| Навык | Ключевые слова запуска |
|------|----------------------|
| `test-driven-development` | «TDD», «тестовая разработка», «сначала писать тест» |
| `brainstorming` | Размытое требование автоматически запустит |
| `systematic-debugging` | «Отладка», «баг», «не работает» |
| `writing-plans` | «Делать план», «планировать» |

### 2. Используйте Superpowers когда требуется дисциплина процесса

- Разработка продакшн кода → упомянуть «TDD»
- Требование размыто → позволить `brainstorming` помочь уточнить
- Сложный проект → использовать `writing-plans` разложить задачи

### 3. Простая задача не нужно принудить

Если быстрый прототип или одноразовый скрипт, не нужно полный процесс. Superpowers подходит долгосрочные разработки.

### 4. Навыки могут комбинироваться использовать

```
Используя TDD способ реализовать аутентификацию пользователя, после завершения помогите проверку кода
```

Это одновременно запустит `test-driven-development` и `code-review` навыки.

## Часто задаваемые вопросы

### Q1: Нужно ли указывать «TDD» когда используешь Superpowers?

**Не обязательно**.

Superpowers это набор навыков, каждый навык имеет свои условия запуска:
- Скажи «используя TDD способ» → запустить `test-driven-development`
- Не скажи TDD → Claude может писать тесты, может не писать (зависит модель)

Ценность Superpowers это **усилить дисциплину процесса**, не создать из ничего способность.

### Q2: Будет ли Superpowers медленнее разработку?

Вначале может ощущаться медленнее, потому что:
- Нужно время уточнить требование
- Нужно сначала писать тесты потом код
- Нужно проходить проверка кода

Но долгосрочно, потому что снижает возделку и баги, общая эффективность выше.

### Q3: Маленький проект нужно ли использовать Superpowers?

Для проверка прототипа или простая задача, можно прямо использовать Claude Code. Superpowers более подходит:
- Продакшн проекты
- Многолюдные сотрудничества проекты
- Долгосрочные разработки проекты

### Q4: Какая разница между Superpowers и Skills?

## Резюме

Superpowers это **набор инженерных навыков разработки**, сделал Claude Code от «умного стажера» к «дисциплинированной команде разработки».

### Ключевые моменты

1. **Superpowers это набор навыков, не магия**
   - После установки, навыки доступны в фоне
   - Запущены через ключевые слова или сценарии
   - Могут вручную вызывать конкретные навыки

2. **Помните ключевые слова запуска**
   - Хотел бы TDD → скажи «используя TDD способ»
   - Требование размыто → `brainstorming` активно спросит
   - Встречу баг → упомянуть «отладка» запустить `systematic-debugging`

3. **Применимые сценарии**
   - ✅ Разработка продакшн кода
   - ✅ Долгосрочные разработки проекты
   - ✅ Командные сотрудничества проекты
   - ❌ Быстрый прототип (опционально)
   - ❌ Одноразовый скрипт (опционально)

Помните: **Superpowers не делает AI умнее, а делает AI дисциплинированнее.**
