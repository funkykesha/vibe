# 1. Понимание границ возможностей AI

Прежде чем начать использовать AI для ассистирования при разработке, нам нужно понимать, что может делать AI, а что — нет. Только так мы сможем установить правильный способ сотрудничества.

## 1.1 На что хорош AI

Представьте AI как очень умного, но нуждающегося в четких инструкциях помощника. Он может быстро создать каркас кода на основе вашего описания, может прочитать несколько тысяч строк кода за несколько секунд и найти нужную вам часть. При встречи с явными ошибками синтаксиса, распространенными уязвимостями безопасности он также может помочь вам их выявить. Повторяющаяся работа, например массовое переименование переменных, форматирование кода, генерация документации комментариев — самое подходящее для него.

Проще говоря, AI хорош в работе, которая имеет четкие правила и может быть автоматизирована.

## 1.2 На что не хорош AI

Но AI также имеет свои ограничения. Он не понимает вашу бизнес-логику — если вы не расскажете ему подробно, он не будет знать, как у вас работает процесс заказов. Технологический выбор, архитектурный дизайн — это решения, требующие взвешивания преимуществ и недостатков, а AI не может это делать, потому что это требует вашего опыта и понимания проекта. Специальные правила вашей команды, например «все API должны добавить логирование», «коды ошибок должны использовать перечисления», AI также не будет знать, нужно ему рассказать или настроить.

Самое главное — код, созданный AI, нельзя использовать напрямую, вы должны проверить и протестировать. Он может написать код, который выглядит правильно, но на самом деле имеет проблемы, или может игнорировать некоторые граничные случаи.

## 1.3 Как сотрудничать с AI

Понимая границы возможностей AI, способ сотрудничества становится ясным: вы отвечаете за то, чтобы ясно понимать, что нужно делать, принимаете решения, гарантируете качество; AI отвечает за конкретную работу кодирования, поиск информации, выявление явных проблем.

Это похоже на работу с junior разработчиком — вы говорите ему, что делать, он это реализует, затем вы проверяете код. Разница в том, что AI работает намного быстрее, но суждение не такое хорошее.

# 2. Стратегии разработки для различных типов проектов

Разные типы проектов имеют разные способы разработки и стратегии использования AI. Выбор подходящей стратегии может значительно повысить эффективность разработки.

## 2.1 Совершенно новый проект (с нуля)

**Характеристики проекта:**
- Нет исторического багажа, можно свободно проектировать
- Нужно установить структуру проекта и правила кодирования
- Подходит для быстрой итерации и экспериментов

**Рекомендуемый рабочий процесс:**

**Первый шаг: Планирование структуры проекта**

Перед началом кодирования сначала позвольте AI помочь вам спланировать структуру проекта и технологический выбор:

```
Мне нужно создать приложение для управления задачами, функции включают:
- Регистрацию и вход пользователя
- Создание, редактирование, удаление задач
- Категоризацию и теги задач
- Напоминания о задачах

Пожалуйста, помогите мне:
1. Рекомендовать подходящий технологический стек
2. Спроектировать структуру каталогов проекта
3. Спланировать структуру таблиц базы данных
```

**Второй шаг: Построение основного каркаса**

На основе плана, позвольте AI создать основную структуру проекта:

```
Согласно только что созданному плану, пожалуйста:
1. Создайте структуру каталогов проекта
2. Инициализируйте конфигурационные файлы (package.json, .env и т.д.)
3. Создайте базовый код сервера
```

**Третий шаг: Реализация функций по приоритету**

Реализуйте функции по приоритету одну за другой:

```
Сейчас реализуйте функцию регистрации пользователя, требования:
- Регистрация по электронной почте и пароль
- Хеширование пароля при сохранении
- Верификация электронной почты
```

**Ключевые моменты:**
- Установите правила кодирования с самого начала, пусть AI генерирует код согласно этим правилам
- Протестируйте каждый модуль функции сразу после завершения
- Вовремя обновляйте документацию проекта

## 2.2 Зрелый проект (много существующего кода)

**Характеристики проекта:**
- Большой объем кода, есть исторические правила
- Нужно сохранять согласованность стиля кода
- Изменения нужно делать с учетом диапазона влияния

**Рекомендуемый рабочий процесс:**

**Первый шаг: Понимание структуры проекта**

Перед изменением кода, сначала позвольте AI помочь вам понять проект:

```
Это электронный проект, мне нужно добавить функцию купонов со скидками.
Пожалуйста, помогите мне:
1. Проанализировать общую структуру проекта
2. Найти код, связанный с заказами
3. Посмотреть, как реализованы другие похожие функции
```

**Второй шаг: Найти код для справки**

Позвольте AI найти похожие реализации в проекте как справку:

```
Найдите, как реализованы другие маркетинговые акции (такие как полная скидка, дисконт) в проекте
```

**Третий шаг: Имитировать существующий стиль**

Позвольте AI имитировать стиль существующего кода для реализации новой функции:

```
На основе реализации маркетинговой акции со скидкой, помогите мне реализовать функцию купонов
Сохраняйте тот же стиль кода и структуру каталогов
```

**Ключевые моменты:**
- Сначала поймите, потом действуйте, чтобы избежать разрушения существующей архитектуры
- Сохраняйте согласованность стиля кода
- После модификации протестируйте связанные функции

## 2.3 Быстрый прототип (проверка идеи)

**Характеристики проекта:**
- Главное — скорость, качество кода не так важно
- Используется для проверки идей продукта или технологических решений
- Может быть отброшен или переписан

**Рекомендуемый рабочий процесс:**

**Прямое описание требований и быстрая реализация:**

```
Создайте простое приложение со списком задач, требования:
- Может добавлять, удалять, отмечать завершение задач
- Данные хранятся локально
- Интерфейс простой, главное чтобы работало
```

**Быстрая итерация:**

```
Добавьте функцию поиска
Измените на темную тему
Добавьте категоризацию задач
```

**Ключевые моменты:**
- Не нужно уделять внимание качеству кода и правилам
- Быстро проверьте идею, вовремя скорректируйте направление
- Если прототип успешен, позже нужен рефакторинг

## 2.4 Проект поддержки (исправление багов)

**Характеристики проекта:**
- Код уже стабилен, главное исправление проблем
- Нужно быстро найти проблему
- Изменение нужно делать осторожно, чтобы не внести новые проблемы

**Рекомендуемый рабочий процесс:**

**Первый шаг: Поиск проблемы**

```
Пользователь сообщил: кнопка «Отправить заказ» нажимается, страница зависает
Консоль браузера показывает ошибку: TypeError: Cannot read property 'id' of undefined

Пожалуйста, помогите мне:
1. Проанализировать возможные причины
2. Найти связанный код
```

**Второй шаг: Анализ основной причины**

```
Посмотрите, откуда берется этот объект пользователя
Проверьте, в каких ситуациях пользователь может быть undefined
```

**Третий шаг: Внедрение исправления**

```
Исправьте эту проблему, и:
1. Добавьте защитный код, чтобы избежать похожих проблем
2. Добавьте сообщение об ошибке, улучшите пользовательский опыт
```

**Ключевые моменты:**
- После исправления полностью протестируйте, чтобы убедиться, что не влияет на другие функции
- Добавьте защитный код для повышения стабильности системы
- Документируйте проблему и решение для последующих ссылок

# 3. Рабочий процесс для общих задач разработки

В ежедневной разработке мы встречаем разные задачи. Ниже приводятся рабочие процессы для нескольких наиболее общих задач с AI.

## 3.1 Разработка новой функции

**Сценарий:** Менеджер продукта дал вам новое требование, нужно реализовать новую функцию.

**Полный рабочий процесс:**

**Шаг 1: Понимание требований** (вы сами)

Перед началом кодирования сначала разберитесь:
- Какую функцию нужно реализовать?
- Что такое вход и выход?
- Какие граничные условия и исключительные случаи?
- Какие требования к производительности и безопасности?

**Шаг 2: Понимание существующего кода** (попросите AI помочь)

```
Мне нужно реализовать функцию комментариев пользователей, помогите мне:
1. Посмотреть, есть ли в проекте похожие функции
2. Найти, как хранятся данные пользователя и статьи
3. Понять правила проекта по работе с базой данных
```

**Шаг 3: Разработка плана реализации** (совместно с AI)

```
Базируясь на только что выполненном анализе, реализация функции комментариев требует:
1. Создать модель данных комментариев
2. Реализовать API добавления, удаления, модификации и запроса комментариев
3. На фронтенде добавить дисплей комментариев и функцию публикации

Пожалуйста, помогите мне подтвердить, разумен ли этот план, есть ли упущение
```

**Шаг 4: Реализация функции** (AI генерирует, вы проверяете)

```
Согласно плану, сначала реализуйте модель данных комментариев
Требования:
- Содержит содержание комментария, автора, ID статьи, время создания
- Поддерживает вложенные ответы на комментарии
- Добавить необходимые индексы
```

```
Теперь реализуйте API интерфейс комментариев
Требования:
- Публикация комментария
- Удаление комментария (только свои)
- Получение всех комментариев к статье
- Поддержка пагинации
```

```
Наконец, реализуйте компонент комментариев на фронтенде
Требования:
- Дисплей списка комментариев
- Форма публикации комментариев
- Поддержка ответов на комментарии
```

**Шаг 5: Проверка и тестирование** (вы сами)

- Ручное тестирование основного рабочего процесса
- Тестирование граничных случаев (пустое содержание, очень длинное содержание и т.д.)
- Тестирование контроля доступа (не может удалить чужие комментарии)
- Попросите AI помочь написать автоматизированные тесты

**Пример реальной беседы:**

```
Вы: Мне нужно добавить функцию комментариев пользователей, пользователи могут публиковать комментарии к статьям

AI: Хорошо, сначала я посмотрю структуру проекта.
    [AI анализирует код проекта]
    Я вижу, что проект уже имеет систему пользователей (models/user.js) и систему статей (models/article.js).
    
    Реализация функции комментариев требует:
    1. Создать модель данных комментариев (models/comment.js)
    2. Добавить связанные API (routes/comment.js)
    3. На странице деталей статьи добавить дисплей и публикацию комментариев
    
    Начать реализацию?

Вы: Хорошо, начните. Сначала создайте модель данных

AI: [Генерирует код models/comment.js]
    Я создал модель данных комментариев со следующими полями:
    - id: ID комментария
    - content: содержание комментария
    - userId: ID автора
    - articleId: ID статьи
    - parentId: ID родительского комментария (для вложенных ответов)
    - createdAt: время создания
    
    Теперь реализовать API интерфейс?

Вы: Да, реализуйте API интерфейс
```

## 3.2 Исправление баг

**Сценарий:** Пользователь сообщил о проблеме, нужно быстро найти и исправить.

**Полный рабочий процесс:**

**Шаг 1: Сбор информации** (вы сами)

Запишите следующую информацию:
- Что такое сообщение об ошибке?
- Как повторить эту проблему?
- Когда она началась появляться?
- Какой диапазон влияния?

**Шаг 2: Поиск проблемы** (попросите AI помочь)

```
Пользователь сообщил: нажимаю кнопку «Отправить заказ», страница зависает
Консоль браузера показывает: TypeError: Cannot read property 'id' of undefined
Ошибка происходит на 45 строке в checkout.js

Пожалуйста, помогите мне:
1. Проанализировать возможные причины
2. Найти связанный код
3. Проверить поток данных
```

**Шаг 3: Анализ основной причины** (совместно с AI)

```
Посмотрите, откуда берется объект пользователя
Проверьте, в каких ситуациях пользователь может быть undefined
```

**Шаг 4: Внедрение исправления** (AI генерирует, вы проверяете)

```
Исправьте эту проблему, требования:
1. Добавьте защитный код, проверьте существование пользователя
2. Если пользователь не существует, перенаправьте на страницу входа
3. Добавьте дружественное сообщение об ошибке
```

**Шаг 5: Проверка исправления** (вы сами)

- Повторите оригинальные шаги для подтверждения исправления
- Протестируйте связанные функции, убедитесь в отсутствии новых проблем
- Подумайте, есть ли похожие проблемы в других местах

**Пример реальной беседы:**

```
Вы: Пользователь сообщил, что после входа при обновлении страницы выходит

AI: Обычно это проблема хранения или проверки токена. Дайте мне проверить:
    1. Где хранится токен? В localStorage или cookie?
    2. При обновлении страницы перечитывается ли токен?
    
    Пожалуйста, скажите мне, где находится код, связанный с токеном

Вы: В utils/auth.js

AI: [Анализирует utils/auth.js]
    Я нашел проблему: токен хранится в sessionStorage,
    при обновлении страницы sessionStorage очищается.
    
    Решение: измените на localStorage для хранения токена
    
    Нужно мне это исправить?

Вы: Хорошо, исправьте

AI: [Модифицирует код]
    Исправление завершено, теперь токен будет храниться в localStorage,
    при обновлении страницы не потеряется.
    
    Рекомендую протестировать:
    1. Войдите и обновите страницу, подтвердите, что остаются в статусе входа
    2. Закройте браузер и откройте заново, подтвердите, что остаются в статусе входа
```

## 3.3 Рефакторинг кода

**Сценарий:** Код становится сложным в поддержке, нужен рефакторинг для улучшения качества.

**Полный рабочий процесс:**

**Шаг 1: Определение цели рефакторинга** (вы сами)

Определите следующие проблемы:
- Какую проблему нужно решить? (повторяющийся код? путаная структура? проблемы производительности?)
- Какой диапазон рефакторинга?
- Какой уровень риска можно принять?

**Шаг 2: Разработка плана рефакторинга** (совместно с AI)

```
Эти три функции (getUserList, getArticleList, getCommentList)
имеют много повторяющегося кода, все они делают пагинацию, сортировку, фильтрацию.

Пожалуйста, помогите мне:
1. Проанализировать повторяющуюся часть
2. Предложить план рефакторинга
3. Оценить риск рефакторинга
```

**Шаг 3: Подготовка сети безопасности** (попросите AI помочь)

# 4. Построение базы знаний проекта

Чтобы AI лучше понимал ваш проект, рекомендуется построить базу знаний. Таким образом AI сможет работать согласно вашим правилам и привычкам.

## 4.1 Создание файла описания проекта

Создайте файл `CLAUDE.md` или `AGENTS.md` в корневом каталоге проекта, запишите ключевую информацию проекта:

```markdown
# Описание проекта

## Описание проекта
Это платформа онлайн образования, предоставляющая управление курсами, обучение пользователей, функции подачи заданий и т.д.

## Технологический стек
- Фронтенд: React 18 + TypeScript + Vite
- Бэкенд: Node.js + Express + PostgreSQL
- Развертывание: Vercel (фронтенд) + Railway (бэкенд)

## Структура проекта
```
src/
├── components/     # React компоненты
├── pages/         # Компоненты страниц
├── api/           # Вызовы API
├── utils/         # Утилиты функции
└── types/         # Определения типов TypeScript
```

## Правила кодирования
- Использовать ESLint и Prettier для форматирования кода
- Файлы компонентов используют PascalCase (например UserProfile.tsx)
- Утилиты функции используют camelCase (например formatDate.ts)
- Константы используют UPPER_SNAKE_CASE (например API_BASE_URL)

## Процесс разработки
1. Создать ветку функции из ветки main
2. После разработки отправить PR
3. После проверки кода слить ветку

## Общие задачи
- Запустить сервер разработки: `npm run dev`
- Запустить тесты: `npm test`
- Собрать продакшн версию: `npm run build`
- Форматировать код: `npm run format`

## Примечания
- Все вызовы API должны добавить обработку ошибок
- Пользовательский ввод должен быть проверен и экранирован
- Операции базы данных используют параметризованные запросы, избегите SQL инъекции
- Конфиденциальная информация (пароль, токен) не может быть записана в логи

## Структура таблиц базы данных
- users: таблица пользователей (id, email, password_hash, created_at)
- courses: таблица курсов (id, title, description, teacher_id)

Принято

Проект нуждается в выборе реляционной БД, кандидаты MySQL и PostgreSQL.

# 6. Часто задаваемые вопросы

## Q1: Можно ли напрямую использовать код, созданный AI?

**A:** Нельзя напрямую использовать, нужно проверить и протестировать.

Код, созданный AI может иметь следующие проблемы:
- Логические ошибки или неправильная обработка граничных случаев
- Не соответствует правилам кодирования проекта
- Есть скрытые уязвимости безопасности
- Производительность не оптимальна

Вам нужно:
- Внимательно прочитать созданный код
- Понять логику кода
- Протестировать разные ситуации
- Убедиться что соответствует правилам проекта

## Q2: Что делать если AI неправильно понял мое значение?

**A:** Вовремя исправьте и переопишите требование.

```
Это не то, я имел в виду...
Это неправильное понимание, должно быть...
Позвольте мне переописать требование...
```

Если несколько раз исправлять все еще не правильно, можно:
- Предоставить больше контекстной информации
- Дать конкретный пример кода
- Разделить на более мелкие задачи

## Q3: Что делать если встретить проблему, которую не знает AI?

**A:** AI не всемогущ, некоторые проблемы нужно решать самостоятельно.

AI может не суметь решить:
- Очень новые технологии (у AI есть временной предел знаний)
- Уникальная бизнес-логика вашей команды
- Проблемы которые требуют доступ к внешним системам
- Сложные проблемы оптимизации производительности

В этом случае нужно:
- Проверить официальную документацию
- Поискать похожие решения
- Проконсультироваться с опытным коллегой
- Спросить в сообществе

## Q4: Как судить правильность рекомендации AI?

**A:** Используйте свой опыт и знание для оценки.

Стандарты оценки:
- Соответствует ли лучшим практикам
- Считаны ли граничные случаи
- Есть ли потенциальные риски безопасности
- Соответствует ли технологическому стеку проекта
- Приемлема ли производительность

Если не уверены, можно:
- Попросить AI объяснить почему это решение
- Запросить другие планы
- Проконсультироваться с членами команды

## Q5: Как использовать AI при сотрудничестве команды?

**A:** Установите общие правила и базу знаний.

Рекомендации по сотрудничеству команды:
- Разделите конфигурацию CLAUDE.md проекта
- Единый стиль кодирования и правила
- Запишите решения часто встречаемых проблем
- Регулярно делитесь полезными шаблонами
- При проверке кода обращайте внимание на код, созданный AI

## Q6: Как избежать чрезмерной зависимости от AI?

**A:** Продолжайте учиться и размышлять, AI это вспомогательный инструмент, не замена.

Рекомендации:
- Поймите код, созданный AI, не копируйте слепо
- Активно учитесь, когда встречаетесь с неизвестными концепциями
- Регулярно повторяйте основные знания
- Попробуйте решить проблемы самостоятельно, потом проверьте с AI
- Участвуйте в проверке кода, учитесь у опыта других
