# Руководство по основным навыкам Claude Code

Claude Code — это официальный инструмент для работы с AI кодированием, разработанный компанией Anthropic. Он интегрирует возможности больших языковых моделей непосредственно в терминал, позволяя вам сотрудничать с AI на естественном языке при выполнении задач программирования. В отличие от традиционных инструментов автодополнения кода, Claude Code понимает контекст всего вашего проекта, выполняет сложные задачи разработки — от генерации кода до рефакторинга, от отладки до написания документации.

В этом разделе вы быстро освоите основные приёмы работы с Claude Code, включая установку и конфигурацию, базовые операции, практические советы и часто используемые команды. Независимо от того, впервые ли вы работаете с инструментами AI программирования или хотите использовать Claude Code более эффективно, здесь вы найдёте всё необходимые знания.

## Быстрая установка

Claude Code построен на базе Node.js, поэтому перед установкой убедитесь, что в вашей системе установлена версия Node.js 18 или выше. Процесс установки очень прост и обычно занимает всего несколько минут.

### Зачем нужен Claude Code

В традиционном цикле разработки разработчики часто переключаются между редактором, терминалом, браузером и документацией. Claude Code объединяет эти рабочие процессы в единый интерфейс: вы можете писать код, запускать тесты, просматривать документацию и даже сотрудничать с членами команды в одном окне терминала. Что ещё важнее, он понимает структуру вашего проекта, запоминает ваши привычки кодирования и действительно становится вашим помощником в программировании.

### Метод 1: Ручная установка

Ручная установка подходит для разработчиков, которые хотят контролировать каждый шаг, и дает вам лучше понимание компонентов инструмента.

```bash
# Глобально установить Claude Code CLI
# Используйте флаг -g, чтобы установить команду глобально для доступа из любой директории
npm install -g @anthropic-ai/claude-code

# Проверить успешность установки
# Если отобразится номер версии (например, 0.1.25), установка успешна
claude --version
```

Во время установки npm автоматически загружает все зависимости и конфигурирует переменные окружения. Если возникнут проблемы с правами доступа, попробуйте добавить `sudo` в начало команды (macOS/Linux) или запустить терминал от администратора (Windows).

### Метод 2: Использование AI Agent для установки

Если вы уже используете другие инструменты AI программирования (такие как Cursor, Windsurf или AI Agent этого проекта), они могут помочь вам с установкой. Преимущество этого подхода в том, что AI автоматически обнаружит вашу среду, обработает возможные конфликты зависимостей и выберет оптимальный способ установки в зависимости от конфигурации вашей системы.

**Просто скажите:**

```
Установи claude code от Anthropic
```

Или более конкретно:

```
Установи claude code cli и проверь совместимость версии Node.js
```

AI Agent будет:
1. Проверять текущую версию Node.js
2. При необходимости предложить её обновить
3. Выполнить команду установки
4. Проверить результаты установки
5. При наличии проблем автоматически попытается их исправить

### Первый запуск и инициализация

После установки перейдите в директорию вашего проекта и запустите Claude Code:

```bash
# Перейти в директорию проекта (Claude Code работает в текущей директории)
cd /path/to/your/project

# Запустить Claude Code
claude
```

При первом запуске Claude Code проведет вас через несколько важных шагов инициализации:

1. **Вход в аккаунт Anthropic**: Вам нужен аккаунт Anthropic для использования Claude Code. Если его нет, система предложит вам зарегистрироваться.

2. **Выбор плана использования**:
   - **Бесплатный план**: Подходит для личного обучения и легкого использования, имеет ограничения на количество вызовов
   - **Pro план**: Для профессиональных разработчиков, предоставляет более высокие квоты и приоритетный ответ

3. **Согласие с условиями использования**: Прочитайте и согласитесь с условиями обслуживания и политикой приватности Anthropic

4. **Опционально: конфигурация API ключа**: Если у вас есть собственный API ключ (например, полученный через сторонний поставщик услуг), вы можете его настроить

> **Важно для пользователей в Китае**
>
> Из-за сетевых причин пользователи в Китае могут не иметь прямого доступа к официальным услугам Anthropic. Claude Code поддерживает использование сторонних сервисов, совместимых с API Anthropic, что полностью возможно с технической точки зрения.
>
> **У вас есть два варианта:**
>
> 1. **Использовать API Token напрямую**: Купите Token у поставщика услуг, совместимого с Anthropic API, и настройте его через переменные окружения
> 2. **Использовать специальный Coding Plan**: Некоторые поставщики предлагают специальный Coding Plan, оптимизированный для сценариев кодирования, обычно более выгодный по цене
>
> **Рекомендуемый подход**: Позвольте AI Agent помочь вам с конфигурацией. Просто предоставьте информацию конфигурации от поставщика (адрес API, ключ и т.д.), и AI автоматически установит правильные переменные окружения.
>
> **Подробное руководство конфигурации см. здесь**: https://github.com/datawhalechina/easy-vibe/blob/main/docs/zh-cn/stage-2/backend/modern-cli/index.md

## Быстрый старт: несколько небольших экспериментов

После установки не спешите использовать Claude Code в реальных проектах. Рекомендуется проделать несколько небольших экспериментов, чтобы ознакомиться с тем, как работает Claude Code. Эти 3 эксперимента разработаны по принципу "от простого к сложному" и соответствуют трём ключевым возможностям Claude Code: пониманию естественного языка, генерации контента и исполнению кода.

### Эксперимент 1: Диалог — почувствуйте способность AI к пониманию

Цель этого эксперимента — испытать способность Claude Code к пониманию естественного языка. В отличие от обычной поисковой системы, Claude Code понимает контекст, ведет многоуровневый диалог и корректирует свои ответы в соответствии с вашей обратной связью.

**Попробуйте эти диалоги:**

```
Привет, кто ты?
```
Claude представится как Claude Code, инструмент AI программирования, разработанный Anthropic.

```
Что такое замыкание (closure)? Версия на одной странице
```
Обратите внимание на то, как Claude на основе подсказки "версия на одной странице" дает краткое, но точное объяснение.

```
В чем разница между JavaScript и TypeScript?
```
Этот вопрос требует сравнения технологий. Посмотрите, сможет ли Claude дать структурированный и глубокий ответ.

**Ключевые моменты эксперимента**: Обратите внимание на стиль ответов Claude — обычно он сначала дает основной вывод, а затем развивает детали. Такой "перевёрнутый пирамидальный" стиль ответов очень удобен для быстрого получения информации.

### Эксперимент 2: Генерация Markdown документации — испытайте создание контента

Этот эксперимент демонстрирует способность Claude Code к созданию контента. Для разработчиков написание документации часто является одной из самых сложных задач. Claude может быстро генерировать чётко структурированную и полную документацию в соответствии с вашими требованиями.

**Введите эту команду:**

```
Напиши для меня Markdown документацию часто используемых команд Git
Требования: включить команду, описание, примеры
```

**Что будет делать Claude:**

1. Анализировать ваши требования: часто используемые команды Git, формат Markdown, три элемента (команда, описание, пример)
2. Планировать структуру документации: обычно распределяет по сценариям использования (инициализация, ежедневная разработка, управление ветками, удаленное сотрудничество и т.д.)
3. Генерировать контент: предоставляет краткое описание и практические примеры для каждой команды
4. Форматировать вывод: использует синтаксис Markdown, обеспечивая правильное форматирование

**Примерный результат:**

```markdown
# Шпаргалка по часто используемым командам Git

## Инициализация репозитория

| Команда | Описание | Пример |
|---------|---------|---------|
| `git init` | Инициализировать новый репозиторий | `git init my-project` |
| `git clone` | Клонировать удалённый репозиторий | `git clone https://github.com/user/repo.git` |

...
```

**Продвинутая попытка**: Вы можете добавить дополнительные требования, такие как "добавить китайские комментарии", "упорядочить по частоте использования", "включить типичную обработку ошибок" и т.д. Посмотрите, как Claude адаптирует вывод.

### Эксперимент 3: Написание и запуск игры — полный рабочий процесс кода

Этот эксперимент наиболее сложен и демонстрирует полный рабочий процесс Claude Code: понимание требований, написание кода, создание файлов, запуск программы, обработка ошибок. Благодаря этому эксперименту вы действительно почувствуете мощь инструмента AI программирования.

**Введите эту команду:**

```
Напиши на Python игру "Змейка"
Требования:
1. Использовать библиотеку pygame
2. Показывать счёт
3. Выход по нажатию ESC

После написания помоги мне её запустить
```

**Claude выполнит следующие шаги:**

**Шаг 1: Проверка окружения**
- Проверить, установлен ли Python
- Проверить, доступна ли библиотека pygame
- При необходимости подсказать установку

**Шаг 2: Написание кода**
- Создать главный файл игры (например, `snake_game.py`)
- Реализовать логику игры: движение змейки, генерация пищи, обнаружение столкновений
- Добавить функцию отображения счёта
- Реализовать выход по нажатию ESC

**Шаг 3: Запуск игры**
- Выполнить Python скрипт для запуска игры
- Окно игры откроется, вы сможете управлять змейкой стрелками

**Шаг 4: Дальнейшая поддержка**
- Если в игре есть ошибка, вы можете сказать "змейка проходит сквозь стены, исправь"
- Если хотите добавить функцию, например "увеличивать сложность по мере роста счета", Claude продолжит модифицировать код

**Ценность этого эксперимента:**

1. **Проверка установки**: Убеждает вас, что Claude Code может корректно исполнять код
2. **Опыт взаимодействия**: Почувствуйте процесс совместной разработки с AI
3. **Уверенность**: Убедитесь, что AI способен независимо завершить полную, исполняемую программу

**Часто задаваемые вопросы:**

- **В: Что если я не установил pygame?**
  - О: Claude обнаружит это и предложит выполнить `pip install pygame`, или вы можете попросить Claude помочь с установкой

- **В: Что делать, если после запуска игры терминал занят?**
  - О: Нажмите ESC для выхода из игры, или продолжайте использовать Claude Code в другом окне терминала

- **В: Можно ли использовать другой язык программирования?**
  - О: Конечно! Попробуйте "напиши на JavaScript", "напиши на HTML5 Canvas" и т.д.

## Основные техники

Овладев этими техниками, вы значительно повысите эффективность работы с Claude Code. Эти техники основаны на практическом опыте разработки и охватывают наиболее часто встречающиеся сценарии операций.

### Техника 1: Двойное нажатие Esc для отката диалога — отмена ошибочных операций

Это наиболее часто используемое и самое важное сочетание клавиш в Claude Code. При сотрудничестве с AI вы можете ошибиться в словах, дать неправильную команду или быть недовольны ответом AI. Двойное нажатие Esc позволяет быстро "вернуться во времени".

**Детальное объяснение сочетаний клавиш:**

```
Одно нажатие Esc     → Очистить текущий ввод (похоже на Ctrl+C)
Двойное нажатие Esc  → Откатить к предыдущему состоянию диалога (отмена последнего раунда)
Тройное нажатие Esc  → Очистить всю историю диалога (начать заново)
```

**Сценарии использования:**

- **Сценарий A**: Вы случайно отправили неправильную команду, и Claude начал её выполнять. Быстро нажмите Esc дважды, чтобы откатить к состоянию до выполнения.
- **Сценарий B**: Ответ Claude не был тем, что вы хотели. Отройте Esc дважды, чтобы отменить, и переформулируйте вопрос.
- **Сценарий C**: Диалог прошёл много раундов, контекст запутался. Тройное нажатие Esc очищает все и даёт новый старт.

**⚠️ Важное замечание**: Двойное нажатие Esc откатывает **состояние диалога**, а не модификации кода. Если Claude уже изменил ваши файлы, эти изменения не будут автоматически отменены. Вам нужно вручную восстановить файлы с помощью `git checkout` или `git reset`.

**Рекомендация**: Перед выполнением операций, которые могут значительно изменить код, сначала зафиксируйте текущую работу (`git commit` или `git stash`), чтобы быстро восстановиться при возникновении проблем.

### Техника 2: Ссылка на файлы с @ — точное указание контекста

Claude Code может автоматически читать файлы проекта, но явная ссылка на файлы помогает AI точнее понять вашу цель и избежать чтения несвязанных файлов, что тратит Token.

**Базовое использование:**

Вместо неопределённого описания:
```
Объясни файл src/utils.ts
```

Лучше используйте прямую ссылку:
```
@src/utils.ts объясни этот файл
```

**Продвинутое использование:**

**Сравнительный анализ нескольких файлов:**
```
@src/app.tsx @src/components/Header.tsx какова связь между этими двумя файлами?
```

**Ссылка на директорию:**
```
@src/components/ выведи краткое описание всех компонентов в этой директории
```

**Ссылка на конкретные строки (при использовании редактора кода):**
```
@src/utils.ts:45-60 объясни назначение этого куска кода
```

**Рекомендации по использованию:**

1. **Tab автодополнение**: После ввода `@` нажмите Tab, Claude покажет список файлов в текущей директории, выбирайте стрелками
2. **Относительные пути**: Поддерживаются относительные пути, например `@./config.json` или `@../shared/types.ts`
3. **Нечёткое совпадение**: Можно вводить часть имени файла, например `@utils` совпадает с `src/utils.ts` или `src/utils/index.ts`

### Техника 3: ! для выполнения команд — интеграция с терминалом

Claude Code имеет встроенную способность выполнять команды терминала без необходимости переключаться в другое окно терминала.

**Базовое использование:**

```
!npm test           # Запустить тесты
!git status         # Проверить статус Git
!ls -la             # Вывести список файлов
```

**Практические сценарии применения:**

**Сценарий: запуск тестов и анализ причин сбоя**
```
!npm test
# После сбоя тестов
Проанализируй причины сбоя тестов и исправь код
```

**Сценарий: проверка различий Git**
```
!git diff
# Затем попроси Claude объяснить изменения
Выведи краткое описание основного содержания этих изменений
```

**Сценарий: построение проекта**
```
!npm run build
# При ошибке сборки
Ошибка сборки, помоги мне её исправить
```

**⚠️ Подсказка безопасности:**

Claude Code будет спрашивать подтверждение для выполнения чувствительных команд (например `rm -rf`, `sudo` и т.д.). Это защитный механизм, пожалуйста, подтвердите осторожно.

### Техника 4: /plan для планирования перед кодированием — правильный подход к сложным задачам

Для сложных задач разработки прямое начало кодирования часто неэффективно. Команда `/plan` позволяет Claude перейти в режим планирования, сначала разработать подробный план реализации, а затем выполнить его пошагово.

**Способ использования:**

```
/plan
Я хочу добавить функцию аутентификации пользователя, пожалуйста помоги мне разработать план реализации
```

**Что будет делать Claude:**

1. **Анализ требований**: Понять функцию, которую вы хотите реализовать
2. **Оценка текущего состояния**: Посмотреть на структуру текущего проекта и технический стек
3. **Разработка плана**: Пошагово перечислить действия, которые необходимо предпринять
4. **Подтверждение плана**: Обсудить с вами план и адаптировать на основе обратной связи

**Примерный результат:**

```
📋 План реализации функции аутентификации пользователя

Этап 1: Проектирование базы данных
- [ ] Создать таблицу users (id, email, password_hash, created_at)
- [ ] Создать таблицу sessions (id, user_id, expires_at)

Этап 2: Backend API
- [ ] POST /api/auth/register - регистрация пользователя
- [ ] POST /api/auth/login - вход пользователя
- [ ] POST /api/auth/logout - выход пользователя
- [ ] GET /api/auth/me - получить текущего пользователя

Этап 3: Интеграция Frontend
- [ ] Создать страницу входа
- [ ] Создать страницу регистрации
- [ ] Добавить маршруты защиты

Этап 4: Тестирование
- [ ] Написать модульные тесты
- [ ] Написать интеграционные тесты

С какого этапа вы хотите начать? Или нужно отрегулировать план?
```

**Лучшие практики:**

- Для задач, требующих более 30 минут, сначала используйте `/plan`
- После разработки плана выполняйте этап за этапом, проверяя каждый завершённый этап
- При изменении требований можно повторно запустить `/plan` для адаптации плана

### Техника 5: /init для автоматической генерации конфигурации — быстрая инициализация проекта

`/init` — одна из самых мощных команд Claude Code. Она может автоматически сканировать ваш проект, понимать технический стек и структуру, а затем генерировать полный файл конфигурации `CLAUDE.md`.

**Способ использования:**

```
/init
```

**Claude будет выполнять следующие шаги:**

1. **Сканирование структуры проекта**: Определить фреймворк, язык, инструмент сборки
2. **Анализ конфигурационных файлов**: Читать package.json, tsconfig.json и другие файлы
3. **Проверка стиля кода**: Понять соглашения об именовании, способ организации файлов
4. **Генерация CLAUDE.md**: Создать файл конфигурации с информацией о проекте

**Пример генерируемого файла CLAUDE.md:**

```
# Мой проект

## Технический стек
- Фреймворк: Next.js 14 (App Router)
- Язык: TypeScript
- Стили: Tailwind CSS
- Управление состоянием: Zustand
- База данных: Prisma + PostgreSQL

## Часто используемые команды

```bash
npm run dev      # Запустить dev сервер
npm run build    # Продакшн сборка
npm run test     # Запустить тесты
npx prisma migrate dev  # Миграция БД
```

## Соглашения о коде
- Использовать функциональные компоненты + Hooks

- Коммиты: Conventional Commits
```

**Почему это важно:**

`CLAUDE.md` — это "память проекта" для Claude Code. При каждом запуске Claude автоматически читает этот файл и узнает предысторию проекта. Это означает:

- Вам не нужно каждый раз объяснять, какой фреймворк использует проект
- Claude будет знать ваши соглашения о коде и лучшие практики
- При командной работе новые члены команды могут быстро ознакомиться с проектом

**Рекомендация**: Сразу после инициализации нового проекта запустите `/init`, а затем подрегулируйте сгенерированную конфигурацию в соответствии с вашей действительной ситуацией.

### Техника 6: /compact для сжатия контекста — экономия Token

Контекстное окно Claude Code ограничено (обычно 200K Token). Длинные диалоги потребляют много Token, что не только увеличивает затраты, но может привести к вытеснению важной ранней информации из контекстного окна.

**Способ использования:**

```
/compact
```

**Принцип работы:**

`/compact` анализирует историю текущего диалога, извлекает ключевую информацию (такую как принятые решения, сгенерированный код, подтверждённые требования), а затем генерирует краткую сводку. Последующие диалоги основаны на этой сводке, а не на полной истории.

**Когда использовать:**

- После 5-6 раундов диалога
- Когда вы чувствуете, что Claude начинает "забывать" прошлое содержание
- Когда переходите на новую подзадачу, но хотите сохранить ключевой контекст

**Рекомендация по использованию:**

```
# После длинного диалога сжать контекст
/compact

# После сжатия продолжить работу
Теперь мы завершили модуль пользователей, перейдём к модулю заказов
```

### Техника 7: Использование Claude Code для помощи в коммитах Git

В Claude Code рекомендуемый процесс коммита — сначала позволить Claude помочь посмотреть diff, организовать сообщение коммита, а затем выполнить стандартные команды Git для завершения коммита. Таким образом как ясно, так и удобно повторно проверить содержание изменений перед коммитом.

Официальная документация:

- [Built-in commands](https://code.claude.com/docs/en/commands)
- [Discover plugins](https://code.claude.com/docs/en/discover-plugins)

**Рекомендуемый рабочий процесс:**

```bash
# 1. Проверить текущие изменения
/diff
!git status

# 2. Позволить Claude выработать краткое описание изменений и генерировать сообщение коммита
Пожалуйста, на основе текущего git diff, согласнонорм Conventional Commits,
сгенерируй сообщение коммита и объясни на английском, почему такая классификация

# 3. После подтверждения, выполнить стандартный Git коммит
!git add -A
!git commit -m "feat(docs): update Claude Code workflow guidance"
```

**Преимущества этого метода:**

1. **Больше соответствует текущим возможностям**: Не зависит от уже удалённых встроенных команд
2. **Больше прозрачности**: Вы можете проверить diff и сообщение коммита перед коммитом, а затем решить, совершать ли коммит
3. **Более универсально**: При переходе на другие AI IDE или чистое окружение Git этот рабочий процесс остаётся действителен

**Если вы хотите сохранить опыт "один-командный коммит":**

Claude Code теперь рекомендует восстановить такую способность через плагины. Например, в примере официального маркетплейса плагинов используется плагин `commit-commands`, который предоставляет команду `/commit-commands:commit`.

```bash
# 1. Добавить пример маркетплейса плагинов
/plugin marketplace add anthropics/claude-code

# 2. Установить плагин рабочего процесса коммитов
/plugin install commit-commands@anthropics-claude-code

# 3. Перезагрузить плагины
/reload-plugins

# 4. Использовать команду плагина для коммита
/commit-commands:commit
```

**Дополнительное уточнение:**

- `/commit-commands:commit` — команда, предоставляемая плагином, а не встроенная команда Claude Code по умолчанию
- Если вы просто хотите проверить изменения перед коммитом, приоритетно используйте `/diff` или попросите Claude прямо прочитать `git diff`
- Официально `/review` также отмечена как deprecated; если вам нужна похожая способность, рекомендуется использовать плагины или рабочий процесс проверки на естественном языке

### Техника 8: Shift+Tab для автоматического принятия — повышение плавности работы

По умолчанию Claude спросит ваше подтверждение перед модификацией кода. На стадии обучения это очень полезно, но после ознакомления может показаться утомительным. `Shift+Tab` включает режим автоматического принятия, делая рабочий процесс более гладким.

**Способ использования:**

- Нажать `Shift+Tab` → Войти в режим автоматического принятия
- Снова нажать `Shift+Tab` → Выйти из режима автоматического принятия

**Сравнение режимов:**

| Режим | Поведение | Сценарий применения |
|-------|-----------|-------------------|
| Режим по умолчанию | Каждый раз спрашивать подтверждение перед изменением | Стадия обучения, важный код |
| Автоматическое принятие | Применить изменение напрямую | После ознакомления, быстрая итерация |

**⚠️ Замечания:**

- В режиме автоматического принятия Claude будет напрямую модифицировать файлы без повторного подтверждения
- Рекомендуется использовать вместе с Git, чтобы при возникновении проблем можно было откатиться
- Для чувствительных операций (таких как удаление файлов, модификация конфигурации), Claude всё ещё будет спрашивать

### Техника 9: Ctrl+C для отмены операции — экстренное торможение

Когда Claude выполняет долгоживущую задачу, или вы осознаёте, что дали неправильную команду, `Ctrl+C` — ваша кнопка "экстренного торможения".

**Способ использования:**

- Нажать один раз `Ctrl+C` → Отменить текущую выполняющуюся операцию
- Нажать два раза `Ctrl+C` → Полностью выйти из Claude Code

**Сценарии использования:**

- Claude выполняет долгую команду, и вы хотите её прервать
- Claude начал генерировать большое количество не относящегося к делу кода
- Вы осознаёте, что дали неправильную команду и хотите немедленно остановить

**Различие с двойным нажатием Esc:**

- `Ctrl+C`: Остановить текущую выполняющуюся **операцию** (такую как запуск команды, генерирование кода)
- `Двойное нажатие Esc`: Откатить **состояние диалога** (отмена последнего раунда диалога)

### Техника 11: /resume для восстановления сессии — переключение между многозадачными диалогами

Когда вы обрабатываете несколько задач одновременно, вы можете открыть несколько диалогов. `/resume` позволяет быстро переключиться обратно на предыдущую сессию в текущем чате, без необходимости выходить и перезапускать.

**Способ использования:**

```
/resume
```

**Принцип работы:**

Claude Code автоматически записывает ваши прошлые диалоговые сессии. Когда вы используете `/resume`, она переключит контекст обратно к предыдущей сессии, сохранив все предыдущие обсуждения и состояние.

**Сценарии использования:**

**Сценарий A: Параллельная работа с несколькими задачами**
```
# Задача 1: Исправление ошибки
claude> Исправить проблему валидации на странице входа
# ... прошли диалог...

# Задача 2: Добавление новой функции (новая сессия)
claude> Добавить функцию регистрации пользователя
# ... прошли другой диалог...

# Переключиться обратно на задачу 1
claude> /resume
# Продолжить работу по исправлению ошибки
```

**Сценарий B: Временный запрос и возвращение**
```
claude> Объясни этот алгоритм
# ... обсудили алгоритм...

claude> /resume
# Автоматически переключиться обратно к предыдущей работе по разработке кода
```

**Сценарий C: Продолжение после перерыва в диалоге**
```
claude> Продолжить предыдущую работу
# Если вы раньше прервали какую-то задачу, используйте /resume для возвращения
```

**Сравнение с похожими командами:**

| Команда | Функция | Сценарий использования |
|---------|---------|----------------------|
| `/resume` | Переключиться на предыдущую сессию в текущем чате | Многозадачность, нужно переключаться взад-вперёд |
| `claude -c` | Продолжить последнюю сессию | Выход и переподключение к той же сессии |
| `claude -r` | Восстановить предыдущую сессию | Выход и восстановление предыдущего состояния сессии |
| `Двойное нажатие Esc` | Откатить до предыдущего состояния диалога | Отмена последнего раунда диалога |

**Рекомендации по использованию:**

1. **Управление несколькими задачами**: Когда вам нужно переключаться между несколькими задачами, использование `/resume` более эффективно, чем переписывание контекста
2. **Память сессии**: Каждая сессия имеет независимый контекст, `/resume` может помочь вам сохранить эти контексты
3. **Использование вместе с /compact**: В длинных сессиях можно сначала `/compact` сжать контекст, а затем `/resume` переключиться, сохраняя контекст ясным

## Основная конфигурация

Правильная конфигурация может помочь Claude Code лучше адаптироваться к вашему проекту и команде. В этом разделе介绍 назначение конфигурационных файлов, приоритеты и как оптимизировать конфигурацию для различных сценариев использования.

### Расположение конфигурационных файлов и приоритеты

Claude Code использует многоуровневую стратегию конфигурации, разные уровни конфигурации имеют разные области действия и приоритеты. Понимание этого механизма позволяет вам более гибко управлять конфигурацией.

**Приоритеты конфигурации (от высокого к низкому):**

| Расположение | Область действия | Назначение | Отправлять ли в Git |
|--------------|------------------|-----------|-------------------|
| `.claude/settings.local.json` | Локальное проекта | Личные предпочтения | ❌ Нет |
| `.claude/settings.json` | Совместная проекта | Единые конфигурации команды | ✅ Да |
| `~/.claude/settings.json` | Глобальное | Личные конфигурации по умолчанию | ❌ Нет |

**Правила слияния конфигураций:**

- Конфигурация с более высоким приоритетом перекрывает конфигурацию с более низким приоритетом на один и тот же элемент
- Конфигурационные элементы без конфликтов будут объединены и вступят в силу
- Конфигурация уровня проекта имеет приоритет над глобальной конфигурацией, личная локальная конфигурация имеет приоритет над совместной конфигурацией

**Практические сценарии применения:**

**Сценарий 1: Командный проект**
```
~/.claude/settings.json          # Ваши личные настройки редактора по умолчанию
.claude/settings.json            # Единые соглашения о коде команды, конфигурация прав
.claude/settings.local.json      # Ваши личные предпочтения отладки, настройки темы
```

**Сценарий 2: Личный проект**
```
~/.claude/settings.json          # Глобальные конфигурации по умолчанию
.claude/settings.json            # Конфигурации, специфичные для проекта (такие как специальные правила прав)
```

### CLAUDE.md - память проекта

`CLAUDE.md` — самый важный конфигурационный файл Claude Code. Это своего рода "инструкция" для проекта. Каждый раз при запуске Claude Code он автоматически читает `CLAUDE.md` в текущей директории, узнавая предысторию, технический стек и соглашения проекта.

**Почему CLAUDE.md настолько важна?**

Представьте такой сценарий: вы присоединились к новому проекту, нужно ознакомиться с техническим стеком, соглашениями о коде, часто используемыми командами. Обычно вам нужно потратить часы на чтение документации, изучение кода, общение с коллегами. С `CLAUDE.md` Claude Code при запуске уже знает всю эту информацию, вы можете сразу начать эффективное сотрудничество.

Если у вас уже есть проект, но нет `CLAUDE.md`, запустите команду `/init`, чтобы Claude автоматически генерировала конфигурацию:

```bash

```

Claude проанализирует структуру вашего проекта, package.json, существующий код и сгенерирует подходящий `CLAUDE.md`. После генерации рекомендуется вручную проверить и при необходимости адаптировать конфигурацию.

### .claudeignore — экономия Token

Файл `.claudeignore` сообщает Claude Code, какие файлы не должны читаться в контекст. Правильная конфигурация может значительно снизить потребление Token (обычно на 40-60%), а также увеличить скорость ответа.

**Зачем нужен .claudeignore?**

Claude Code при понимании проекта пытается прочитать связанные файлы. Но некоторые файлы не помогают в понимании проекта, а наоборот:
- Потребляют много Token (например, определения типов в node_modules)
- Вносят шум (файлы логов, произведённые сборкой)
- Содержат чувствительную информацию (файлы .env)

**Рекомендуемая конфигурация:**

3. **Регулярно оптимизируйте**: используйте `/context` для просмотра, какие файлы потребили больше всего Token, рассмотрите добавление их в список игнорирования

### Конфигурация прав доступа

Claude Code по умолчанию перед выполнением чувствительных операций будет спрашивать подтверждение. Через конфигурацию `permissions` в `settings.json` вы можете точно контролировать, какие операции выполняются автоматически, какие требуют подтверждения, а какие полностью запрещены.

**Структура конфигурации прав:**

```json
{
  "permissions": {
    "allow": [
      // Автоматически разрешены, без подтверждения
    ],
    "ask": [
      // Перед выполнением спрашивать подтверждение
    ],
    "deny": [
      // Полностью запрещены
    ]
  }
}
```

**Синтаксис конфигурации прав:**

Правила прав используют формат `ТипОперации(ШаблонСовпадения)`:

| Тип операции | Описание | Пример |
|------------|---------|--------|
| `Bash` | Выполнение команд терминала | `Bash(git status)` |
| `Edit` | Редактирование файлов | `Edit(src/**/*.ts)` |
| `Read` | Чтение файлов | `Read(README.md)` |
| `Write` | Создание новых файлов | `Write(src/components/*.tsx)` |

**Шаблоны совпадения поддерживают подстановочные знаки:**

- `*` совпадает с любыми символами (кроме `/`)
- `**` совпадает с любыми путями
- `?` совпадает с одним символом

**Практические примеры конфигурации:**

```json
{
  "permissions": {
    "allow": [
      "Bash(git status)",
      "Bash(git log:*)",
      "Bash(git diff:*)",
      "Bash(npm test:*)",
      "Bash(npm run lint:*)",
      "Edit(src/**/*.{ts,tsx})",
      "Edit(tests/**/*.test.ts)",
      "Read(src/**/*.ts)",
      "Write(src/components/*.tsx)"
    ],
    "ask": [
      "Bash(git commit:*)",
      "Bash(git push:*)",
      "Bash(git pull:*)",
      "Bash(npm install:*)",
      "Bash(npm run build)",
      "Edit(package.json)",
      "Edit(tsconfig.json)",
      "Read(.env)",
      "Read(config/secrets.*)"
    ],
    "deny": [
      "Bash(rm -rf:*)",
      "Bash(sudo:*)",
      "Bash(curl * | sh)",
      "Bash(wget * | sh)",
      "Edit(.git/*)",
      "Write(/etc/*)",
      "Read(/etc/passwd)"
    ]
  }
}
```

**Рекомендации по конфигурации:**

1. **На этапе разработки**: установите более свободные права для увеличения скорости итерации
2. **На production**: ограничьте права, особенно для операций развёртывания и доступа к чувствительным данным
3. **При командной работе**: поместите базовые права в `settings.json` (совместное использование), личные настройки — в `settings.local.json`

### Директория Rules для организацииправил

Для больших проектов один файл `CLAUDE.md` может стать громоздким и сложным в обслуживании. Claude Code поддерживает использование **директории Rules** для модульной организации, расщепляя различные аспекты규范 на отдельные файлы.

**Структура директории:**

```
.claude/
├── settings.json          # Основной конфигурационный файл
├── CLAUDE.md              # Обзор проекта (всё ещё требуется)
└── rules/                 # Директория правил
    ├── 00-security.md     # Правила безопасности (глобальные)
    ├── 01-coding-style.md # Стиль кодирования (глобальные)
    ├── 10-api.md          # APIнорм разработки
    ├── 11-frontend.md     # Фронтенднорм
    ├── 12-backend.md      # Бэкенднорм
    └── 20-testing.md      # Правила тестирования
```

**Рекомендации по именованию файлов:**

Используйте числовые префиксы для управления порядком загрузки (например `00-`, `01-`), убедитесь, что базовые правила загружаются раньше, а специфические — позже.

**Формат файлов правил:**

Файлы правил поддерживают YAML frontmatter для управления областью применения правил:

```markdown
---
# Опционально: укажите пути файлов, к которым применяются правила
globs:
  - "src/api/**/*.ts"
  - "src/services/**/*.ts"

# Опционально: укажите команды, к которым применяются правила
commands:
  - "generate api"
  - "create endpoint"

# Опционально: приоритет правил (меньшее число — выше приоритет)
priority: 10
---

# APIнорм разработки

## Проектирование маршрутов
- RESTful стиль, использовать множественное число существительных
- Версионирование: /api/v1/users
- Вложенные ресурсы: /api/v1/users/123/orders

## Формат запроса/ответа
- Единообразно использовать JSON
- Ошибочный ответ должен содержать code и message
- Пагинация использует структуру { data, pagination }

## Требования безопасности
- Все эндпоинты должны проверить аутентификацию (кроме открытых)
- Чувствительные операции требуют двойного подтверждения
- Реализовать ограничение скорости для предотвращения злоупотреблений
```

**Наследование и переопределение правил:**

- Глобальные правила (без frontmatter или `globs: *`) применяются ко всем файлам
- Правила для конкретного пути применяются только к совпадающим файлам
- При конфликте нескольких правил правило с более высоким приоритетом вступает в силу
- Специфичные правила могут переопределить глобальные правила

**Примеры сценариев использования:**

**Сценарий 1: Проект с раздельным фронтенд-бэкенд**
```
.claude/rules/
├── 00-general.md          # Общиенорм (сообщения коммитов, соглашения об именовании)
├── 10-backend.md          # Бэкенднорм (специфическая NestJS)
├── 11-frontend.md         # Фронтенднорм (специфическая React)
└── 20-database.md         # Правила БД (специфическая Prisma)
```

**Сценарий 2: Архитектура микросервисов**
```
.claude/rules/
├── 00-global/             # Глобальные правила
│   ├── security.md
│   └── logging.md
├── 10-services/           # Правила для конкретных сервисов
│   ├── user-service.md
│   ├── order-service.md
│   └── payment-service.md
└── 20-shared/             # Правила для общих компонентов
    ├── shared-lib.md
    └── common-utils.md
```

**Рекомендации по миграции:**

Если у вас есть большой файл `CLAUDE.md`, вы можете мигрировать в директорию Rules по следующим шагам:

1. Создать директорию `.claude/rules/`
2. Разделить содержимое `CLAUDE.md` по темам
3. Добавить соответствующий frontmatter к каждому файлу правил
4. Сохранить `CLAUDE.md` как обзор проекта, удалить подробныенорм
5. Проверить, что правила правильно загружаются

## Основные команды операций

Claude Code предоставляет полный набор команд операций, позволяющих вам эффективно сотрудничать с AI. Эти команды разделены на несколько категорий: команды Slash (встроенные функции), система символов (быстрые операции) и команды на естественном языке (повседневная разработка).

### Быстрая справка по командам Slash

Команды Slash — это встроенные функции Claude Code, начинающиеся с `/`. Они предоставляют стандартизированные операции, такие как инициализация проекта, управление конфигурацией, просмотр состояния и т.д.

| Команда | Функция | Сценарий использования |
|---------|---------|----------------------|
| `/help` | Показать все команды | Быстро посмотреть команды при забывчивости |
| `/init` | Инициализировать проект, генерировать CLAUDE.md | Новый проект или добавление конфигурации |
| `/plan` | Войти в режим планирования | Разработать план перед сложной задачей |
| `/clear` | Очистить историю диалога | Перезагрузить контекст при его запутанности |
| `/compact` | Сжать контекст | Экономия Token при длинных диалогах |
| `/diff` | Открыть интерактивное представление diff | Просмотр текущих незафиксированных изменений |
| `/plugin` | Управление плагинами | Установка расширенных возможностей коммитов,审查 и т.д. |
| `/context` | Просмотр использования контекста | Оптимизация потребления Token |
| `/cost` | Просмотр стоимости текущей сессии | Контроль затрат на использование |
| `/config` | Открыть панель конфигурации | Изменить настройки |
| `/permissions` | Управление правами доступа | Отрегулировать права операций |
| `/model` | Переключить AI модель | Выбрать другую модель |

**Примеры сочетания команд:**

```bash
# Полный рабочий процесс разработки
/plan                    # 1. Разработать план
# ... выполнить разработку ...
/diff                    # 2. Просмотр изменений
Пожалуйста, на основе текущего diff сгенерируй сообщение коммита
!git add -A              # 3. Зафиксировать изменения
!git commit -m "..."     # 4. Совершить коммит
/cost                    # 5. Посмотреть затраты
```

### Система символов

Система символов — это способ быстрой операции в Claude Code, через специальные символы быстро запускаются специфические функции.

| Символ | Название | Назначение | Пример |
|--------|----------|-----------|--------|
| `/` | Slash команда | Выполнить встроенную операцию | `/help`, `/plan` |
| `@` | At ссылка | Ссылка на файл/директорию | `@src/app.tsx` |
| `!` | Bang режим | Выполнить команду терминала | `!npm test` |
| `&` | Фоновое выполнение | Фоновое выполнение задачи | `&npm run dev` |

## Часто задаваемые вопросы

При использовании Claude Code вы можете столкнуться с различными вопросами. В этом разделе собраны самые частые вопросы и их решения.

### Token потребляется слишком быстро?

Быстрое потребление Token — наиболее распространённая проблема при использовании Claude Code. Ниже приведена полная стратегия оптимизации использования Token.

**Диагностика проблемы:**

Сначала используйте команду `/context` для просмотра текущего использования Token:
```
/context
```

Обратите внимание на следующие показатели:
- **Процент использования Token**: если превышает 70%, нужно рассмотреть сжатие контекста
- **Количество ссылок на файлы**: чем больше файлов, тем больше Token потребляется
- **Крупные файлы**: посмотрите, какие файлы потребили больше всего Token

**Стратегии оптимизации:**

**1. Совершенствование конфигурации .claudeignore**

Убедитесь, что ваш файл `.claudeignore` содержит все ненужные файлы:
```
# Обязательно игнорировать
node_modules/
dist/
build/
*.log
.env

# Добавить по типу проекта
# React проект
.next/
out/

# Vue проект
.nuxt/
.output/

# Общее
.vscode/
.idea/
coverage/
*.min.js
*.bundle.js
```

**2. Регулярное сжатие контекста**

Длинные диалоги накапливают много Token. Рекомендуется использовать `/compact` после каждых 5-6 раундов диалога:
```
# После длинного диалога
/compact

# Продолжить работу
Теперь реализуем модуль заказов...
```

**3. Точная ссылка на файлы**

Не ссылайтесь на целые директории, ссылайтесь на конкретные нужные файлы:
```bash
# Не рекомендуется (прочитает целую директорию)
@src/ объясни этот код

# Рекомендуется (прочитает только нужные файлы)
@src/utils/auth.ts @src/components/Login.tsx объясни процесс входа
```

**4. Избегайте чтения больших файлов**

Если `/context` показывает, что какой-то файл потребил много Token, рассмотрите:
- Действительно ли нужен этот файл?
- Можно ли ссылаться только на часть кода?
- Можно ли разделить большой файл на меньшие модули?

### Claude не понимает проект?

Когда ответы Claude недостаточно точны или она часто спрашивает базовую информацию о проекте, это говорит, что ей не хватает знаний о контексте проекта.

**Решение:**

**1. Генерировать CLAUDE.md**

Запустите `/init`, чтобы Claude автоматически сгенерировала конфигурацию проекта:
```bash
/init
```

После генерации проверьте и дополните следующее:
- Точна ли информация в обзоре проекта?
- Полный ли технический стек?
- Правильны ли часто используемые команды?
- Ясны ли соглашения о коде?

**2. Ручное редактирование CLAUDE.md**

Если автоматически сгенерированная конфигурация недостаточно детальна, добавьте вручную:
```markdown
## Информация, специфичная для проекта

### Архитектурные решения
- Почему выбран X а не Y?
- Какой основной паттерн дизайна?

### Общие ошибки
- При использовании useEffect нужно обратить внимание на...
- Запросы в БД должны...

### Интеграции с внешними сервисами
- Платежи используют Stripe
- Email используют SendGrid
- Хранилище файлов использует AWS S3
```

**3. Использование директории Rules**

Крупные проекты могут использовать директорию Rules для организации規范:
```
.claude/rules/
├── 00-architecture.md    # Обзор архитектуры
├── 01-coding-style.md    # Стиль кодирования
├── 10-frontend.md        # Фронтенднорм
├── 11-backend.md         # Бэкенднорм
└── 20-testing.md         # Правила тестирования
```

**4. Добавить контекст в команду**

Для конкретных задач добавьте контекст в команду:
```
Мы используем пользовательский Hook useAuth для обработки аутентификации,
он возвращает { user, login, logout, isLoading }.
На основе этого Hook реализуй компонент меню пользователя.
```

### Как откатить операцию?

Claude Code предоставляет несколько механизмов отката для различных сценариев.

**Сценарий 1: Откат состояния диалога**

Если вы просто ошиблись в словах или недовольны ответом Claude:
```
Двойное нажатие Esc  →  Откатить к предыдущему раунду диалога
Тройное нажатие Esc  →  Очистить всю историю диалога
```

**⚠️ Замечание**: это откатывает только состояние диалога, не отменяет модификации файлов.

**Сценарий 2: Отмена модификации файлов**

Если Claude уже изменила файлы, вам нужно вручную отменить:

```bash
# Просмотр изменений
!git status
!git diff

# Отмена конкретного файла
git checkout -- src/utils/helpers.ts

# Отмена всех изменений
git checkout -- .

# Если уже был совершён коммит
# Мягкий откат (сохраняет изменения)
git reset --soft HEAD~1

# Жёсткий откат (отбрасывает изменения)
git reset --hard HEAD~1
```

**Сценарий 3: Использование Git рабочего процесса для предотвращения**

Лучшая практика — совершить текущую работу перед использованием Claude Code:
```bash
# Сохранить текущее состояние перед началом
git add .
git commit -m "WIP: before Claude Code session"
# или использовать git stash
git stash push -m "before claude"

# Использовать Claude Code для разработки...

# Если результат не удовлетворяет, полностью откатить
git reset --hard HEAD~1
# или
git stash pop
```

### Слишком много подтверждений прав доступа?

Частые подтверждения прав доступа влияют на эффективность разработки. Путём правильной конфигурации прав можно сделать рабочий процесс более гладким.

**Понимание системы прав:**

Права Claude Code разделены на три уровня:
- **allow**: автоматически разрешено, без подтверждения
- **ask**: спросить подтверждение перед выполнением
- **deny**: полностью запрещено

**Оптимизация конфигурации:**

Отредактируйте `.claude/settings.json`:

```json
{
  "permissions": {
    "allow": [
      // Только для чтения Git операции
      "Bash(git status)",
      "Bash(git log:*)",
      "Bash(git diff:*)",
      "Bash(git branch)",
      
      // Тестирование и проверка
      "Bash(npm test:*)",
      "Bash(npm run lint:*)",
      "Bash(npm run typecheck)",
      
      // Dev сервер
      "Bash(npm run dev:*)",
      
      // Редактирование исходного кода
      "Edit(src/**/*.{ts,tsx})",
      "Edit(tests/**/*.test.ts)",
      "Write(src/**/*.ts)"
    ],
    "ask": [
      // Git операции записи
      "Bash(git commit:*)",
      "Bash(git push:*)",
      "Bash(git pull:*)",
      
      // Управление пакетами
      "Bash(npm install:*)",
      "Bash(npm uninstall:*)",
      
      // Сборка и развёртывание
      "Bash(npm run build)",
      "Bash(npm run deploy:*)",
      
      // Редактирование файлов конфигурации
      "Edit(package.json)",
      "Edit(tsconfig.json)",
      
      // Чтение чувствительных файлов
      "Read(.env)",
      "Read(config/secrets.*)"
    ],
    "deny": [
      // Опасные команды
      "Bash(rm -rf:*)",
      "Bash(sudo:*)",
      "Bash(curl * | sh)",
      "Bash(wget * | sh)",
      
      // Системные файлы
      "Edit(/etc/*)",
      "Write(/usr/*)",
      
      // Git директория
      "Edit(.git/*)"
    ]
  }
}
```

**Прогрессивная стратегия прав доступа:**

- **На этапе обучения**: сохраняйте настройки по умолчанию, учитесь, какие операции будет выполнять Claude
- **На этапе знакомства**: добавьте частые безопасные операции (как git status, npm test) в allow
- **На этапе эффективности**: на основе особенностей проекта задайте более точные правила прав

### Как использовать в Китае?

Из-за сетевых причин пользователи в Китае могут не иметь прямого доступа к официальным услугам Anthropic. Ниже приведены несколько решений.

**Решение 1: Использование API прокси-сервиса**

Многие облачные поставщики услуг предоставляют прокси-сервис совместимый с API Anthropic:

```bash
# Установить переменные окружения
export ANTHROPIC_BASE_URL="https://your-api-proxy.com/v1"
export ANTHROPIC_API_KEY="your-api-key"

# Запустить Claude Code
claude
```

**Решение 2: Использование сторонних инструментов, совместимых с Claude Code**

Некоторые китайские поставщики услуг предоставляют инструменты, совместимые с Claude Code:

```bash
# Установить совместимую версию
npm install -g @some-provider/claude-code

# Конфигурировать API ключ
claude config set api.key your-api-key
claude config set api.baseUrl https://api.some-provider.com
```

**Решение 3: Использование других инструментов AI программирования**

Если Claude Code недоступен, рассмотрите следующие альтернативы:

| Инструмент | Особенности | Сценарий применения |
|-----------|-----------|---------|
| Cursor | На основе VS Code, функции полные | Нужен полный опыт IDE |
| GitHub Copilot | Сильная способность к автодополнению кода | В основном нужно автодополнение |
| Tongyi Lingma | Отечественный, стабильный доступ внутри страны | Окружение разработки в Китае |
| Codeium | Много свободных лимитов | Ограниченный бюджет |

**Решение 4: Попросить AI Agent помочь с конфигурацией**

Если вы не уверены в конфигурации, попросите AI Agent помочь:

```
Я хочу использовать Claude Code, но в Китае нет прямого доступа.
Я купил API у поставщика XXX,
адрес API https://api.xxx.com,
ключ sk-xxx.

Пожалуйста, помоги мне конфигурировать переменные окружения,
чтобы Claude Code работала нормально.
```

**Часто задаваемые вопросы:**

- **В: После конфигурации всё ещё не могу соединиться?**
  - О: Проверьте правильность адреса API, включен ли путь `/v1`
  - О: Проверьте валидность API ключа и наличие средств
  - О: Проверьте, нужен ли локальный прокси

- **В: Скорость ответа очень медленная?**
  - О: Выберите поставщика ближе географически
  - О: Используйте Coding Plan вместо общего API
  - О: Рассмотрите использование `/compact` для снижения потребления Token

- **В: Некоторые функции не работают?**
  - О: Некоторые сторонние сервисы могут быть полностью несовместимы со всеми функциями Claude Code
  - О: Проверьте документацию поставщика, узнайте поддерживаемый диапазон функций
