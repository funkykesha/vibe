## 1. Какое окружение и какие инструменты нужны для написания кода

### 1.1 Изменение мышления: при проблеме сначала спросите AI

Перед тем как вводить различные окружения и инструменты, прежде всего нужно **изменить ваши привычки мышления**.

В традиционном обучении программированию, если вам нужно установить Python, настроить Conda или решить проблему неудачной установки npm, вы обычно откроете поисковик, найдёте учебник, затем шаг за шагом следуете инструкциям. Если посередине произойдёт ошибка, вам может потребоваться поиск сообщения об ошибке и повторные попытки.

Неправильно! ❌

В эпоху AI, особенно при использовании AI IDE, помните **основной принцип: любую операцию можно сначала спросить у AI, или даже дать ему сделать это.**

- **Не знаете, как установить окружение?** Спросите AI в боковой панели: "Я хочу писать Python, проверь установлен ли Python, если нет — помоги мне установить."
- **Сеть зависла?** Если установка пакетов зависает или выдаёт ошибку, скопируйте ошибку и скажите AI: "Загрузка не удалась, это сетевая проблема? Можешь поменять зеркало для скачивания внутри страны?"
- **Команды не запоминаются?** Не нужно зубрить команды Git или Conda, просто скажите AI: "Помоги мне создать новое виртуальное окружение, назови его demo."

### 1.2 Почему нужны окружение и инструменты

От "попробуем написать несколько строк кода" к "создадим долгосрочно поддерживаемый проект" требования к окружению и инструментам совершенно различны.

Теоретически можно писать код даже в системном блокноте, но проблемы появятся быстро:

- **Весь код — чёрный текст**, ключевые слова, строки, комментарии перемешаны, трудно с первого взгляда увидеть структуру
- **Нет умной подсказки**, каждое слово нужно полностью писать самостоятельно, одна опечатка требует многократной проверки
- **Много файлов — беда**, десять-двадцать файлов переключать туда-сюда, часто забываешь, какую строку нужно менять
- **При ошибке только гадаешь**, программа упала — не знаешь что, приходится печатать логи строка за строкой

Поэтому вам нужна IDE (интегрированная среда разработки). Она будет отображать код разными цветами, давать вам автоподсказки при вводе, организовывать файлы по проектам, отслеживать ошибки пошагово, делая разработку эффективнее и с меньшим количеством ошибок.

## 2. Что такое IDE и почему она нужна

> **Совет для подготовки 💡**
>
> Если вы ещё не знакомы, что такое IDE и какие функции имеют элементы интерфейса, рекомендуем сначала прочитать [Введение в IDE](https://github.com/datawhalechina/easy-vibe/blob/main/docs/zh-cn/appendix/2-development-tools/ide-basics/index.md) для подготовки, чтобы понять базовые концепции и основные функции IDE.

В ранний период программирования нам нужны только простой текстовый редактор и обработчик языка. Но с ростом сложности проектов разработчики остро нуждались в инструменте, который мог бы эффективно управлять файлами, поддерживал подсветку синтаксиса и отладку, поэтому появилась интегрированная среда разработки (IDE).

IDE можно понять как программу, специально предназначенную для "редактирования, управления, запуска и отладки" кода. Ранние IDE выглядели очень "примитивно", управление осуществлялось почти полностью клавиатурой.

Известная и функционально зрелая "встроенная IDE" такая как `Vim`, часто используется для удалённого управления серверами.

Для большей эффективности нам нужна современная IDE с поддержкой мыши, которая обычно включает:

- **Редактор исходного кода**: подсветка синтаксиса, автодополнение.
- **Инструменты сборки и запуска**: встроенный компилятор/интерпретатор.
- **Отладчик**: отладка по точкам останова, просмотр переменных.

Современные IDE часто встраивают также инструменты типа Git. Самая популярная — **[Visual Studio Code (VS Code)](https://code.visualstudio.com/)** от Microsoft, она лёгкая и расширяемая. Хотя есть и профессиональные IDE вроде семейства JetBrains, но VS Code — самая удобная для новичков.

Основная идея VS Code — "всё это плагины". Через механизм плагинов она поддерживает различные языки: установи плагин Python — получишь Python IDE, установи C++ — получишь C++ IDE. Без плагинов — это просто продвинутый текстовый редактор.

Можно даже использовать для редактирования Markdown-документов.

В общем, IDE — это набор инструментов, помогающих разработчикам эффективно писать код и запускать программы.

Более детальное объяснение, смотрите в [приложении — визуальная IDE и принципы визуализации](https://github.com/datawhalechina/easy-vibe/blob/main/docs/zh-cn/appendix/2-development-tools/ide-basics/index.md).

## 3. В чём различие между AI IDE и обычной IDE

Обычная IDE (например, оригинальный VS Code) по сути это "набор инструментов":
можно открыть проект, писать код, запустить и отладить, установить плагины, но при условии, что вы сами знаете что делать и как:

- При ошибке сами читаете подсказку, сами ищете какая строка проблемная;
- Хотите добавить новую страницу или интерфейс — сами ищите файл, сами пишете код;
- Хотите настроить окружение или упаковать — сами ищите документацию, следуете по шагам.

Но в AI IDE вы можете напрямую использовать большую языковую модель для помощи в кодировании и изменении файлов:

- Скажите "сделай страницу входа" — оно сгенерирует базовую структуру кода;
- Скопируйте сообщение об ошибке и соответствующий код — оно сначала проанализирует причину и даст совет по изменению;
- После вашего подтверждения — автоматически создаст файлы, массово изменит код, справится с трудоёмкой работой по нескольким файлам.

Например, вы можете выделить участок кода и попросить "переделай" или "добавь комментарии"; или в боковой панели спросить "как организован этот проект?", используя `@название_файла` или `@весь_проект`, одной фразой автоматически создать файл, написать код и запустить проект.

В последней версии VS Code уже встроен помощник большой языковой модели. Вы можете напрямую общаться с моделью про весь репозиторий кода, конкретный файл или даже функцию. Можно также, как раньше на веб-сайте использовали автоматическое создание кода, отправить требования в виде подсказки встроенному Agent кодирования, давая ему автоматически реализовать нужные функции, создавать файлы, менять код, настраивать окружение и т.д.

Вы можете загрузить и установить VS Code, нажав на вход боковой панели в верхнем правом углу, открыть зону функций AI, опробовать эти способности.

Однако VS Code — это не AI IDE с самыми сильными способностями. Для сценариев, требующих большого объёма вспомогательного AI-кодирования, мы обычно хотим использовать "более умный, более эффективный" инструмент — хорошая AI IDE может значительно сэкономить время на написание кода и исправление ошибок. Ниже мы представим несколько популярных в настоящее время AI IDE, вы можете выбрать и использовать любую AI IDE в зависимости от личных предпочтений.

Поскольку VS Code открыта (каждый может загрузить исходный код и самостоятельно скомпилировать), в настоящее время абсолютное большинство AI IDE на рынке разработаны на основе VS Code в ходе вторичной разработки. Поэтому вам не нужно беспокоиться о "изучении множества IDE" — **если вы знакомы с основным использованием VS Code**, миграция на эти AI IDE не требует переучивания.

В целом различия между разными AI IDE сосредоточены на четырёх аспектах: цена; типы доступных моделей (некоторые продвинутые модели могут быть ограничены в некоторых регионах); способности Agent (уровень интеллекта и способность исполнения при помощи в кодировании); и скорость работы, производительность. Вы можете выбирать в зависимости от результатов фактического тестирования, что подходит вам — то и лучше.

> **Типичные способности AI IDE:**
>
> - Умное создание и дополнение кода: в традиционной IDE мы обычно вводим несколько символов для дополнения имени переменной или функции; в современной AI IDE вы можете написать несколько строк псевдокода или просто сказать требование, IDE автоматически дополнит полную логику, даже генерирует большой фрагмент или весь блок кода по инструкции.
> - Понимание кода и ответы на вопросы: IDE может понять и ответить на вопросы о конкретном коде, файле, или даже всей структуре папки проекта.
> - Рефакторинг и оптимизация кода: IDE может переписать или оптимизировать логику реализации выбранного фрагмента кода в соответствии с вашим намерением.
> - Автоматическое создание тестов: IDE может автоматически генерировать код тестов для различных функций и модулей, облегчая целевое тестирование.
> - Выполнение задач в стиле Agent: умный Agent может автоматически генерировать, упаковывать, устанавливать, запускать и менять код, в работе многих задач может частично заменить начинающего инженера-программиста.

### Antigravity

**[Antigravity](https://antigravity.google/)**

Antigravity — это совершенно новая AI IDE, выпущенная Google в ноябре 2025 года вместе с Gemini 3, использующая режим разработки "Agent-First" (приоритет intelligent agent). В отличие от традиционного AI-вспомогательного кодирования, Antigravity делает AI-агента "активным исполнителем", который может напрямую управлять редактором, терминалом, браузером и другими инструментами, принимая на себя больше работы "выполнения", "планирования", "проверки". Разработчик должен только поставить высокоуровневую цель, агент автоматически разделит задачу, составит план, выполнит код, запустит тесты, генерирует результаты. Она поддерживает переключение между множеством моделей, включая Gemini 3 Pro, Claude Sonnet 4.5 и др., в настоящее время предоставляется в виде общественной предварительной версии, поддерживает Windows, macOS, Linux, полная кроссплатформенность.

### Trae

**[Trae](https://www.trae.ai/)**

Trae — это AI-ассистент для программирования, выпущенный компанией ByteDance, поддерживающий более 100 языков программирования и интегрирующийся в основные IDE. Его функции включают: генерирование кода из естественного языка, автоматическую отладку, преобразование макетов дизайна в компоненты React/Vue и т.д. После обновления в августе 2025 года Trae добавил умные предложения по импорту зависимостей, переименованию, управлению списком задач; режим SOLO также начал поддерживать генерирование кода back-end и редактирование документации технической архитектуры.

### Cursor

**[Cursor](https://cursor.com/)**

Cursor — это AI-редактор кода, разработанный Anysphere, основанный на VS Code с кастомизацией, с акцентом на оптимизацию сценариев с большими базами кода и многофайловой совместной работой. Она поддерживает модели GPT-4o, Claude 3.7 и т.д.; режим Claude Max, выпущенный в 2025 году, может работать с проектами уровня миллионов строк кода. Профессиональная версия отменила ограничение количества запросов, очень подходит для сложных корпоративных проектов.

На данный момент Cursor можно сказать, что имеет одну из лучших интегрированных опытов среди "AI IDE с интерфейсом", с большой пользовательской базой и высокой частотой обновления функций. Его самый большой недостаток — высокая цена — профессиональная версия примерно 20 долларов в месяц.

### Qoder

**[Qoder](https://qoder.com/)**

Qoder — это AI IDE, выпущенный компанией Alibaba, подчеркивающий "прозрачное сотрудничество" и "усилие способностей контекстной инженерии". Она через Action Flow поддерживает разделение задачи на несколько шагов и отслеживание процесса выполнения AI в реальном времени; также поддерживает динамическую маршрутизацию множественных моделей и управление машиной состояния задач, очень подходит для архитектурного управления в средних и больших проектах и "обратной инженерии" анализе для устаревших систем.

### CodeBuddy

**[CodeBuddy](https://www.codebuddy.com/)**

CodeBuddy — это AI-инструмент программирования, выпущенный Tencent Cloud, подчеркивающий поддержку китайских команд и способность корпоративного соответствия. Она предоставляет дополнение кода, массовую проверку кода, переключение множественных моделей и других функций; интеллектуальный агент Craft может реализовать генерирование многофайлового кода и интеграцию API. Корпоративная версия поддерживает приватизированное развёртывание и получила сертификацию трёхуровневой защиты информации, подходит для финансов, здравоохранения и других отраслей с высокими требованиями к безопасности данных.

### VS Code + Cline

**VS Code + [Cline](https://cline.bot/)**

Cline — это плагин Agent для AI-программирования VS Code (Visual Studio Code), который может гибко переключаться между используемыми большими моделями через настройку различных API endpoints. Cline поддерживает многомодальный ввод, расширение инструментов MCP и мониторинг затрат, все операции должны быть подтверждены пользователем перед выполнением. Это очень подходит для быстрой проверки идей или интеграции с существующим рабочим процессом разработки. Базовые функции бесплатны, корпоративная версия поддерживает развёртывание модели в приватной среде.

### Kiro

**[Kiro](https://kiro.dev/)**

Kiro — это AI IDE программирования, выпущенный AWS (Amazon Web Services), глубоко интегрирующийся с Amazon Bedrock и экосистемой облачных сервисов AWS. Она поддерживает множество больших моделей, таких как Claude, Nova и т.д., особенно подходит для сценариев разработки, требующих тесной интеграции с облачными сервисами AWS. Kiro предоставляет умное создание кода, автоматизацию тестирования, а также бесшовное подключение к ресурсам AWS (таким как Lambda, S3, DynamoDB), имеет уникальные преимущества для облачной разработки приложений.

> **Примечание**: Если вы хотите использовать модели Anthropic Claude, вам нужно использовать Cursor, Kiro или Antigravity в качестве IDE. Эти IDE имеют официальное сотрудничество с Anthropic или глубокую интеграцию, обеспечивающую более стабильный и полный опыт работы с моделью Claude.

## 4. Практическое применение: генерирование игры змейка с AI IDE локально

Предыдущие части в основном касались "концепции" и "различий". Этот раздел через полную практику воплотит абстрактные концепции в конкретные операции: **создайте пустую папку → откройте её в AI IDE → в боковой панели чате попросите создать игру змейка на React с нуля.** Здесь в качестве примера используем Trae из приведённых выше, сначала нужно установить и простенько разобраться что такое Trae.

> **Мини-совет: Бесшовный переход от веб-версии к локальной 💡**
>
> Если вы раньше уже разрабатывали проекты на z.ai или других веб-платформах AI-программирования, вы можете напрямую загрузить код локально, затем открыть в AI IDE для продолжения разработки. Таким образом вы сохраните предыдущие результаты и получите мощнейшие способности локального AI IDE.
>
> Операция очень простая:
> 1. На z.ai и др. платформах нажимаем кнопку загрузки, сохраняем проект локально
> 2. После распаковки открываем папку в Trae/Cursor и других AI IDE

### 4.1 Подготовка: установка и изучение Trae

#### 4.1.1 Что такое Trae

Полное название Trae можно понять как "The Real AI Engineer" — это адаптивная интегрированная среда разработки AI (IDE), разработанная компанией ByteDance. Она построена на основе популярного VS Code, это значит, что если вы уже привыкли к VS Code, при использовании Trae, как в расположении интерфейса, так и в базовых операциях, вы будете чувствовать себя очень знакомо и комфортно.

Основная цель Trae — стать "умным партнёром программиста" разработчика. Благодаря глубокой интеграции способностей AI, она может автоматически справляться с большим количеством повторяющейся работы, предоставляя более интуитивный и эффективный опыт разработки. Это не просто "инструмент дополнения кода", а хочет охватить весь рабочий процесс разработки — от создания проекта, написания кода, отладки, тестирования до развёртывания — предоставить помощь.

#### 4.1.2 Установка Trae

Trae делится на международную версию и китайскую версию. Международной версии нужен доступ к зарубежной сети, но можно использовать новейшие зарубежные модели типа GPT-5; китайская версия в основном поддерживает новейшие отечественные большие модели, такие как GLM, Qwen, Kimi и т.д.

Адрес загрузки международной версии: https://www.trae.ai/
Адрес загрузки китайской версии: https://www.trae.cn/

##### Ценообразование Trae и способы использования

> **Совет выбора версии (для новичков рекомендуется CN версия) 💡**
> - **Для абсолютных новичков настоятельно рекомендуется загрузить китайскую версию (CN версия, trae.cn)**, в настоящее время опыт использования лучше, базовые функции бесплатны, не нужна зарубежная сеть
> - Если вам нужны зарубежные модели типа GPT-5 и сетевые условия позволяют, можете выбрать международную версию
> - Если уже есть API Key сторонней модели, подключение сторонней модели может гибко контролировать стоимость

> **В настоящее время рекомендуется использовать бесплатные модели OpenRouter для тестирования 💡**
>
> На момент написания учебника (2026-02-12) в настоящее время всё ещё возможна бесплатная пробная версия модели StepFun. Конкретно можно обратиться к разделу 4.2 ниже для способа подключения модели, подключите `stepfun/step-3.5-flash:free`.

Относительно сборов и способов использования Trae у вас есть несколько вариантов:

- **Китайская версия CN (настоятельно рекомендуется)**: базовое использование бесплатно, в целом эффект использования лучше, чем международная версия, очень подходит для абсолютных новичков. Из-за большого количества пользователей иногда может потребоваться очередь ожидания.
- **Международная версия**: стоимость подписки примерно 3 доллара в месяц, можно использовать зарубежные модели типа GPT-5, но нужен доступ к зарубежной сети.
- **Подключение сторонней модели**: если у вас уже есть API Token отечественной большой модели (типа DeepSeek, Tongyi Qianwen, Kimi и т.д.), вы можете использовать функцию настройки модели стороннего Trae для подключения этих API. Основные облачные поставщики услуг (типа Alibaba Cloud, Tencent Cloud, Baidu Cloud и т.д.) обычно предоставляют планы подписки Coding Plan, после покупки можно использовать большую модель API поставщика по более выгодной цене. Таким образом вы можете свободно выбирать любимую модель, одновременно контролируя стоимость использования.

Рекомендуется начинающим начать с бесплатной версии отечественного CN (адрес загрузки: https://www.trae.cn/), в настоящее время опыт использования CN версии лучше и полностью бесплатен. Если столкнётесь с проблемой очередей или нужна более стабильная служба, можете рассмотреть подключение сторонней модели и покупку плана Coding Plan соответствующего облачного поставщика.

#### 4.1.3 Краткое описание интерфейса Trae

По внешнему виду Trae очень похож на используемый нами в повседневной жизни VS Code: то же расположение левого обозревателя ресурсов, средней зоны редактирования, правой панели расширений — классический трёхколонный макет.

Правая боковая панель — это окно взаимодействия Copilot, или можно понять как окно Agent. Если вы временно его не видите, нажмите значок боковой панели в верхнем правом углу Trae, чтобы его открыть.

После открытия боковой панели вы увидите опцию `Builder` — это режим Agent. Просто говоря, это "локальная версия" z.ai, которая может помочь вам управлять локальным окружением, устанавливать рабочее окружение, открывать веб-сайты и т.д.

После нажатия на "Builder" вы увидите режим "Chat" и режим "Builder with MCP":

- **Режим Chat**: в основном используется для диалога с кодом в текущей папке или использования как обычный chat-модель. (Вы можете через меню "File" в верхнем левом углу открыть папку, в этой папке производить операции редактирования. В этом случае файлы, созданные или изменённые Builder, будут происходить только внутри этой папки.)
- **Режим Builder with MCP**: предоставляет Agent больше доступных инструментов (например, подключение большой языковой модели с другим ПО, запросы погоды и т.д.). Вы можете просто понять: MCP делает удобнее для языковой модели вызывать различные внешние инструменты.

В области ниже вы также увидите опцию выбора модели, нажав на которую вы можете изменить текущую используемую большую модель. В китайской версии вы можете выбрать использование отечественных моделей типа Kimi k2 или GLM; если вы используете международную версию Trae, вы также можете выбрать ChatGPT или Claude и т.д. Однако, поскольку развитие отечественных больших моделей очень быстро, Kimi, Qwen, GLM и т.д. в реальности выполняют много задач уже близко к Claude 3.5 или 3.7, для повседневной разработки уже полностью достаточно, здесь не требуется использование международной версии или отечественной версии для операций.

**Нужно обратить внимание, что здесь не рекомендуется использовать режим Auto (автоматический выбор модели). Если это международная версия, мы рекомендуем использовать модели Gemini или GPT, если это отечественная версия, мы рекомендуем вам попробовать Kimi k2 или Minimax, GLM и другие отечественные модели**. Разные модели имеют разные случаи использования, нет догматического различия хорошо или плохо, вы можете при трудностях в разных задачах переключить модель, через множество тестов получить принадлежащий вам лучший экспериментальный результат.

Выше приведено простое введение в Trae. Далее мы можем вспомнить операции, которые мы делали раньше на z.ai, и попробовать делать в Trae то же самое.

### 4.4 Третий шаг (опционально): дальше расспрашивайте AI о деталях реализации кода

Когда игра змейка уже может нормально работать, если вы ещё не знакомы с фронтенд или React, вы можете в том же окне чата продолжить просить AI объяснить вам код максимально разговорным языком. Вам не нужно переключать инструмент, не нужно специально искать в документации, только продолжайте задавать вопросы вокруг текущего проекта.

Довольно практичный способ — просить AI сначала объяснить "как работает игра в целом", потом разобраться в деталях. Например, вы можете напрямую спросить:

> "Пожалуйста, объясните сверху вниз, как каждый шаг этой игры змейка движется? По возможности используйте меньше профессиональных терминов."

Затем продолжайте следовать её ответу и задавайте вопросы на ключевые точки, например:

> "Каждая часть тела змейки на экране, какой структурой данных записывается? Можешь привести пример?"
> "Как ты контролируешь 'движение через некоторое время'? Это в какой части кода?"
> "Когда змейка ест еду, ты сделал какие несколько шагов? В каком логическом блоке судишь что съела?"
> "Столкновение со стеной и столкновение с собой, в каких кодах соответственно судят?"

Если вы видите какой-то файл (например `SnakeGame.tsx`) но совсем не знаете что он делает, также можете напрямую просить AI разделить и объяснить:

> "Пожалуйста, объясните `SnakeGame.tsx` по функциональности несколько блоков: каждый блок примерно отвечает за что, используйте более разговорную речь."

В этом раунде диалога вы можете любое непонятное слово использовать как вход для дальнейшего вопроса, например:

> "Что конкретно означает 'состояние' которое ты только что сказал? Можешь объяснить примером из жизни?"
> "Что главное делает 'таймер' о котором ты говоришь здесь? Если его убрать что произойдёт?"

Через этот способ, ваша цель не запомнить все концепции сразу, а разобраться три вещи: какие ключевые данные есть в этой игре (змейка, еда, очки, состояние игры и т.д.), когда эти данные изменяются (движение, съедение еды, конец игры и т.д.), и какая строчка кода соответствует каждому типу изменения. Если эти три пункта ясны, вы в основном можете понять главную логику этого кода.

### 4.5 Четвёртый шаг: просите AI сделать интерфейс красивее

Здесь сначала напомню одну очень важную вещь для новичков: не говорите AI только одной фразой "я хочу сделать интерфейс красивее". Это объяснение для дизайнера-человека уже слишком смутно, не то что для модели — "красивый" это какой стиль, какие места нужно менять, это проблема раскладки или цвета, AI не может это прочитать из вашей одной фразы. Чтобы AI действительно выдал результат близко к вашему ожиданию, вам нужно научиться разбивать "я хочу красивый" туманную цель на серию конкретных, выполняемых маленьких требований.

Например, многие люди вначале так скажут:

> "Я хочу сделать интерфейс красивее."

Например, вы сначала можете дать общий набор требований:

> "Пожалуйста, помоги мне улучшить интерфейс игры в целом:
>
> - Область игры должна отображаться в центре, не прилипать в левый верхний угол;
> - Переделай на более светлый фон, чтобы змейка и еда были более заметны;
> - Увеличь размер очков, положи на видное место;
> - В качестве основного цвета используй синий, улучши общую цветовую схему и кнопки."

Если вы надеетесь на более чёткую обратную связь когда "игра кончается", вы можете дальше дополнить:

> "Когда игра кончается, пожалуйста показывай 'Игра окончена' в центре экрана, под этим кнопка 'Начать заново', которой можно перезагрузить игру."

AI в соответствии с вашим описанием напрямую изменит React-компоненты и стили. После сохранения обновите браузер, вы сможете увидеть новый интерфейс. Если результат не совпадает с вашим воображением, можете продолжить делать маленькие корректировки, например:

> "Очки ещё больше, цвет ещё более выделяющийся."
> "Область игры ещё более плотная, вокруг оставь немного пустого места."
> "Кнопка перезапуска переделай на синий скруглённый стиль, положи в центр под подсказку."

На этом этапе, если какое-то изменение вызвало ошибку, также не нужно самим искать. Напрямую скопируйте сообщение об ошибке в окно чата, или вместе с кратким описанием, например "это ошибка которая появилась после улучшения интерфейса", пусть AI в контексте текущего проекта поможет найти и исправить. Таким образом вы в цикле "постоянного диалога, постоянного обновления" можете постепенно отполировать работающее Demo в интерфейс с чётким видом и гладким взаимодействием маленького готового продукта.

## 5. Каждая кнопка на интерфейсе — для чего

В операциях выше мы уже быстро прошли полный цикл генерирования минимальной программы, но всё ещё не можем сказать что хорошо знаем IDE. Для полного изучения этого инструмента с которым мы будем долго работать, в этом разделе мы углубимся в каждый детальный аспект IDE, сначала с интерфейса. Разные AI IDE имеют небольшие отличия в интерфейсе, но большинство продолжают [расположение VS Code](https://code.visualstudio.com/docs/getstarted/getting-started).

Конкретные функции каждой части:

- **Title Bar (Строка заголовка)**: отображает имя файла и кнопки управления окном.
- **Activity Bar (Панель активности)**: переключение между функциями представления файлов, поиска и т.д.
- **Side Bar (Боковая панель)**: отображение конкретного содержания, например список файлов.
- **Editor Groups (Группы редактирования)**: основная область для написания кода.
- **Breadcrumbs (Полоса навигации пути)**: отображение пути файла, поддержка прыганий.
- **Minimap (Миникарта кода)**: быстрый просмотр и позиционирование кода.
- **Panel (Нижняя панель)**: содержит терминал и окно вывода.
- **Status Bar (Строка состояния)**: отображение текущего состояния окружения.

Более детальное объяснение, пожалуйста, обратитесь к [приложению — визуальная IDE и принципы визуализации](https://github.com/datawhalechina/easy-vibe/blob/main/docs/zh-cn/appendix/2-development-tools/ide-basics/index.md).

## 6. Как разговаривать с AI, чтобы было эффективно

По мере того как способности AI растут, мы уже можем много "работы по написанию кода" передать AI.
Но в реальном использовании вы обнаружите: одно и то же AI, одной и той же инструменты, одни люди несколькими фразами получают запускаемый маленький проект, другие болтают полдня, результат совсем не тот что хотели. Различие часто не в том "кто умнее", а в том — **как вы разговариваете с AI**, достаточно ли конкретно, достаточно ли пошагово.**
Этот раздел начинает с несколько типичных сценариев, представляет подходящие для полных новичков способы задавания вопросов, помогая вам более стабильно получать используемые результаты от AI.

### 6.1 Ясно описывайте требования: от "смутной идеи" к "конкретному объяснению"

Многие люди когда впервые пользуются AI, привыкли говорить только очень общую фразу, например:

> "Помоги мне сделать веб-сайт."
> "Помоги мне написать маленькую программу."

В этом случае AI может только "угадывать" что вы хотите, поэтому будет случайно вам что-то выдавать, которое выглядит полным, но обычно очень отличается от того что вы действительно хотите делать.
Чтобы AI лучше вас понял, нужно разобрать "идею в голове" и пошагово объяснить несколькими фразами.

Можно дополнить с этих нескольких аспектов:

1. **Скажите, для чего это нужно**
   Например, не говорите "личный сайт", а скажите:
   - "Я хочу сделать личный сайт из одной страницы для представления себя, чтобы показать кадрам при поиске работы."

2. **Скажите, какие блоки контента нужны примерно**
   Не нужны профессиональные слова, только описать что надо на странице, например:
   - "На странице три части: вверху имя и одна фраза самопредставления, в середине несколько пунктов опыта работы, внизу email и номер WeChat."

3. **Скажите, ваш уровень и ограничения**
   Дайте AI сделать способом, который новичок может принять, например:
   - "Я совсем не умею писать код, пожалуйста используй самый простой способ, чтобы я смог напрямую скопировать в файл и открыть в браузере."

4. **Скажите, как хотите получить результат**
   Например:
   - "Пожалуйста дайте мне полный код который можно напрямую сохранить как `index.html` и открыть в браузере."

Вместе можете сказать AI таким образом:

> "Я совсем не умею писать код, хочу сделать личный сайт из одной страницы для представления себя, чтобы показать кадрам при поиске работы.
> На странице нужны три части: вверху одна строчка — имя и одна фраза самопредставления, в середине несколько пунктов опыта работы, внизу email и номер WeChat."

Когда вы четко расскажите эту информацию, AI сможет лучше понять ваши истинные требования, вместо того чтобы случайно дать вам "выглядящее впечатляющим но неиспользуемое".

### 6.2 Используйте правильный темп: сначала "чтобы запустилось", потом постепенно сложнее

Для полных новичков самая типичная ошибка: сразу хотят делать "очень полное", "много функций".
Например:

> "Помоги мне сделать сайт как Taobao."
> "Помоги мне сделать систему которая может регистрироваться, входить, заказывать."

Результат обычно: AI выдаст кучу кода, вы скопируете — либо не откроется, либо везде ошибки; вы не поймёте где проблема, в конце можете только сдаться.

Подходящий способ — **сами контролируйте темп**, дайте AI следовать вам пошагово, не выплёскивайте всё сразу. Можете следовать этому порядку предъявления требований:

1. **Первый шаг: сначала просите "самый минимальный пример"**
   Только проверьте одно: можно ли видеть что-то в браузере.
   Например:

   > "Пожалуйста сначала дайте мне самый простой пример, только нужно чтобы в браузере была видна строчка 'это моя главная страница' — готово.
   > Потом пошагово скажите мне: как должен называться файл, как его сохранить, как открыть."

2. **Второй шаг: на этой основе постепенно добавляйте контент**
   Когда подтвердили что "действительно видна та строчка", потом скажите:

   > "На основе раньше, помоги мне добавить область 'опыт работы', дай мне полный код заново. Не только часть изменений."

3. **Третий шаг: когда структура готова, потом думайте о внешнем виде**
   Например:
   > "Теперь страница может нормально показывать контент. Потом помоги мне немного улучшить внешнее: всё в центре, заголовок побольше, используй удобный шрифт. Дайте обновлённый полный код."

На каждом этапе вы сначала проверьте один раз, подтвердите что действительно есть изменения, потом дайте AI продолжить. Таким образом если какой-то шаг вышел неправ, вы быстро можете вернуться на "предыдущая версия всё работала", не требуется полностью переделывать.

### 6.3 Хорошо используйте скриншоты и копирование: не знаете как сказать — "бросьте изображение AI"

Много полных новичков встречают трудность, не в том "не умею менять код", а в том что **не знаешь как объяснить проблему**.
Например:

- В браузере внезапно вылезла куча английского текста ошибок, вы совсем не понимаете.
- Раскладка веб-страницы не такая как вы представили, но вы не знаете как это описать словами.

В этих случаях не требуется выискивать профессиональные термины, самый простой способ — **бросьте AI то что вы видите, как есть**.

Можно сделать так:

1. **Скопируйте текст ошибки**
   Когда видите строчку красной ошибки, можете напрямую скопировать, потом скажите:

   > "Это полная информация об ошибке которая появилась после запуска. Я не понимаю этот английский, пожалуйста сначала объясни обычным языком, это примерно какая проблема.
   > Потом скажи, сейчас я что самое простое должен менять."

2. **Покажите AI скриншот**
   Если вы чувствуете что "эта страница явно не то", но не можете описать, можете:
   - Сделать скриншот текущей страницы;
   - Скопировать весь код которого вы используете, отправить одним куском AI;
   - Потом объяснить:
     > "Это как выглядит сейчас страница, это весь мой текущий код.
     > Я ожидал что будет трёхколонная раскладка, сейчас получилось одна колона. Пожалуйста посмотри причину, и дай мне исправленный полный код."

   > **Дополнительное объяснение про функцию скриншота 💡**
   >
   > Нужно обратить внимание, что **не все модели AI поддерживают 'видение изображений'**. Это касается двух различных концепций:
   >
   > - **Чистая текстовая большая языковая модель (LLM)**: может обрабатывать только текст, не может распознавать содержание изображения. Если вы ей отправите скриншот, она либо откажется обработать, либо не сможет правильно понять информацию на изображении.
   >
   > - **Мультимодальная модель**: может одновременно обрабатывать текст, изображение и другие типы входа, может "видеть и понимать" отправленные вами скриншоты, и дать советы на основе содержания изображения.
   >
   > **Справочник способностей модели** (на примере моделей которые можно выбрать в Trae):
   >
   > | Модель | Поддерживает входное изображение |
   > |------|-----------------|
   > | Doubao-Seed серия | ✅ Поддерживает |
   > | GLM-4.7 / 4.6 | ❌ Не поддерживает |
   > | MiniMax-M2.7 / M2.5 | ❌ Не поддерживает |
   > | DeepSeek-V3.1 | ❌ Не поддерживает |
   > | Kimi-K2.5 | ✅ Поддерживает |
   > | Kimi-K2-0905 | ❌ Не поддерживает |
   > | Qwen-3-Coder | ❌ Не поддерживает |
   > | Gemini серия | ✅ Поддерживает |
   > | GPT серия | ✅ Поддерживает |
   >
   > **Рекомендация по использованию**: Если хотите через скриншот дать AI помощь в проверке проблем интерфейса, пожалуйста сначала убедитесь что ваша модель поддерживает входное изображение. Если не поддерживает, вы можете использовать текстовое описание проблемы, или скопировать сообщение об ошибке и отправить AI.

3. **Встречали понравившийся сайт, хотите сделать похожий**
   Не нужно говорить "эта раскладка как называется", напрямую:
   - Сделайте скриншот или скопируйте основные заголовки, параграфы той страницы;
   - Потом скажите:
     > "Я хочу сделать страницу с похожей структурой как это, не нужно совсем одинаковой.
     > Пожалуйста помоги мне используя более простой код, соберите похожий каркас, потом я сам свою текст поменяю."

Просто говоря: вы отвечаете за "перемещение видимого в AI", потом самым простым языком скажите "я хочу чтобы оно стало как это"; остальное "переводить в код, объяснять названия, находить проблемы" — оставьте AI.

### 6.4 Когда AI-генерированный код не работает: универсальный способ обращения

В реальной практике вы точно встречаете такое: AI очень ответственно дал вам код, вы послушно скопировали, но результат либо браузер белый экран, либо совсем не тот эффект что оно говорило.
Это не значит что вы "не можете учиться", не значит что AI совсем ошибся, а значит что между вами ещё не хватает несколько раундов "взаимного подтверждения".

Когда код "не работает", можете следовать этой фиксированной процедуре как разговаривать с AI:

1. **Сначала четко описайте "что вы сделали + как сейчас"**
   Избегайте только говорить "не открывается", "не то". Можете описать так:

   > "После открытия страница совсем белая, не показана та приветственная строчка что ты говорил.
   > Я открыл xxxx страницу, там не видна часть что я говорил раньше, это не может быть"

2. **Дайте AI ваш текущий полный код**
   Много раз проблема в том: скопировали неполный кусок, или содержание от раньше и сейчас смешалось.
   Вы можете сказать:

   > "Вот весь код который сейчас в этом файле.
   > Пожалуйста проверь в сравнении с твоим есть ли что-то неполное, написано неправильно, или порядок неправильный.
   > Пожалуйста дай мне полный исправленный код напрямую, не только маленький кусок."

3. **Если есть сообщение об ошибке, дайте вместе**
   Например ошибка в верхнем правом углу браузера, или внизу какой-то красный текст. Вы можете:
   - Скопировать текст ошибки;
   - Или сделать скриншот;
   - Потом скажите:
     > "Это сообщение об ошибке которое я видел. Я совсем не понимаю, пожалуйста сначала простым способом объясни это примерно какая проблема, потом скажи сейчас главное нужно менять какие несколько строк."

4. **Просите метод "для полного новичка" пошагово**
   Можете напрямую сказать вашу ситуацию, дайте оно не пропускать промежуточные шаги:

   > "Я совсем не умею писать код, пожалуйста пошагово скажи мне:
   > Шаг 1 нужно менять какую строку,
   > Шаг 2 как сохранить,
   > Шаг 3 как переоткрыть или обновить страницу.
   > Каждый шаг пожалуйста напиши полной фразой."

5. **В конце, просите оно помощь "что должно быть видно"**
   Например:
   > "Пожалуйста сначала скажи, по твоему исправленному коду, нормально ли я открою сайт и что должен видеть."

Если вы будете следовать этой процедуре при взаимодействии с AI, большинство ситуаций "код не работает" можно решить в несколько раундов диалога.
Одновременно, вы будете постепенно знакомиться с типичными типами проблем, следующий раз встречаете похожее, можете напрямую решить.

## 7. Краткое резюме и следующие шаги

В этой главе вы завершили升级 от "может играть AI-генерированную змейку в браузере" к "может локально сам выстроить маленькую игру на AI IDE". Вы примерно разобрались три вещи: почему написание кода неразлучно с IDE вроде VS Code; на этой основе, добавьте AI (Trae, Cursor и т.д.), IDE больше не просто "набор инструментов", а добавилось "может слышать естественный язык, помочь создать файлы, установить окружение, менять код" "практикант-инженер"; и каждый блок на интерфейсе IDE (левый файл, нижний терминал, средний редактирование, правый AI-панель) соответственно за что, используя становится не в замешательстве.

Ещё важнее, вы уже реально прошли полный процесс: создать пустую папку локально → открыть в AI IDE → в боковой панели диалога описать требования → дайте AI генерировать проект и запустить сервер разработки → когда появилась проблема, бросьте "явление + весь код + скриншот ошибки" вместе AI, просите использовать "режим новичка" пошагово. В этом процессе вы также практиковались как писать более эффективные подсказки: четко описать цель, структуру контента и ваш уровень, контролировать темп, от "сначала может запуститься" к "потом красивее, потом веселее". 

Следующая глава, мы сместим фокус от "умеешь пользоваться инструмент" к "делаешь действительно прототип который люди будут использовать": от пользовательской перспективы, дизайн правила, взаимодействия и обратную связь, потом дайте AI помощь эти идеи воплотить в прототип продукта.

Вы уже используя локальный AI IDE сделали змейку. Сейчас пожалуйста еще бросьте вызов более сложной маленькой игре, полностью пройдите процесс "описание требований → генерирование проекта → локальный запуск → отладка итерирование".

   - Может быть "Tetris", "whack a mole", "Minesweeper", "2048", "Shootem" и т.д.

2. **Обязательно используйте локальный AI IDE для завершения полного процесса**
   - Создайте пустую папку, откройте на AI IDE
   - В боковой панели чата четко описывайте требования вашей игры
   - Дайте AI отвечать за создание файлов, строить структуру проекта и реализовать главную логику
   - Локально запустите сервер разработки, убедитесь игра может нормально работать

3. **Должна иметь базовую "играемость" и обратную связь**

   - На экране есть четкая обратная связь очков или прогресса

4. **Обязательно делайте 2 и больше раундов итерирования**
   - Первый раунд дайте AI выстроить "может играть" версию
   - Второй раунд и далее постепенно предложите конкретное улучшение (стиль, сложность, оптимизация взаимодействия и т.д.)

## Раздел 1: Слова связанные с "интерфейсом инструмента"

### 1. IDE, редактор, терминал

**IDE (интегрированная среда разработки)**
Можно представить IDE как "рабочий стол программиста":

- Одна сторона — письменный стол (редактор),
- Другая сторона есть розетка и кнопки (запуск, отладка),
- В ящиках разные маленькие инструменты (поиск, управление версиями).
  VS Code, Trae, Cursor — всё это IDE или инструменты изменённые на основе IDE.

**Редактор кода (Editor)**
Больше похож на "продвинутый блокнот", только отвечает за:

- Дать вам печатать код;
- Используя цвет разделить разное содержание (подсветка синтаксиса);
- Дать вам автодополнение.
  Та часть в IDE где пишешь код — это редактор кода.

**Терминал / Командная строка (Terminal)**
Окно с чёрным фоном и белым текстом, где вы **вводите команду** чтобы компьютер работал:

- Например: `npm run dev` значит "помоги мне запустить сервер разработки";
- `python main.py` значит "запусти этот Python файл".
  Можно представить: "вы отправляете компьютеру短 сообщение-команду, он отвечает текстом результат выполнения".

### 2. Несколько типичных областей в IDE

**Панель активности (Activity Bar)**
Самая левая вертикальная линия маленьких значков, как "функциональные вкладки":

- Клик на значок файла → слева показывается список файлов;
- Клик на значок лупы → слева становится поиск;
- Клик на значок Git → слева показывается управление версиями.

**Боковая панель (Side Bar)**
Большая область справа от панели активности, специально отображает текущий режим содержание:

- Режим файлов: показывает файлы и папки в проекте;
- Режим поиска: показывает результат поиска в списке;
- Режим управления исходным кодом: показывает какие файлы изменены.

**Область редактирования (Editor)**
Самая большая область в центре — это где после открытия файла вы действительно видите и меняете содержание;
Вверху табы (вкладки) показывают "сейчас открыто какие файлы".

**Нижняя панель (Panel)**
Обычно внизу, типичных несколько:

- Terminal (терминал): вводить команды запускать проект;
- Problems (проблемы): список файлов с ошибками и номера строк;
- Output (вывод): информация выполнения которую выдали инструменты;
- Debug Console (консоль отладки): вывод при отладке.

**Строка состояния (Status Bar)**
Самая низкая тонкая линия:

- Показывает текущий файл какой язык (JS, HTML, Python и т.д.);
- Показывает отступ "2 пробела" или "4 пробела";
- Показывает есть ошибки ли, текущая Git ветвь какая.
  Можно считать "маленькая проверка текущего окружения редактирования".

## Раздел 2: Слова связанные с "веб-сайтом / сетью / сервисом"

### 1. URL, http, порт, локально

**URL (веб-адрес)**
То что видно в адресной строке браузера, например:

- `https://www.trae.cn/`
- `http://localhost:3000/`
  Это как "полный адрес конкретной комнаты в интернет-мире".

**HTTP / HTTPS**
`http://` или `https://` который видно в начале URL:

- HTTP: обычный способ передачи;
- HTTPS: плюс один слой шифрования, более безопасно.
  Вы можете сначала запомнить: "адрес веб-сайта обычно начинается с `http` или `https`".

**Порт (Port)**
Можно представить компьютер как большое здание, порт это **номер двери каждой комнаты**:

- `:3000` значит 3000-я комната;
- На одном компьютере можно одновременно открыть много сервисов, каждый занимает один порт.
  `http://localhost:3000` это "посещаю мою собственный компьютер 3000-й комнаты где работает сервис".

**Локально (Local / localhost)**
Значит ваш собственный компьютер.

- `localhost` можно понять как "эта машина сама".
  Когда вы посещаете `http://localhost:3000`, на самом деле вы общаетесь с программой запущенной на вашем компьютере, не посещаете через интернет чужой сервер.

**Сервис (Service / Server)**
"Сервис" это **программа которая всё время в фоне работает, слушает ваши команды**:

- Веб-сервис: когда браузер посещает адрес, он возвращает содержание веб-страницы;
- Игровой сервис: отвечает за управление матчем, сохранение档案, таблица лидеров и т.д.
  Когда в терминале выполняете `npm run dev` запустить проект, это по сути "локально открыли веб-сервис".

## Раздел 3: Слова связанные с "фронтенд / бэкенд / данные"

### 1. Фронтенд, бэкенд

**Фронтенд (Frontend)**
Часть которую пользователь **может видеть, может кликнуть**:

- Кнопка, текст, изображение, анимация на веб-сайте;
- Страница написанная React / Vue.
  Отвечает за отображение интерфейса и ответ на операции пользователя (клик, ввод, перетягивание и т.д.).

**Бэкенд (Backend)**
Часть которую пользователь **не может видеть**, работает на сервере:

- Сохранение и чтение данных (информация пользователя, заказы, очки и т.д.);
- Выполнение бизнес-правил (проверка входа, проверка прав).
  Можно сравнить фронтенд с "витрина и продавец", бэкенд с "склад и система учёта".

### 2. Интерфейс, запрос, ответ, JSON

**Интерфейс / API**
Фронтенд и бэкенд заранее договорились "вопрос и ответ" правило.

- Фронтенд говорит: "я с этим адресом, этим форматом спрашиваю вас";
- Бэкенд говорит: "я с этим форматом дам вам результат".

**Запрос (Request)**
Один раз "спросить" которое фронтенд отправляет бэкенду:

- Куда идёт запрос (URL);
- Какой способ использует (GET, POST и т.д.);
- Какие параметры захватил (например ID пользователя).

**Ответ (Response)**
Бэкенд дал фронтенду "ответ":

- Статус код (200 успех, 404 не найдено, 500 ошибка сервера);
- Действительные данные (большинство JSON).

**JSON**
Способ показания данных используя **очень похожий на код JavaScript способ**, например:

```json
{
  "name": "Alice",
  "score": 120
}
```

Можно понять как "версия ключ-значение для машины", фронтенд и бэкенд часто обмениваются данные используя это.

**Переменная (Variable)**
"Наклейка нанесённая на блок данных".

- Например запомнить очки как `score`;
- Потом используя имя `score` может читать и писать этот блок данных:

```js
let score = 0
score = score + 10
```
