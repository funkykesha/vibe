# Начальный уровень 4: Добавление AI способностей к прототипу

## Введение в главу

В предыдущих разделах мы завершили полный цикл от **поиска хороших идей** к **созданию прототипа продукта**. Но текущий прототип — это только "оболочка" — клик по кнопке не создаёт содержимое, все данные на странице жёсткозакодированы.

Помните, что мы подчеркивали в первой главе? **Мы должны делать "продукт, за который люди готовы платить", а не "прототип, который выглядит хорошо"** Реальная ценность приходит от того, что продукт может **решить реальные проблемы**, и для этого прототип должен **действительно работать**.

В этой главе прототип "оживёт": мы встроим **реальные AI способности**, начиная с получения API Key, чтения официальной документации и помощи AI IDE в интеграции интерфейсов в код. Вы научитесь на примере **текстовой модели DeepSeek** как让приложение **действительно вызывать большую языковую модель для генерирования содержимого**; если вам интересно, вы также можете **выбрать интеграцию генерирования изображений**.

Поле завершения этой главы, ваш прототип **перестанет быть статической демонстрацией** и станет **приложением, которое может вызывать реальные AI способности и решать реальные проблемы**.

## 1. Основные концепции API

Как упоминалось ранее, наша цель — "встроить AI способности" чтобы прототип перестал быть статической демонстрацией и стал инструментом, который может вызывать реальные AI сервисы. Ключ к достижению этого — понимание и использование API (интерфейс программирования приложений).

API — это важная абстрактная концепция в компьютеростроении, мы можем просто понимать как: **вы "задаёте вопрос" в формате, требуемом другой стороной, и другая сторона "возвращает результат" в таком же формате**.

- **Содержимое, которое вы отправляете**: обычно включает "ключ (API Key)" и "что вы хотите создать"
- **Содержимое, которое вам возвращают**: если успешно — результат; если нет — скажут причину (например "ключ неправильный""баланс недостаточен""параметры неправильные")

Конкретно, вам нужно овладеть следующими основными элементами:

1. **API Key**: ваш "пропуск", также "ключ кошелька". Если кто-то его получит, может вызывать интерфейс от вашего имени и производить расходы.
2. **Endpoint (путь интерфейса)**: конкретный путь запроса API, говорит серверу какую функцию вы хотите вызывать. Полный адрес запроса обычно состоит из "базового URL + путь Endpoint". Например:
   - Генерирование текста: базовый URL (`https://api.service.com`) + Endpoint (`/v1/chat/completions`) = полный URL `https://api.service.com/v1/chat/completions`
   - Генерирование изображения: базовый URL (`https://api.service.com`) + Endpoint (`/v1/images/generations`) = полный URL `https://api.service.com/v1/images/generations`
3. **Вызов/запрос**: процесс отправки задачи AI сервису и получение результата
4. **Содержимое запроса**: конкретное содержимое, которое вы отправляете AI, например тема статьи, которую вы хотите AI написать, описание изображения которое нужно создать и т.д.
5. **Результат ответа**: содержимое, которое AI возвращает после обработки, например созданная статья, изображение и т.д.
6. **Обработка ошибок**: когда возникают проблемы (например неправильный API Key, слишком частые запросы), знать как диагностировать и решать проблемы.

> **ℹ️ Что такое API**
> 
> Для более глубокого объяснения API, смотрите приложение: [Введение в API](https://github.com/datawhalechina/easy-vibe/blob/main/docs/zh-cn/appendix/4-server-and-backend/api-intro/index.md).

> **🔐 Соображения безопасности API**
> 
> API Key — это "пропуск" для запроса AI сервиса, это строка символов пароля, используемая для аутентификации и выставления счетов.
> 
> Так как API Key напрямую связан с аккаунтом и расходами, обязательно обращайте внимание:
> 
> - Абсолютно **не делитесь в групповых чатах, не загружайте скриншоты в интернет** и не публикуйте на открытых форумах
> - **Не жёсткозакодируйте в коде** и не отправляйте в Git репозиторий (особенно открытый репозиторий)
> - Если вы подозреваете что Key скомпрометирован, **немедленно создайте новый Key**
> 
> Мы будем **прямо вставлять API KEY в AI IDE для операций** в содержимом ниже, **в реальных проектах так не делайте!!**, так как это учебный курс, это можно делать. (Когда вы станете более опытны, вы сможете дать AI создать файл конфигурации, вам только нужно будет вставить API KEY в файл конфигурации)

## 2. Интеграция API генерирования текста: DeepSeek

Хотя API включает эти технические концепции, на этапе разработки прототипа, операции могут быть очень простыми и эффективными. Основная идея:

> **Найти официальный пример, получить API Key, дать AI IDE помочь вам интегрировать на кнопку.**

Овладев этими концепциями, вы обнаружите, что независимо от интеграции текстовой модели или модели изображения, основной процесс одинаков: когда пользователь кликает кнопку, фронтэнд организует вводные данные и инициирует запрос; после возврата результата интерфейса, результат отображается на странице. Дальше, мы через реальную операцию проверим этот принцип.

В разделе `1.2 Создание прототипа` вы уже создали интерактивный прототип. Дальше нам нужно сделать следующее, преобразовать "функции, которые выглядят как AI" в настоящие способности: **когда пользователь кликает кнопку, прототип отправляет запрос внешнему AI сервису и отображает возвращённый текст.**

> **ℹ️ Расширение принципов**
> 
> Если вы хотите узнать больше о принципах, смотрите приложение: [Введение в большие языковые модели (LLM)](https://github.com/datawhalechina/easy-vibe/blob/main/docs/zh-cn/appendix/8-artificial-intelligence/llm-principles/index.md).

> **Что такое DeepSeek?**
> 
> **Hangzhou DeepSeek Artificial Intelligence Basic Technology Research Co., Ltd.** (杭州深度求索人工智能基础技术研究有限公司), под коммерческим названием DeepSeek, — это **компания китайского искусственного интеллекта (AI), разрабатывающая большие языковые модели (LLMs)**. Штаб-квартира DeepSeek находится в Ханчжоу, Чжэцзян, принадлежит и финансируется китайским хедж-фондом High-Flyer (幻方量化). DeepSeek была основана сооснователем High-Flyer Лян Вэньфэном в июле 2023 года, он также является CEO обеих компаний. Компания запустила одноименного чат-бота и модель DeepSeek-R1 в январе 2025 года.
> 
> Давайте посмотрим как DeepSeek выступает в сравнении с другими топовыми моделями в рейтинге GPQA. Стоит отметить, что DeepSeek — открытая модель (любой может скачать модель из интернета), в то время как другие часто используемые модели как Grok, Google Gemini и ChatGPT закрыты. Как видим, DeepSeek уже значительно приблизилась к моделям первого уровня.
> 
> GPQA — это аббревиатура "Graduate-level Google-Proof Q&A Benchmark", это рейтинговая базовая линия для задач научных вопросов на уровне выпускника. Вот детальное введение.
> 
> GPQA содержит 448 вопросов с множественным выбором, охватывающих подразделы биологии, физики и химии, такие как квантовая механика, органическая химия, молекулярная биология и т.д. Эти вопросы написаны 61 экспертом с докторской степенью или находящимися в процессе получения докторской степени, и прошли суровый процесс проверки.

## Больше выбора текстовых моделей генерирования

Кроме DeepSeek, вы также можете попробовать другие большие языковые модели. Так как большинство моделей предоставляют **совместимые с OpenAI интерфейсы**, переключение очень простое — просто нужно поменять API Key, базовый URL и имя модели.

### Интеграция MiniMax

> **Что такое MiniMax?**
> 
> **MiniMax** — это китайская компания искусственного интеллекта, посвящённая исследованиям и разработке технологии искусственного интеллекта общего назначения. MiniMax последовательно запустила серии больших языковых моделей MiniMax-M3 и MiniMax-M2.7, показав отличные результаты во многих тестовых критериях с очень высокой экономичностью.
> 
> **Главные характеристики серии MiniMax:**
> 
> - **Сверхдлинный контекст**: M3 поддерживает окно контекста до 512K tokens (M2.7 — 204,800 tokens), подходит для обработки длинных документов, многораундовых диалогов
> - **Высокая экономичность**: цена очень конкурентоспособная
> - **Совместимый с OpenAI интерфейс**: можно прямо использовать OpenAI SDK для вызова, не нужно учить новый формат API
> - **Доступные модели**:
>   - `MiniMax-M3`: новейшая флагманская модель, 512K контекст, 128K максимальный выход, поддерживает ввод изображений
>   - `MiniMax-M2.7`: предыдущая флагманская модель, всё ещё доступна
>   - `MiniMax-M2.7-highspeed`: высокоскоростная версия, сохраняет ту же производительность но быстрее

Способ интеграции такой же как DeepSeek, только три шага:

1. Перейдите на [открытую платформу MiniMax](https://platform.minimax.io/) зарегистрируйте аккаунт и создайте API Key
2. Найдите пример вызова в документации MiniMax
3. Вставьте API Key + пример в AI IDE

Так как MiniMax предоставляет совместимый с OpenAI интерфейс, вы можете прямо скопировать следующий curl пример и ваш API Key, отправить AI IDE для интеграции:

```bash
curl https://api.minimax.io/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ${MINIMAX_API_KEY}" \
  -d '{
        "model": "MiniMax-M3",
        "messages": [
          {"role": "system", "content": "You are a helpful assistant."},
          {"role": "user", "content": "Hello!"}
        ],
        "stream": false
      }'
```

> **✅ Подсказка**
> 
> Формат API MiniMax почти полностью совпадает с DeepSeek (оба совместимы с OpenAI), поэтому если вы уже успешно интегрировали DeepSeek, переключение на MiniMax требует только изменения трёх мест:
> 1. **Базовый URL**: измените на `https://api.minimax.io/v1`
> 2. **API Key**: используйте API Key MiniMax
> 3. **Имя модели**: измените на `MiniMax-M3` (новый флагман), `MiniMax-M2.7` или `MiniMax-M2.7-highspeed`
> 
> Больше информации смотрите [документация совместимого с OpenAI интерфейса MiniMax](https://platform.minimax.io/docs/api-reference/text-openai-api).

## 3. Интеграция API преобразования изображения в текст: Qwen3 VL

> **ℹ️ Расширение принципов**
> 
> Если вы хотите узнать больше о принципах, смотрите приложение: [Введение в модели визуального языка (VLM)](https://github.com/datawhalechina/easy-vibe/blob/main/docs/zh-cn/appendix/8-artificial-intelligence/multimodal-models/index.md).

> **Что такое Qwen3 VL?**
> 
> **Qwen3 VL** — это последняя версия серии многомодальных моделей визуального языка выпущенная командой Alibaba Qwen. VL означает "Vision-Language" (визуальный язык), то есть модель визуального языка. Она может понимать содержимое изображения и генерировать текстовые описания на основе изображения, отвечать на вопросы о изображении, извлекать информацию из изображения и т.д.
> 
> **Главные способности Qwen3 VL включают:**
> 
> - **Понимание изображения**: может распознавать объекты, сцены, людей, текст и другое содержимое в картинках
> - **Визуальный вопросо-ответ**: на основе вопроса пользователя, точно ответить на вопросы об изображении
> - **Описание изображения**: генерировать детальное или краткое текстовое описание изображения
> - **Понимание множества изображений**: поддерживает одновременную обработку нескольких изображений, выполнение сравнительного анализа
> - **Извлечение текста**: извлекать текстовое содержимое из изображения (способность OCR)
> 
> **Почему выбрать Qwen3 VL?**
> 
> По сравнению с предыдущей версией модели, Qwen3 VL имеет значительное улучшение в точности понимания изображения, поддерживает более длинные и сложные задачи анализа изображения. Она показывает отличные результаты в понимании китайского языка, относительно низкая стоимость вызова API, хороший коэффициент цены/качества. Кроме того, её окно контекста больше, может обрабатывать более сложные задачи визуальной логики.
> 
> **Типичные сценарии применения:**
> 
> - Электронная торговля: автоматическое генерирование названия товара, описание, продающие пункты из картинок
> - Создание содержимого: автоматическое генерирование текста на основе материала или рекомендация выбора картинок
> - Офис: извлечение содержимого картинок, автоматическое распознавание отчётов
> - Образование: автоматическое анализирование картинок вопросов, извлечение ключевых пунктов

В предыдущей части мы объяснили как интегрировать API генерирования текста, но для предыдущего сценария приложения мы обнаружим проблему, мы загружаем картинку, если используем только большую языковую модель, она не может хорошо понимать содержимое картинки, созданный результат может быть очень разным.

Мы хотим иметь модель которая может помочь нам превратить картинку в текстовое описание, это требует использования модели визуального языка (VLM). В примере, мы будем использовать модель визуального языка для генерирования описания продающих пунктов товара, улучшения пользовательского опыта.

Для удобства, мы используем интерфейс API [облачной платформы SiliconFlow](https://cloud.siliconflow.cn/me) для интеграции API преобразования изображения в текст.

> **Что такое Siliconflow?**
> 
> **SiliconFlow (硅基流动)** — известная в стране AI-платформа агрегирования моделей, предоставляет API интерфейс многих основных больших языковых моделей и моделей визуального языка.
> 
> **Характеристики платформы:**
> 
> - **Поддержка многих моделей**: интегрирует различные основные AI модели, включая открытые модели серий DeepSeek, Qwen, Llama и т.д.
> - **Технологическая оптимизация**: проводит оптимизацию вывода для открытых моделей, предоставляет API сервис с низкой задержкой и высокой параллельностью

>

## Приложение: Как найти "текущее сильное" AI модели

Развитие текстовых моделей (также часто называемых "большие языковые модели") очень быстро, всегда нам нужно убедиться что мы используем одну из моделей с лучшей производительностью. Через следующих два веб-сайта, вы можете легко увидеть "сейчас обычно используемые, с лучшей оценкой модели".

В основном, этот тип веб-сайта можно понимать как **"арена соревнования моделей"**: выведет выходы двух моделей вместе, вы голосуете за то, какой вам больше нравится. Модели с высокими голосами обычно означает "больше людей думает что она лучше используется".

Кроме того, вы иногда можете видеть в этих больших соревнованиях языковых моделей таинственные анонимные модели ("Unknown Model"). Это обычно означает: кто-то тихо поместил "внутреннюю тестовую модель" для слепого теста, вы можете иметь шанс заранее испытать более сильную способность.

### LMArena

Веб-сайт: <https://lmarena.ai/>

LMArena более подходит для определения "большинство людей предпочитают ответ какой модели". Много голосов, высокий счёт, обычно означает стабильнее в реальном использовании.

Простой способ использования:

1. Прямо смотрите рейтинговую таблицу (Leaderboard)
2. Сначала выберите направление что вам нужно делать (например общий диалог / программирование / зрение)
3. Выберите Top 3 тот, который вы можете использовать (доступно, цена приемлема, задержка приемлема)

### Artificial Analysis

Веб-сайт: <https://artificialanalysis.ai/>

Artificial Analysis более подходит для сравнения "эффект / цена / скорость" на одной таблице, вы можете рассматривать его как таблицу параметров выбора моделей.

Обычно способы использования:

1. Найти категорию моделей что вас интересует (текст / создание изображение и т.д.)
2. Смотрите индекс качества (Quality) + цену (Price) + задержку/пропускную способность (Latency/Throughput)
3. Выберите один "комплексное соотношение цены/качества" наиболее соответствующий вашему продукту

> **✅ Рекомендация**
> 
> Не спорьте на чувство "какой сильнее". Более надёжный способ: используйте одинаковый набор вводных данных одновременно тестировать 2-3 модели, потом комбинируйте рейтинг и цену принять решение.

## Заключение

При встраивании различных AI сервисов, не нужно воображать API слишком сложным. Усваивая следующие несколько основных концепций, в основном можете справиться с большинством сценариев:

**Сущность API это коммуникационный мост**. Это делает очень просто: отправляет ваш запрос, потом возвращает ответ модели. Вам не нужно заботиться что происходит позади, только нужно правильно организовать формат запроса.

**SDK это инкапсуляция API**. Если API это raw интерфейс, SDK это готовый набор инструментов — это делает запись сигнатуры запроса, обработку ошибок, валидацию параметра и другие сложные детали за вас. В дневной разработке, выбирайте SDK первым место, чем прямой вызов API, можете сэкономить много проблем.

**При чтении документации, обратите внимание на три вещи достаточно**: адрес сервиса (endpoint), удостоверение личности (API key) и как заполнить параметры вызова. Разобравшись с этими тремя пунктами, вызвать только вопрос времени.

Остальная работа, IDE и современные инструменты разработки помогут вам завершить. Сосредоточьтесь на вашей бизнес-логике, передайте нижнего уровня вызова на эти зрелые SDK и цепочки инструментов.
