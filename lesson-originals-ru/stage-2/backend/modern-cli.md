# Инструменты программирования AI в командной строке (CLI)

В этом уроке мы представим AI программные агенты, которые работают непосредственно в командной строке. Они отличаются от изученных ранее Trae и Cursor с интегрированными агентами — CLI AI инструменты программирования работают только в терминале. По сравнению с агентами, встроенными в IDE, они обычно имеют более длинное окно контекста, более быструю скорость вызова инструментов и поддерживают совместимость с более разнообразными большими языковыми моделями. В последних практиках AI Vibe Coding мы часто отдаем предпочтение CLI AI инструментам вместо встроенных в IDE агентов.

## Начиная с CLI

Помните ли вы о CLI, который мы представили ранее? CLI относится к использованию текстовых команд через терминал или командную строку для управления программным приложением, а не к полаганию на графический интерфейс (GUI — вы можете просто понимать его как интерфейс на компьютере или телефоне с кнопками и операциями наведения мыши, не требующей ввода команд).

> На Windows обычные терминалы включают "командную строку (cmd)" и "PowerShell". Вы можете запустить эти программы командной строки, введя "cmd" или "powershell" в поле поиска/запуска на вашем компьютере.

![Windows command prompt](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/backend/modern-cli/images/image1.png)![PowerShell](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/backend/modern-cli/images/image2.png)

CLI по своей природе подходит для текстовых командных операций. В небольшой группе экстремальных разработчиков (ищущих совершенства любителей программирования) CLI даже более популярен, чем GUI — они хотят, чтобы все операции выполнялись с помощью клавиатуры, считая, что перемещение мыши замедляет эффективность их кодирования.

В промышленности CLI часто является самой распространенной формой интерфейса, потому что GUI требует от операционной системы дополнительного рисования интерфейса и управления окнами, что требует больше ресурсов компьютера; в то время как CLI просто передает полученные команды системе для выполнения. Поэтому при подключении к большим кластерам серверов мы обычно взаимодействуем только через CLI.

![Large server clusters](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/backend/modern-cli/images/image3.png)

Для многих студентов без опыта работы с CLI может показаться, что операции CLI сложные, команд слишком много, и даже можно опасаться, что "можно случайно повредить компьютер". Не волнуйтесь. Помните, как мы часто просили Trae помочь выполнить различные базовые операции в предыдущих уроках? Мы можем полностью применить эту логику здесь — мы можем попросить CLI инструмент программирования помочь нам выполнить все операции CLI: помочь вам перейти в указанную папку, искать и обрабатывать файлы, запускать или копировать проекты с открытым исходным кодом и т.д. Весь процесс можно выполнить через диалог с CLI инструментом программирования AI.

## Что отличает его от IDE с AI?

Мы можем провести аналогию между CLI инструментами программирования AI и ранее изученными z.ai и Trae. В некотором смысле, CLI инструменты программирования AI можно рассматривать как специальный тип z.ai: они также требуют простого входа для диалога и будут автоматически выполнять все необходимые операции для вас (только иногда вам может потребоваться вручную открыть браузер для просмотра финального результата). Если провести аналогию с IDE с AI, то CLI инструменты программирования AI можно рассматривать как модуль Agent в IDE — то есть область диалога сбоку.

![IDE Agent interface](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/backend/modern-cli/images/image4.png)![CLI Agent comparison](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/backend/modern-cli/images/image5.png)

Однако, поскольку различные IDE с AI реализуют Agent по-разному и имеют большие различия в возможностях, производительность программирования AI часто нестабильна. Поэтому CLI инструменты программирования AI обычно разрабатываются напрямую крупными технологическими компаниями, такими как Anthropic (создатели Claude) и OpenAI (создатели ChatGPT).

По сравнению с другими AI программными агентами, непосредственное использование этих продуктов крупных компаний часто является лучшей практикой. Особенно Claude Code сам по себе создан для внутренней команды исследований и разработок Anthropic и был разработан с самого начала с целью "удовлетворения реальных потребностей инженеров".

Для более наглядного сравнения, мы можем просмотреть различия между Claude Code и определенным IDE с AI агентом (используя здесь Cursor как пример):

| Особенности функциональности | Claude Code | Cursor | Лучше |
| ----------------------- | ----------- | -------- | -------- |
| Автоматическое выполнение задач | ✅ Очень сильное | ❌ Ограниченные возможности | Claude Code |
| Интеграция IDE | ❌ Только командная строка | ✅ Встроенный VS Code | Cursor |
| Дополнение кода в реальном времени | ❌ Нет | ✅ Отличный опыт | Cursor |
| Многофайловые операции | ✅ Очень сильное | ⚠️ Хорошо | Claude Code |
| Интегрированные операции GitHub | ✅ Можно отправлять напрямую | ⚠️ Требует ручных операций | Claude Code |
| Кривая обучения | ⚠️ Среднее | ✅ Легко начать | Cursor |
| Длина контекста | ✅ Очень длинное | ⚠️ Хорошо | Claude Code |
| Помощь в отладке | ✅ Автоматизированная | ⚠️ Требует больше ручных операций | Claude Code |

Источник таблицы: <https://northflank.com/blog/claude-code-vs-cursor-comparison>

Проще говоря, CLI инструменты программирования AI обычно могут:

- Поддерживать более длительные непрерывные диалоги (даже могут помочь вам "работать целый день").
- Предоставлять более длинное окно контекста (больше не нужно часто говорить "продолжай").
- Иметь более быструю скорость ответа (можно подключить больше настраиваемых API моделей).

В операциях, связанных с кодированием, они обычно умнее и стабильнее, чем большинство встроенных в IDE агентов.

## Распространенные инструменты программирования CLI AI

Хотя в настоящее время существует много реализаций с открытым исходным кодом, в практике мы рекомендуем только две основные категории CLI инструментов программирования AI как "предпочтительную комбинацию". Вы можете выбрать одну на основе ваших привычек, и настоятельно рекомендуется попробовать обе, а затем выбрать наиболее подходящую для вас.

- Codex использует GPT-5, с более сильными общими возможностями;
- Claude Code передает API через GLM 4.6, общий опыт близок к Claude 4, но цена дешевле.
- OpenCode может свободно переключаться и комбинировать модели, предоставляя бесплатные модели, что позволяет лучше контролировать затраты.

Однако, какой из них лучше работает в реальных проектах, можно определить только путем личного тестирования. Овладение несколькими инструментами программирования AI всегда полезно: после овладения вы можете гибко переключаться между Claude Code, Codex или Trae в различных сценариях. Если после нескольких попыток вы обнаружите, что некоторый инструмент работает плохо, вы можете просто переключиться на другой инструмент или модель и продолжить экспериментирование.

В то же время, поскольку обновления версий моделей происходят очень быстро, рекомендуется сначала выбрать решение с лучшей "производительностью за деньги (эффект / стоимость)".

### Claude Code

Claude Code — это инструмент программирования AI, разработанный Anthropic на основе возможностей большой языковой модели Claude. Его основным сценарием взаимодействия является терминал, и он также поддерживается в качестве плагина VS Code. Подобно агентам в IDE с AI, он может глубоко понимать репозиторий кода разработчика и выполнять сквозные задачи разработки через инструкции на естественном языке — включая редактирование кода, исправление ошибок, выполнение и исправление тестов, управление рабочим процессом Git (например, разрешение конфликтов слияния, создание PR), сложное объяснение кода, выполнение команд терминала и т.д.

![Claude Code interface](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/backend/modern-cli/images/image6.png)

Преимущества Claude Code в основном проявляются в: чрезвычайно длинном окне контекста (может обрабатывать полные файлы и даже небольшие проекты), может активно уточнять неясные требования, автоматически планировать и распределять задачи выполнения, а также глубоко понимать и объяснять содержимое всей кодовой базы. По сравнению с обычным IDE агентом он больше подходит для "погруженного vibe coding" процесса разработки.

При практическом использовании вы можете направить диалог, чтобы помочь вам создавать новые проекты, выполнять операции CLI (например, организовывать папки, массовое переименование файлов, развертывание проектов с открытым исходным кодом и т.д.), настраивать среду разработки (например, устанавливать и отлаживать среду Python). Если вы считаете, что какой-то кусок кода трудно понять или структура папки нечеткая, вы также можете напрямую попросить Claude Code создать структурированный документ анализа или пошагово объяснить определенное содержимое.

Далее мы научимся использовать Claude Code. Поскольку прямое использование официального Claude Code часто имеет очень высокую стоимость (как показано на рисунке ниже), мы будем использовать платформу API, совместимую с протоколом Claude Code, но основанную на других больших языковых моделях.

![Claude Code pricing](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/backend/modern-cli/images/image11.png)

Вам нужно изучить несколько различных решений ниже (рекомендуется попробовать все), а затем выбрать наиболее подходящее для вас как основной практический путь.

Первый способ — напрямую использовать "API, совместимый с интерфейсом Anthropic". С растущей популярностью Claude Code все больше поставщиков больших языковых моделей начинают поддерживать способ вызова в стиле Anthropic. Обычные поставщики услуг включают GLM, Kimi, DeepSeek и Siliconflow и т.д., и они все предоставляют совместимые интерфейсы API. О конкретной конфигурации мы расскажем подробнее позже.

Следует отметить, что Claude Code обычно потребляет большое количество токенов. Если вы беспокоитесь о высокой стоимости вызова API, вы можете рассмотреть возможность покупки ежемесячного пакета GLM (около 20 юаней в месяц) для контроля затрат. Если вы хотите сначала почувствовать фактические затраты, вы также можете сначала пополнить счет на 10 юаней для небольших экспериментов.

Другой способ — использовать проект "Claude Code Route". Это инструмент с открытым исходным кодом, который не только поддерживает все обычные интерфейсы вызова API, но также позволяет вам точно настраивать модель для использования в различных сценариях и поддерживает подключение к локально развернутым большим языковым моделям. Однако, поскольку эта схема относительно сложна в конфигурации, рекомендуется начать с первого способа.

#### Использование GLM от Zhipu в качестве бэкэнда (рекомендуется)

GLM (General Language Model) — это серия больших языковых моделей, самостоятельно разработанных компанией Zhipu AI. GLM-4.6 является последней версией в серии GLM, с основным достоинством отличной производительности в способности кода (в открытых бенчмарках и реальных задачах соответствует Claude Sonnet 4, находится в первом уровне в стране).

![GLM capabilities](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/backend/modern-cli/images/image12.png)

Он также расширяет окно контекста до 200K, позволяя более удобно обрабатывать длинные тексты и большие объемы кода, одновременно укрепляя возможности рассуждения и вызова инструментов, достигая хорошего баланса между производительностью и стоимостью.

![GLM context window](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/backend/modern-cli/images/image13.png)

Перед подключением GLM нам необходимо сначала установить Claude Code.

Если вам кажется, что шаги установки из командной строки сложны или во время установки возникают ошибки, вы можете попросить агента Trae помочь вам с установкой.

```bash
# Установка Claude Code
npm install -g @anthropic-ai/claude-code

# Перейти в ваш проект
cd your-awesome-project

# Запуск Claude Code
claude

# Нажмите Ctrl+C для выхода из Claude
```

Далее нам нужно изменить адрес запроса API по умолчанию Claude Code, чтобы он поддерживал сервис API GLM. Вы можете напрямую скопировать следующее содержимое и попросить Trae помочь вам создать соответствующие переменные окружения; или вы можете выбрать их постоянное написание в переменные окружения системы (если возникнут проблемы, агент также может помочь вам их изменить).

Сначала вам нужно получить API Key GLM и сохранить его наиболее удобным для вас способом.

Адрес внутри страны: <https://bigmodel.cn/usercenter/proj-mgmt/apikeys>  
Международный адрес: <https://z.ai/manage-apikey/apikey-list>

Если вы используете **GLM для внутреннего рынка**, используйте следующую конфигурацию переменных:

```bash
# Выполните следующую команду в Cmd
# Примечание: замените `your_zhipu_api_key` на API Key, который вы только что получили
setx ANTHROPIC_AUTH_TOKEN your_zhipu_api_key
setx ANTHROPIC_BASE_URL https://open.bigmodel.cn/api/anthropic
```

Если вы используете **международный GLM**, используйте следующую конфигурацию:

```bash
# Выполните следующую команду в Cmd
# Аналогично замените `your_zai_api_key`
setx ANTHROPIC_AUTH_TOKEN your_zai_api_key
setx ANTHROPIC_BASE_URL https://api.z.ai/api/anthropic
```

Вы можете напрямую ввести подсказку в Trae, подобную той, что ниже:

⚠️ Если вы используете Trae для помощи в конфигурировании "постоянных переменных окружения", то после завершения конфигурации **вы должны перезагрузить Trae**, иначе переменные окружения во встроенном терминале не будут обновлены, что может привести к ошибкам входа или ошибкам подключения к сети.

```bash
Based on my environment variable settings:
setx ANTHROPIC_AUTH_TOKEN your_zai_api_key
setx ANTHROPIC_BASE_URL https://api.z.ai/api/anthropic

and my key (Replace it with your own key):
681fea485851d29060cc.13gfaendggaFOhb

please help me configure and start Claude Code
```

Вы увидите вывод, похожий на следующий:

![Claude Code setup process](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/backend/modern-cli/images/image14.png)

> **Что такое переменные окружения?**
>
> Переменные окружения по сути представляют собой набор информации о конфигурации "ключ-значение", хранящейся в операционной системе, обычно существующей в форме "имя переменной = конкретное значение". Пока программа предварительно настроена в терминале или системных параметрах, она может в любое время читать эти переменные для получения соответствующей информации. Поскольку переменные окружения можно писать непосредственно в терминал без необходимости изменения самого кода, мы обычно сохраняем ключи, необходимые для доступа к большим языковым моделям, в переменные окружения, чтобы избежать утечек. Программе просто нужно прочитать соответствующие переменные окружения, чтобы завершить вызов большой языковой модели.
>
> В системе Windows переменные окружения, кроме хранения ключей доступа к большим языковым моделям, часто используются для сохранения "пути вызова" инструментов командной строки.
>
> Мы знаем, что терминал сам по себе является программой. Иногда мы хотим запустить внешнюю программу в терминале, например ввести `claude` для запуска Claude Code. Причина, по которой вы можете просто ввести `claude` для запуска, заключается в том, что терминал будет читать переменные окружения системы, и переменная PATH содержит каталог, где находится исполняемый файл Claude Code, поэтому терминал может его найти и выполнить (эквивалентно вставке абсолютного пути этой программы в терминал и нажатию Enter).
>
> Типичная переменная окружения может выглядеть так: `PATH=C:\Windows\system32;C:\Program Files\Python`. Таким образом, мы можем выполнять эти программы в системе из любого пути, например, непосредственно вводя `python` в командной строке для запуска интерпретатора Python.
>
> Если вы хотите просмотреть текущие переменные окружения системы, вы можете ввести "переменные окружения" в поиск Windows и увидеть все переменные и их значения в появившемся окне "Редактирование переменных окружения системы". Некоторые переменные используются для хранения ключей больших языковых моделей, некоторые используются для добавления каталогов программ, облегчая вызов из любого пути.

**CLAUDE.md**

Ссылка: <https://www.anthropic.com/engineering/claude-code-best-practices>

`CLAUDE.md` — это специальный файл, который Claude автоматически читает и включает в контекст при запуске диалога. Поэтому он очень подходит для записи:

- Часто используемые команды bash
- Основные файлы и служебные функции
- Соглашения о стиле кода
- Способ тестирования
- Стандарты сотрудничества репозитория (например, именование веток, использование merge или rebase и т.д.)
- Описание конфигурации среды разработки (например, использование ли pyenv, рекомендуемый компилятор и т.д.)
- Поведение или ловушки, которые требуют особого внимания в проекте
- Любая информация, которую вы хотите, чтобы Claude "запомнил"

`CLAUDE.md` сам по себе не имеет обязательного формата, просто будьте краткими и удобны для чтения человеком. Например:

```markdown
# Bash commands
- npm run build: Build the project
- npm run typecheck: Run the typechecker

# Code style
- Use ES modules (import/export) syntax, not CommonJS (require)
- Destructure imports when possible (eg. import { foo } from 'bar')

# Workflow
- Be sure to typecheck when you're done making a series of code changes
- Prefer running single tests, and not the whole test suite, for performance
```

#### Внутренний принцип Claude Code

Ссылка: <https://github.com/shareAI-lab/analysis_claude_code>

Если вам любопытно, почему Claude Code в многих сценариях работает лучше, чем другие инструменты агентного программирования, такие как Trae или Cursor, мы можем просто посмотреть его внутренний механизм работы.

Общий способ реализации других CLI инструментов программирования AI также во многом похож.

![Claude Code internal mechanism](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/backend/modern-cli/images/image25.png)

Claude Code разбивает задачи программирования на непрерывный цикл "восприятие—мышление—действие—проверка" и в нем вызывает различные инструменты для выполнения задач. Он имитирует рабочий процесс человека-разработчика: постоянно "пишет код → запускает → смотрит результат → снова улучшает". Система в целом через основной цикл задач постоянно выполняет шаги. В каждом цикле Claude может вызывать различные инструменты — например, читать и писать файлы, выполнять команды, искать код и т.д. — а затем, на основе истинных результатов, возвращаемых инструментами, решать следующий шаг действия.

Есть несколько ключевых особенностей, достойных внимания:

- **Потоковая обработка (Stream Processing)**: Claude может одновременно думать и выводить результаты, вместо того чтобы ждать, пока весь код будет написан перед выполнением.
- **Интеллектуальное сжатие (Intelligent Compression)**: длинные диалоги могут привести к переполнению контекста. Claude сжимает историю в ключевую информацию, чтобы уменьшить вероятность "забывчивости", а через различение краткосрочной и долгосрочной памяти обеспечить эффективное выполнение.
- **Контроль параллелизма (Concurrency Control)**: внутренний параллельный дизайн позволяет выполнять несколько задач одновременно без помех друг другу.
- **Управление суб-агентом (Sub-agent Management)**: на практике это не просто эквивалент одной "роли", обрабатывающей все. Вы можете управлять несколькими суб-агентами, работающими совместно для обработки кода, каждый агент отвечает за различные задачи, такие как специально для тестирования, специально для написания документации и т.д.

### OpenCode

![OpenCode features](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/backend/modern-cli/images/image33.png)

OpenCode — это платформа AI Coding Agent с открытым исходным кодом, предназначенная для разработчиков, позиционируемая как "многомодельная версия Claude Code". Он использует Terminal в качестве основной точки входа взаимодействия, а также поддерживает интеграцию с редакторами (такие как VS Code, Neovim и т.д.), способен глубоко интегрироваться с локальным репозиторием кода и выполнять весь набор процессов разработки от понимания кода к инженерному выполнению через инструкции на естественном языке.

Это не инструмент программирования AI, привязанный к одной модели, а открытая платформа AI Coding Agent, которая может свободно переключать GPT, Claude, Gemini и даже локальные модели. Даже официальный OpenAI также позволяет OpenCode интегрировать Codex / подписку OpenAI.

#### Конфигурация модели и API (продвинутое)

Через `/connect` вы можете быстро подключить модель в интерфейсе чата, но если вам нужен более точный контроль — например, указать различные модели для различных задач, настроить несколько API Provider резервных копий — вы можете напрямую отредактировать файл конфигурации `opencode.json` OpenCode.

Этот файл находится в `~/.config/opencode/opencode.json` (путь Windows: `C:\Users\ваше имя пользователя\.config\opencode\opencode.json`), будет автоматически создан при первом запуске OpenCode.

Ниже приведен пример конфигурации для подключения модели Qwen платформы Bailian (Aliyun):

```json
{
  "model": "bailian-coding-plan/qwen3.5-plus",
  "small_model": "bailian-coding-plan/qwen3.5-plus",
  "provider": {
    "bailian-coding-plan": {
      "options": {
        "apiKey": "sk-ваш API ключ"
      }
    }
  }
}
```

> Формат поля `model` это `провайдер/имя-модели`. Вы можете получить API Key после регистрации на соответствующей платформе и заменить значение `apiKey` выше.

Если вы хотите одновременно настроить несколько моделей, вы можете указать различные категории задач в конфигурации:

```json
{
  "model": "bailian-coding-plan/qwen3.5-plus",
  "categories": {
    "visual-engineering": {
      "model": "bailian-coding-plan/qwen3.5-plus",
      "description": "фронтенд, UI/UX, дизайн, стили"
    },
    "ultrabrain": {
      "model": "bailian-coding-plan/qwen3-coder-next",
      "description": "сложная логика, алгоритмы, решения архитектуры"
    },
    "quick": {
      "model": "opencode-go/minimax-m2.5",
      "description": "простые изменения, исправления орфографии"
    }
  }
}
```

Таким образом, OpenCode будет автоматически выбирать наиболее подходящую модель на основе типа задачи: использовать быструю модель для простых изменений, чтобы сэкономить затраты, использовать более мощную модель для сложных проблем архитектуры для обеспечения качества.

#### Расширение OpenCode с помощью серверов MCP

MCP (Model Context Protocol) — это открытый протокол, который позволяет инструментам программирования AI вызывать внешние инструменты — например управление браузером, поиск в сети, анализ изображений и т.д. OpenCode изначально поддерживает MCP, способ конфигурации аналогичен Claude Code.

Добавьте конфигурацию сервера в поле `mcp` в `opencode.json`:

```json
{
  "mcp": {
    "chrome-devtools": {
      "type": "local",
      "command": ["npx", "-y", "chrome-devtools-mcp@latest"]
    },
    "zai-mcp-server": {
      "type": "local",
      "command": ["npx", "-y", "@z_ai/mcp-server"]
    }
  }
}
```

После перезагрузки OpenCode AI сможет автоматически вызывать эти инструменты в диалоге — например, помочь вам открыть браузер для скриншота, анализировать проблемы макета пользовательского интерфейса, поиск информации в интернете и т.д.

> **Практический сценарий**: Когда вам нужна помощь AI в анализе проблемы с макетом веб-страницы, добавьте MCP chrome-devtools, просто скажите "помоги мне открыть эту страницу, посмотри, почему позиция кнопки неправильная", и AI сможет автоматически открыть браузер, сделать снимок экрана, анализировать и предоставить рекомендации по исправлению.

#### Советы по повседневному использованию и часто задаваемые вопросы

**Использование AGENTS.md для направления поведения AI**

Создайте файл `AGENTS.md` в корневой папке проекта, чтобы сказать OpenCode соглашения вашего проекта и предпочтения. AI будет автоматически читать этот файл при каждом запуске:

```markdown
## Соглашения проекта
- Использовать TypeScript в строгом режиме
- Ответы API должны соответствовать JSON Schema
- Обработка ошибок использует пользовательские подклассы Error

## Рабочий процесс разработки
1. Понимать существующий код перед изменением
2. Мини-коммиты, каждый коммит — одна логическая единица
3. После завершения запустить npm test для проверки

## Запрещенные действия
- Не используйте тип any
- Не удаляйте файлы тестов
```

**Параллельное изучение кодовой базы**

Когда вы не знакомы с проектом, вы можете попросить OpenCode одновременно искать несколько аспектов:

> Пожалуйста, сделайте эти несколько вещей одновременно:
> 1. Найти все места в проекте, которые обрабатывают HTTP запросы
> 2. Найти весь код, связанный с базой данных
> 3. Перечислить структуру каталога проекта и ответственность каждого модуля

OpenCode будет параллельно выполнять эти задачи исследования, предоставляя вам полную карту кодовой базы за раз.

**Часто задаваемые вопросы**

| Вопрос | Решение |
|--------|---------|
| Команда `opencode` не найдена | Глобальный каталог npm не в PATH. В терминале выполните: `[Environment]::SetEnvironmentVariable("Path", "$env:Path;$env:USERPROFILE\AppData\Roaming\npm", "User")` и перезагрузите терминал |
| AI отвечает очень медленно | Для простых задач используйте категорию quick (автоматическая маршрутизация на быструю модель); когда история диалога слишком длинная, можно открыть новый сеанс |
| Ошибка вызова API | Проверьте, правильный ли API Key, правильно ли написано имя модели (формат provider/model-name), достаточно ли средств на счете |
| Навыки (Skills) не работают | Убедитесь, что формат файла SKILL.md правильный (требуется YAML frontmatter), и поле description точно описывает условие срабатывания |
| Контекст диалога слишком длинный | Откройте новый сеанс или определите ключевые соглашения в AGENTS.md, чтобы новый сеанс также их унаследовал |

## Дополнительное использование CLI инструментов программирования AI

### Использование AI для написания требуемых документов: научитесь "конкретизировать требования"

Для больших языковых моделей абстрактные требования должны быть "конкретизированы". Например: "Я голоден" — это абстрактное требование, нам нужно превратить его в: "Мне немного голодно, возможно, мне нужен красный хлеб из бобов, и еще кружка соевого молока." — это вид требований, который может быть выполнен.

Но превращение абстрактных требований в конкретные — это процесс, требующий много энергии. Если мы не видели достаточно примеров, трудно быстро подумать о том, как разобрать абстрактную проблему на детальные модули. В этом случае лучший способ — позволить AI помочь вам завершить этот шаг "конкретизации".

Например, я хочу разработать приложение "ежедневные планы", самое первоначальное мышление может быть:

`Please help me write a daily planning app where I can write my plans each day and get reminders.`

AI действительно может разделить задачи непосредственно на основе этого требования, а затем завершить их шаг за шагом, но в середине легко сделать ошибку или неправильное понимание. Чтобы снизить риск, мы можем попросить AI помочь нам сначала расширить требование:

`Based on my needs, please elaborate and provide a more detailed Product Requirement Document for reference. My idea is: Please help me write a daily planner app that supports daily plan-writing and provides reminders .`

В этом случае AI может дать результат, похожий на полный PRD ниже:

```
Product Requirements Document (PRD): "Today's Plan" App
Document Version: 1.0
Creation Date: October 27, 2023
Author: (Your Name/Product Manager)

1. Product Introduction
1.1 Product Name
Today's Plan
1.2 Product Vision
"Today's Plan" is a minimalist and highly efficient daily planning and reminder tool, dedicated to helping users eliminate procrastination and forgetfulness, plan every day clearly, and ensure tasks are carried out through an intelligent reminder system—ultimately enabling users to gain a stronger sense of control and achievement over their time.
1.3 Target Users (User Personas)
We mainly serve three types of users:
Students (Xiao Ming):
Characteristics: Multiple tasks such as courses, assignments, club activities, exam prep, needing organized time arrangement.
Pain Points: Easily forget small tasks or assignment deadlines; feel overwhelmed switching between tasks; want to build regular study and life habits.
Needs: A simple tool to list daily to-dos and provide reminders before class/self-study.
Office Workers (Zhang Wei):
Characteristics: Fast-paced work, many meetings, reports, project milestones, and personal affairs (fitness, picking up children).
Pain Points: Easily forget important meetings or work milestones; get interrupted by urgent tasks and forget the original plan; feel busy but inefficient at end of day.
Needs: Need a tool to quickly record and schedule daily work and send strong reminders at key times (e.g., 15 minutes before meetings).
Freelancers/Self-disciplined Seekers (Li Na):
Characteristics: High freedom of time, but strong self-management required for work output and personal growth.
Pain Points: Easily procrastinate, lack external supervision; start the day without a clear plan, leading to low time utilization.
Needs: Need a tool to help build a daily fixed routine (Morning Routine) and review daily achievements for positive feedback.

2. User Stories
As a user, I want to quickly create today's plan list so I have an overview of all my tasks for the day.
As a user, I want to set specific start and end times for each task so I can create a visual timeline.
As a user, I want to receive push notification reminders before a task starts so I won't miss any important arrangements.
As a user, I want to customize the reminder time (such as 5, 15, or 60 minutes in advance) so reminders better fit my habits.
As a user, I want to easily mark completed tasks so I can feel accomplished and clearly see my progress.
As a user, I want to see a summary of my completed plans at the end of each day for reviewing and self-motivation.
As a user, I want to conveniently edit and delete tasks to handle last-minute changes.
As a user, I want to view plans and achievements from previous days to review my efficiency and habits.

3. Feature Breakdown
Core Features (MVP - Minimum Viable Product)
Module 1: Plan Management
3.1.1 Daily Plan Homepage
Interface: "Today" as the core view, current date shown at the top.
View: Timeline list, clearly showing tasks scheduled from morning to evening. Tasks without a time can be listed in the top or bottom "To-do List" section.
Interactions:
Click the "+" button in the bottom right to quickly create a new task.
Pull down to refresh the page.
Swipe left/right to view yesterday's and tomorrow's plans.
3.1.2 Create/Edit Task
Entry: Click "+" on the homepage or a time slot in the list.
Fields:
Task title (required): Briefly describe the task, e.g., "10 AM Weekly Product Meeting."
Task time (optional):
Set "start time" and "end time."
Provide "all-day" option for unspecified time tasks.
Default time picker should be quick and convenient.
Reminder setting (required, with default value): See Module 2.
Notes (optional): Add further descriptions, links, or location info.
Actions: Save, cancel, delete task.
3.1.3 Task Interaction
Mark as complete: Checkbox before each task; checking adds a strikethrough and gray background, indicating completion. Can unmark if needed.
Edit task: Click the task itself to enter edit page.
Delete task: Swipe left on a task to reveal "Delete" button.
Module 2: Smart Reminder System
3.2.1 Reminder Trigger
Mechanism: Based on task's set "start time" and the user's "reminder lead time," send a push notification from device.
Offline Support: Locally scheduled reminders must trigger even if user is offline.
3.2.2 Reminder Content & Format
Notification title: App name "Today's Plan."
Body: "Reminder: [Task Title] will start at [Start Time]." E.g., "Reminder: Product Meeting will start at 10:00."
Sound: Use system default or offer several simple, effective tones.
3.2.3 Reminder Settings
Global Settings (in Settings page):
User can set a default reminder time, e.g., "15 minutes before task starts." New tasks adopt this by default.
Single Task Settings (in create/edit page):
Users can override global settings for important tasks, choosing specific reminder times like "on time," "5 minutes early," "30 minutes early," or "1 hour early."
Provide "no reminder" option.
Subsequent Features (V1.1, V2.0)
3.3 Daily Review & Statistics
Push a summary notification at a set time every night (e.g., 22:00): "How was your day? Take a look at your achievements!"
Generate a simple daily report card: shows total planned tasks, completed tasks, completion rate, plus an encouraging message.
3.4 History Review
Calendar view to click on any past day and check its plans and completion status. Days with high completion rates marked with a special color.
3.5 Templates
Allow users to save a successful daily plan as a template, e.g., "Efficient Workday," "Relaxing Weekend."
When creating tomorrow's plan, one-click import a template, modify slightly to save time.
3.6 Themes & Personalization
Offer dark mode.
Allow changing several primary color themes.

4. Non-Functional Requirements
4.1 Performance
Response: App launch time under 2 seconds; adding/editing tasks must be smooth and lag-free.
Resource Use: Low battery and memory consumption in background; do not over-consume resources waiting for reminders.
4.2 Usability
Minimal & intuitive: UI must be minimal, primary functions accessible within 3 clicks. No tutorial needed for new users.
Error tolerance: Offer undo (e.g. brief undo after mistakenly deleting a task).
4.3 Reliability
Reliable reminders: Reminder function is the product's lifeline; must guarantee 99.99% timely and accurate delivery.
Data loss-free: User plans must be reliably stored locally. Future versions can support cloud sync to prevent data loss on device change.
4.4 Compatibility
Platform: Support major iOS and Android versions (latest 3-4 releases).
Screen: Layout must fit various phone screen sizes.

5. Roadmap
V1.0 (MVP):
Goal: Validate core value—planning & reminders.
Features: Complete all "Core Features" described above (Plan management, smart reminders).
V1.1 (Quick Optimization):
Goal: Improve retention and achievement.
Features: Add "Daily Review & Statistics," "History Review."
V2.0 (Enhanced Experience):
Goal: Increase efficiency and personalization.
Features: Add "Templates," "Themes & Personalization," and start developing "Cloud Sync."
```

По сравнению с нашей первоначальной фразой "помоги мне написать приложение, где я смогу писать планы каждый день и получать напоминания", этот документ теперь намного более подробный. Вы можете добавлять, удалять и изменять содержимое в соответствии с вашими реальными потребностями; для некоторых модулей, в которых вы не уверены, вы также можете попросить AI предоставить больше альтернативных вариантов, а затем выбрать и объединить в финальную версию.

Таким образом, мы можем очень легко преобразовать абстрактные идеи в конкретные описания. Для разработки AI "конкретность" — это производительность: чем конкретнее требования, тем легче получить проект со стабильной структурой и высоким качеством. Вы можете попробовать таким образом переделать один из предыдущих мини-проектов и сравнить различия в результатах.

Если вы считаете, что этот вид "требуемых подсказок" слишком длинный, очень естественный способ — написать его отдельно в markdown документ в качестве "требуемого документа / документа разработки / PRD". После этого, каждый раз когда вы просите AI написать проект, вам просто нужно попросить его "ссылаться на этот документ", вместо того чтобы переписывать длинную подсказку каждый раз. Вы также можете непрерывно совершенствовать этот документ в процессе итерации, позволяя последующим проектам напрямую получать выгоду.

Ниже приведены некоторые другие распространенные сценарии использования:

### Управление папками

Мы можем попробовать использовать CLI инструмент программирования AI для управления различными файлами в текущей папке. Например, у вас есть куча беспорядочных файлов, которые нужно организовать и классифицировать, вы можете сказать Claude Code или Codex:

`Please help me organize the contents of the current folder. I want to group files with the same content together & I want to group files from the same time period together. Please help me handle this.`

### Разработка нового проекта

Это почти полностью совпадает с использованием, которое мы делали в z.ai, Trae раньше — мы также можем использовать CLI инструмент программирования AI для разработки нового проекта с нуля. Конечно, лучше подготовить требуемый документ заранее.

Чем более подробный документ требований, тем лучше финальный результат. Вы можете многократно оптимизировать документ на основе постоянно меняющихся идей; чем совершеннее документ, тем более стабильным и зрелым будет реализация кода.

### Развертывание проекта с открытым исходным кодом (например, Dify)

Для студентов, которые только начали работать с компьютерами, развертывание проекта с открытым исходным кодом из GitHub часто очень сложно. Но мы полностью можем передать эту работу Claude Code, как мы делали в учебнике Dify:

<https://github.com/langgenius/dify>

Если я хочу запустить свой собственный Dify локально, мне просто нужно передать эту ссылку Claude Code, а затем ввести:

`I want to deploy this GitHub project ``https://github.com/langgenius/dify`` . Please help me clone the project and run it.`

После получения вашего запроса Claude Code будет автоматически выполнять серию операций, включая получение кода с GitHub, конфигурирование среды запуска, запуск проекта и т.д. Если где-то в середине происходит ошибка или статус запуска проекта ненормален, вы можете затем выполнить небольшую ручную обработку в соответствии с подсказками. Помимо Dify, вы также можете использовать Claude Code для развертывания большинства распространенных проектов с открытым исходным кодом GitHub — вам просто нужен диалоговый ящик и время, чтобы выпить чашку кофе ☕️.

### Объяснение кода и написание документации

Для некоторых сложных проектов или больших проектов, созданных автоматически AI, вы можете почувствовать, что код слишком длинный, логика слишком сложная и трудно понять. В этом случае вы можете позволить CLI инструменту программирования AI помочь вам "прочитать код". Вы можете задать такие вопросы:

- Пожалуйста, объясни этот проект: как запустить, как использовать, как изменять и продолжать разработку в будущем?
- Пожалуйста, объясни общий процесс этого проекта: как работает программа? Какие операции может выполнять пользователь в интерфейсе?
- Пожалуйста, напиши полную документацию для этого проекта, включая документацию разработки и документацию запуска и т.д.
- На основе всего содержимого в текущей папке, пожалуйста, напиши подробное объяснение и сохрани в указанный markdown документ.

### Больше игровых методов

Конечно, CLI инструменты программирования AI могут делать намного больше, чем вышеизложенное. Не думайте о них только как о "инструментах кодирования", а думайте о них как об интеллектуальном агенте с независимой способностью действия. Вы можете попросить его помочь вам:

- Управлять и организовать локальные файлы;
- Писать дневники, писать резюме;
- Анализировать и исправлять системные ошибки;
- Выполнять различные повторяющиеся задачи командной строки и т.д.

Возможно, в недалеком будущем это станет самым важным и самым понимающим вас AI компаньоном на вашем компьютере.
