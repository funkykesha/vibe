# Как развернуть веб-приложение

В этом уроке мы представим, как развернуть ваше веб-приложение в интернете, чтобы другие люди могли его использовать. Мы представим три распространенные платформы развертывания: **Tencent Cloud CloudBase**, **Vercel** и **Zeabur**, помогая вам быстро завершить полный процесс от "написания кода" до "позволения другим людям использовать ваш веб-сайт через интернет".

# Что такое "развертывание"?

Перед тем как начать, давайте поймём, что означает "развертывание (Deployment)". Для того, чтобы любой веб-сайт могли использовать внешние пользователи, он должен иметь доступный в интернете сетевой адрес (этот адрес может быть IP адресом, например 123.45.67.89, или доменным именем, например [google.com](https://google.com/)). Но просто адреса недостаточно — весь код веб-страницы, который вы написали (например, файлы HTML, CSS, JavaScript или проекты, написанные на React, Vue и т.д.), а также связанные с ним ресурсы изображений / видео, должны быть "помещены" на сервер, который работает 24 часа в сутки, чтобы отвечать на сетевые запросы. Только тогда браузеры других людей смогут получать доступ и загружать эти ресурсы.

Весь процесс загрузки ресурсов, конфигурирования окружения и запуска сервиса называется **развертыванием (Deployment)**.

Проще говоря: веб-страница, которую вы написали на своём компьютере, может быть доступна только в браузере на локальном адресе, пока вы запускаете программу локально, потому что эти коды существуют только на вашем жёстком диске. "Развертывание" — это перемещение вашего кода и ресурсов на профессиональный сервер, подключённый к публичной сети, и его конфигурирование, чтобы сервер знал "как мне ответить, когда кто-то получает доступ" — например, когда кто-то вводит ваше доменное имя в браузер, сервер немедленно найдёт соответствующий файл веб-страницы, передаст содержимое обратно на устройство пользователя, позволяя пользователю увидеть вашу страницу.

Если развертывать вручную, проект часто требует нескольких шагов, и каждый шаг может быть проблематичным. Распространенные ключевые шаги включают:

1. **Подготовка сервера**: вам сначала нужно купить облачный сервер (например, Aliyun, Tencent Cloud или AWS EC2), выбрать регион сервера (например, Шанхай, Сингапур), конфигурировать (ЦП, память, размер диска и т.д.), и вам также нужно научиться удаленно подключаться к серверу (например, вход через SSH инструмент).

2. **Конфигурирование окружения**: веб-приложение требует определенного "окружения" для работы — например, запуск проекта Node.js требует предварительной установки Node.js; запуск проекта Python требует установки Python и соответствующих сторонних библиотек. Если версии окружения не совпадают, программа может выдать ошибку и не запуститься.

3. **Загрузка ресурсов**: вам нужно загрузить локальный код и ресурсы на сервер. Распространенные методы включают FTP или Git. Если проект больших объёмов (например, содержит видеофайлы), при разрыве соединения во время загрузки иногда требуется повторная загрузка.

4. **Запуск сервиса и тестирование**: после завершения загрузки, вам все еще нужно выполнить команду на сервере для запуска приложения и протестировать "может ли назначенный сетевой адрес быть доступен". Если к нему невозможно получить доступ, это может быть из-за того, что брандмауэр сервера не позволил соответствующий порт (например, ваше приложение слушает порт 3000, но этот порт заблокирован брандмауэром), или это может быть из-за ошибки в самой программе. В этом случае необходимо просмотреть журналы сервера для диагностики.

5. **Обслуживание и обновление**: каждый раз, когда вы изменяете код позже, вам нужно перезагрузить и перезапустить сервис. Если сервер выходит из строя (например, отключение питания, отказ сети), вам также потребуется вручную перезагрузить приложение. Иногда вам также нужно дополнительно конфигурировать "инструмент защиты процесса", чтобы программа автоматически перезапускалась после неожиданного выхода.

Платформы развертывания с низким кодом, такие как CloudBase, Vercel и Zeabur, были созданы для решения вышеуказанных сложных задач. Они автоматически завершают шаги "покупка сервера, конфигурирование окружения, загрузка кода, запуск сервиса, мониторинг работы" для вас. Вам просто нужно подключить свой репозиторий кода (например, GitHub или GitLab) к платформе или напрямую загрузить код, и она автоматически загрузит код, определит тип приложения, конфигурирует соответствующую среду выполнения, и затем предоставит вам публичный сетевой адрес, который может быть доступен кому-либо. Даже можно привязать свой собственный доменное имя одним щелчком.

Далее мы представим характеристики и способы использования этих трех платформ, помогая вам выбрать наиболее подходящий план развертывания.

# Сравнение платформ развертывания

| Платформа | Характеристики | Подходящие сценарии | Бесплатный объём |
|-----------|---------------|------------------|-----------------|
| **Tencent Cloud CloudBase** | Быстрая скорость доступа в стране, глубокая интеграция с экосистемой WeChat | Проекты с основными пользователями в стране, требующие поддержки мини-программ WeChat | Есть бесплатный объём |
| **Vercel** | Хорошая поддержка фронтенд фреймворков, плотная интеграция с GitHub | Современные фронтенд проекты на React/Vue/Next.js | Есть бесплатный объём |
| **Netlify** | Полные функции, поддержка обработки форм и аутентификации, хорошая интеграция с Git | Статические веб-сайты, требующие обработки форм и аутентификации | Есть бесплатный объём |
| **Zeabur** | Поддерживает несколько языков и шаблонов служб, гибкая конфигурация | Сложные проекты, требующие развертывания нескольких служб (например, Dify, n8n) | Около 5 долларов США в месяц бесплатный объём |

# 1. Tencent Cloud CloudBase

Tencent Cloud CloudBase (облачная разработка) — это комплексный облачный сервис бэкэнда, предоставляемый Tencent Cloud, особенно подходящий для отечественных разработчиков. Его преимущества:

- **Быстрая скорость доступа в стране**: серверы находятся в стране, низкая задержка доступа
- **Интеграция с экосистемой WeChat**: можно удобно подключить к мини-программам WeChat, публичным аккаунтам
- **Комплексное решение**: предоставляет полный набор услуг, включая хостинг статических веб-сайтов, облачные функции, базы данных, хранилище
- **Достаточный бесплатный объём**: личные разработчики имеют достаточный бесплатный объём ресурсов

## Развертывание веб-приложения с помощью CloudBase

### Шаг 1: Регистрация и вход

Посетите [консоль Tencent Cloud CloudBase](https://console.cloud.tencent.com/tcb), войдите, используя WeChat или QQ.

### Шаг 2: Создание окружения

Нажмите "Создать новое окружение", выберите имя окружения (например, `my-web-app`).

> ⚠️ **Внимание**: бесплатная пробная версия CloudBase требует кода обмена для открытия. Вам нужно подписаться на официальный аккаунт Tencent Cloud CloudBase, введите "получить код обмена" в официальном аккаунте, получите код обмена для бесплатной пробной версии, затем заполните код обмена при создании окружения для открытия бесплатного окружения (бесплатный пробный период 6 месяцев).

### Шаг 3: Открытие хостинга статических веб-сайтов

На странице управления окружением найдите функцию "хостинг статических веб-сайтов" и откройте её. После открытия вы получите доменное имя для доступа по умолчанию.

CloudBase предоставляет несколько способов развертывания хостинга статических веб-сайтов, подобных Zeabur:

- **загрузка локального проекта**: загрузка построенных статических файлов напрямую (HTML, CSS, JS и т.д.)
- **развертывание по шаблону**: использование предустановленных шаблонов для быстрого создания проектов, например шаблон React веб-приложения, шаблон Vue веб-приложения
- **развертывание репозитория Git**: поддержка автоматической загрузки кода из репозитория кода (например, GitHub) и развертывания

### Шаг 4: Развертывание кода

На странице хостинга статических веб-сайтов CloudBase предоставляет три способа развертывания:

**Способ 1: развертывание локального проекта (загрузка локального проекта)**
- выберите "развертывание локального проекта" в консоли
- загрузьте построенные статические файлы напрямую (HTML, CSS, JS и т.д.)
- выберите папку вашего локально построенного проекта (например, каталог `dist` или `build`)
- дождитесь завершения загрузки и вы сможете получить доступ

**Способ 2: развертывание по шаблону**
- используйте предустановленные шаблоны для быстрого создания проекта
- поддержка шаблона React веб-приложения, шаблона Vue веб-приложения
- построение и развертывание автоматически на основе шаблона

**Способ 3: развертывание репозитория Git**
- **развертывание личного репозитория Git**: привяжите свой личный репозиторий кода (например, GitHub)
- **развертывание публичного репозитория**: поддержка загрузки кода из публичного репозитория Git
- конфигурируйте команду автоматической сборки (например, `npm run build`)
- каждый раз, когда вы отправляете код, будет автоматически переразвёрнуто

> 💡 **Совет**: вы также можете использовать инструмент CLI для развертывания:
> ```bash
> # Установка CloudBase CLI
> npm install -g @cloudbase/cli
> # Вход
> tcb login
> # Развертывание
> tcb hosting deploy ./dist -e your-env-id
> ```

### Шаг 5: Конфигурирование пользовательского доменного имени (опционально)

В параметрах хостинга статических веб-сайтов вы можете привязать свой собственный домен и подать заявку на получение бесплатного сертификата HTTPS.

# 2. Vercel

Vercel — это одна из самых популярных платформ развертывания фронтенда в мире, особенно подходящая для развертывания проектов современных фронтенд фреймворков, таких как React, Vue, Next.js. Его характеристики:

- **глубокая интеграция с GitHub**: отправка кода автоматически развертывается
- **автоматический предпросмотр**: каждый Pull Request генерирует независимую ссылку предпросмотра
- **глобальный CDN**: веб-сайт автоматически распределяется на глобальные ноды, быстрая скорость доступа
- **бессерверные функции**: поддержка написания API бэкэнда в проекте

> ⚠️ **Внимание**: Vercel может быть нестабилен в некоторых сетевых окружениях. Пользователи в стране рекомендуется сначала рассмотреть CloudBase.

## Развертывание веб-приложения с помощью Vercel

### Шаг 1: Регистрация аккаунта

Посетите [официальный веб-сайт Vercel](https://vercel.com), войдите, используя аккаунт GitHub.

### Шаг 2: Импорт проекта

1. Нажмите "Add New Project"
2. Выберите репозиторий GitHub, который вы хотите развернуть
3. Если вы не видите нужный репозиторий, нажмите "Adjust GitHub App Permissions" для предоставления доступа

### Шаг 3: Конфигурирование параметров сборки

Vercel автоматически распознает тип проекта и конфигурирует команду сборки:

| Фреймворк | Команда сборки | Каталог вывода |
|----------|---|---|
| React | `npm run build` | `build` |
| Vue | `npm run build` | `dist` |
| Next.js | `next build` | - |
| Чистый HTML | - | корневой каталог проекта |

Если автоматическое распознавание неправильно, вы можете изменить вручную:
- **Build Command**: команда сборки, например `npm run build`
- **Output Directory**: каталог вывода сборки, например `dist` или `build`
- **Install Command**: команда установки зависимостей, обычно `npm install`

### Шаг 4: Развертывание

Нажмите кнопку "Deploy", дождитесь завершения сборки. После успешной сборки вы получите доменное имя вида `xxx.vercel.app`.

### Шаг 5: Пользовательское доменное имя (опционально)

На странице параметров проекта в разделе "Domains" можно добавить свой собственный домен. Vercel автоматически конфигурирует HTTPS.

# 3. Netlify

Netlify — это еще одна очень популярная платформа развертывания фронтенда, подобная Vercel, особенно подходящая для развертывания статических веб-сайтов и одностраничных приложений (SPA). Его характеристики:

- **полные функции**: кроме хостинга статических веб-сайтов, поддерживает обработку форм, аутентификацию, граничные функции и другие передовые функции
- **глубокая интеграция с Git**: поддержка GitHub, GitLab, Bitbucket, отправка кода автоматически развертывается
- **предпросмотр веток**: каждая ветка автоматически генерирует независимую ссылку предпросмотра
- **глобальный CDN**: веб-сайт автоматически распределяется на глобальные ноды, быстрая скорость доступа
- **обработка форм**: без кода бэкэнда вы можете обрабатывать отправку форм веб-сайта
- **аутентификация**: встроенная функция аутентификации пользователей, может быстро реализовать вход / регистрацию

> ⚠️ **Внимание**: скорость доступа Netlify в стране может быть не лучше, чем CloudBase. Рекомендуется использовать для проектов, в основном ориентированных на зарубежных пользователей.

## Развертывание веб-приложения с помощью Netlify

### Шаг 1: Регистрация аккаунта

Посетите [официальный веб-сайт Netlify](https://www.netlify.com), нажмите "Sign up" для регистрации. Вы можете зарегистрироваться, используя GitHub, GitLab, Bitbucket или адрес электронной почты.

### Шаг 2: Импорт проекта

1. После входа нажмите "Add new site" → "Import an existing project"
2. Выберите вашу платформу хостинга кода (например, GitHub)
3. Предоставьте Netlify доступ к вашему репозиторию
4. Выберите репозиторий, который вы хотите развернуть, из списка

### Шаг 3: Конфигурирование параметров сборки

Netlify автоматически распознает распространенные фронтенд фреймворки и конфигурирует параметры сборки:

| Фреймворк | Команда сборки | Каталог публикации |
|----------|---|---|
| React | `npm run build` | `build` |
| Vue | `npm run build` | `dist` |
| Angular | `ng build` | `dist/<project-name>` |
| Next.js | `next build` | `out` |
| Чистый HTML | - | `.` (корневой каталог проекта) |

Если автоматическое распознавание неправильно, вы можете конфигурировать вручную:
- **Build command**: команда сборки, например `npm run build`
- **Publish directory**: каталог вывода сборки, например `dist` или `build`

### Шаг 4: Развертывание

Нажмите кнопку "Deploy site", дождитесь завершения сборки. После успешной сборки вы получите доменное имя вида `xxx.netlify.app`, и любой человек может получить доступ к вашему веб-сайту по этому адресу.

### Шаг 5: Конфигурирование пользовательского доменного имени (опционально)

1. Перейдите в параметры сайта, нажмите "Domain management"
2. Нажмите "Add custom domain"
3. Введите ваше доменное имя и следуйте подсказкам для конфигурирования записей DNS
4. Netlify автоматически подаст заявку и конфигурирует сертификат HTTPS

### Специальные функции

#### 1. Обработка форм

Netlify предоставляет очень удобную функцию: обработка отправки форм без кода бэкэнда.

Просто добавьте атрибут `netlify` в HTML форму:

```html
<form name="contact" netlify>
  <p>
    <label>Имя: <input type="text" name="name" /></label>
  </p>
  <p>
    <label>Email: <input type="email" name="email" /></label>
  </p>
  <p>
    <label>Сообщение: <textarea name="message"></textarea></label>
  </p>
  <p>
    <button type="submit">Отправить</button>
  </p>
</form>
```

После развертывания данные отправки формы будут автоматически отправлены на бэкэнд Netlify. Вы можете просмотреть все записи отправки на странице "Forms". Вы также можете установить уведомления по электронной почте или перенаправить данные на другие сервисы.

#### 2. Netlify Functions (граничные функции)

Netlify поддерживает развертывание бессерверных функций, позволяя вам реализовать простые интерфейсы API без построения полного сервера бэкэнда. Вы можете писать функции на JavaScript или TypeScript. После развертывания автоматически получаете доступный URL.

Например, создайте файл `hello.js`:

```javascript
exports.handler = async (event, context) => {
  return {
    statusCode: 200,
    body: JSON.stringify({ message: "Hello from Netlify!" })
  };
};
```

После развертывания вы можете получить доступ к этой функции через `https://ваш-домен/.netlify/functions/hello`.

#### 3. Поддержка локальной разработки

Netlify предоставляет инструмент CLI для удобной локальной разработки и тестирования:

```bash
# Установка Netlify CLI
npm install -g netlify-cli

# Вход в аккаунт
netlify login

# Локальный запуск сервера разработки
netlify dev

# Локальное тестирование функций
netlify functions:serve
```

Использование инструмента CLI позволяет имитировать окружение Netlify локально, включая отправку форм, вызовы функций и другие функции, удобно для тестирования перед развертыванием.

# 4. Zeabur

Zeabur — это новая появившаяся платформа развертывания, особенно подходящая для сложных проектов, требующих развертывания нескольких служб. Его преимущества:

- **богатые шаблоны служб**: встроены шаблоны многих служб, таких как Dify, n8n, базы данных
- **поддержка нескольких способов развертывания**: GitHub, шаблоны, Docker образы, локальные проекты
- **гибкое комбинирование служб**: можно развертывать несколько взаимосвязанных служб в одном проекте
- **оплата по использованию**: платить за то, что используете. Подходит для экспериментальных проектов

## Развертывание Dify с помощью Zeabur

На предыдущих уроках мы кратко познакомились с Dify. Теперь мы можем очень легко запустить собственный сервис Dify через [Zeabur](https://zeabur.com/projects). Сначала откройте [страницу консоли](https://zeabur.com/projects), давайте посмотрим на различные область.

На этой странице вы сначала можете видеть много квадратов, это развёрнутые сервисы. В верхнем меню вы увидите несколько опций, таких как Agent, Servers, Docs, Templates. Они соответственно представляют:

1. **Agent**: можно открыть встроенный интеллектуальный помощник (Agent) Zeabur, задавать ему вопросы о том, как оперировать или запрашивать статус текущего сервера.
2. **Servers**: здесь вы можете добавить облачные серверы, которые вы купили сами, или напрямую купить серверы через Zeabur.
3. **Docs**: просмотр полной документации Zeabur.
4. **Templates**: здесь перечислены все встроенные шаблоны образов.

> "Образ (Image)", упомянутый здесь, может быть понят как "сжатый пакет, содержащий код и окружение выполнения". После успешного запуска определенного сервиса на одном сервере, мы можем выбрать "упаковать это окружение выполнения + код" в образ. Позже, на любом новом сервере, пока мы распакуем и запустим этот сжатый пакет, нам не нужно переконфигурировать окружение и код. Сервис может сразу же запуститься.

В правом верхнем углу страницы вы также можете увидеть свой баланс. По умолчанию каждый месяц есть бесплатный объём около 5 долларов. О деталях правил тарификации пока можно не слишком беспокоиться. Просто знайте: пока сервер работает, он потребляет объём.

Нажмите на баланс, чтобы просмотреть детали дневного потребления.

Теперь создадим собственный сервис Dify. Сначала на [главной странице консоли](https://zeabur.com/projects) нажмите "New Project".

Далее объяснение различных способов создания:

1. **GitHub**
   Можно подключить к своему аккаунту GitHub. После привязки вы можете напрямую выбрать проект из репозитория GitHub для развертывания (GitHub — это на данный момент самая крупная платформа хостинга кода в мире).

2. **Template (шаблон)**
   Можно развертывать сервисы на основе шаблонов. Zeabur имеет встроены много предустановленных шаблонов проектов (например, Dify, n8n и т.д.). Вы можете быстро создать и развернуть приложение на основе этих шаблонов.

3. **Databases (базы данных)**
   Используется для развертывания служб базы данных, таких как MySQL, MongoDB и другие распространённые базы данных.

4. **Functions (функции)**
   Можно развертывать сервисы функций. Вы можете писать код на JavaScript или Python и позволить их быть вызваны в форме функций.

5. **Local Project (локальный проект)**
   Загрузить локальную папку. Zeabur автоматически распознает стартовый скрипт в её. Это подходит для быстрого развертывания проекта, который вы уже разработали локально, на Zeabur.

6. **Docker Image**
   Развертывание уже упакованного Docker образа. Если ваш проект уже упакован в Docker образ (например, хранится в Docker Hub или другом репозитории образов), вы можете напрямую развернуть его здесь.

7. **Cursor**
   Если вы установили Cursor (например, Cursor IDE), вы можете развернуть проект в Cursor на Zeabur через этот вход.

Если вы хотите развернуть собственный сервис Dify, рекомендуется выбрать способ **Template**, затем введите "dify" в поле поиска. Вы можете видеть множество версий, поддерживаемых различными авторами. Вы можете выбрать любую из них (например, версию v1.6.0).

Далее, введите любое имя. Zeabur создаст временное пользовательское доменное имя на основе этого имени. Позже все люди могут получить доступ к вашему сервису через этот веб-адрес.

После создания вы увидите, как несколько программ (сервисы) поочередно запускаются. Вам нужно терпеливо ждать, пока все сервисы не перейдут в статус "запущено". (Сервис Dify состоит из нескольких программ. Каждая программа отвечает за различные функции и сотрудничают друг с другом.)

Как правило, вам просто нужно нажать на приложение Dify слева, чтобы увидеть адрес входа по умолчанию. Однако в этом примере, поскольку впереди есть ещё один слой nginx, вам нужно нажать на сервис nginx, чтобы получить финальный адрес доступа. Поймите это так: nginx — это основная программа, отвечающая за внешний "приём и отправку запросов", которая будет распределять адреса внешних обращений различным внутренним сервисам. Нажмите на nginx слева. На странице деталей вы можете видеть текущий адрес сервиса. Затем откройте этот адрес в браузере и ждите, пока сервис полностью запустится.

Спустя мгновение, вы увидите интерфейс входа Dify. Введите адрес электронной почты и пароль регистрации, и вы сможете начать использовать свой собственный сервис Dify.

Если вам интересно, вы также можете запустить сервис n8n. n8n также является очень популярной платформой рабочего потока AI за границей.

## Развертывание игры "Змейка" с использованием Zeabur и Trae

В следующей части этого урока мы испытаем некоторые продвинутые использования Zeabur. Мы сначала используем Trae для создания малой игры в "Змейку", а затем развертываем её на сервере Zeabur и конфигурируем доступную для всех публично ссылку, позволяя кому-либо открыть вашу игру.

Первый шаг — это создание проекта "Змейка" локально с помощью Trae.

### Реализация с использованием HTML фреймворка

Для Trae создание веб-игры "Змейка" на основе HTML очень просто. После создания игры, вам просто нужно следовать представленному выше способу локального развертывания Zeabur, загрузить папку, содержащую все файлы.

После завершения вы перейдете на страницу деталей этого сервиса.

Нажмите на опцию "Network" слева. На странице найдите область "Public Address". Нажмите "Generate Domain", и вы создаёте адрес для внешнего доступа. Вы можете ввести любое понравившееся имя.

После создания, просто откройте этот адрес в браузере, вы сможете запустить собственную игру "Змейка". Другие типы веб-приложений HTML также можно развертывать абсолютно так же.

### Реализация с использованием фреймворка React

Выше мы научились развертывать веб-приложения на основе чистого HTML. Далее, мы попробуем развернуть более распространенный фронтенд фреймворк: приложение React. По сравнению с чистым HTML, React считается более зрелым и современным фреймворком фронтенд разработки. Он организует структуру страницы через компонентный подход, может значительно ускорить разработку сложных страниц и является очень популярным выбором в корпоративных проектах.

#### Переструктурирование в архитектуру React

В Trae вам просто нужно сказать Agent: "помоги мне переструктурировать этот код в архитектуру React", и вы сможете довольно легко переструктурировать первоначальную структуру на основе HTML в проект React.

Однако, по сравнению с простыми файлами HTML, приложения React зависят от более сложных инструментов построения и структуры проекта. Поэтому процесс развертывания будет немного более сложным. Типичная проблема проявляется в конфигурировании портов: по умолчанию приложения React обычно слушают порт 3000 (вы также можете видеть это в файле конфигурации или в логах запуска). 

Однако развертывание таким образом на Zeabur будет неудачным — потому что Zeabur поддерживает только приложения, слушающие порт 8080. Другими словами, если вы хотите, чтобы приложение React нормально работало на Zeabur, мы должны сначала изменить порт прослушивания по умолчанию с 3000 на 8080.

Чтобы правильно выполнить этот шаг конфигурирования, нам нужно сначала понять два понятия: что такое "порт (Port)" и что означает "прослушивающий порт (Listening Port)".

#### Что такое порт?

В компьютерной сети порт может быть понят как "логическая конечная точка коммуникации", используется для различия различных сетевых сервисов, работающих на одном устройстве. Проще говоря, если IP адрес как "номер дома" (например, 162.128.1.1), то номер порта подобен "номеру комнаты" в этом здании — каждая комната соответствует сервису (например, веб-сервер, почтовый сервис или ваше приложение React).

Номера портов представлены 16-битным целым числом. Диапазон значений составляет от 0 до 65535.

Если вы не хотите запоминать эти детали, вы можете просто понять: порт — это необходимая часть, составляющая "сетевой адрес доступа".

Когда мы обычно получаем доступ к веб-сайтам или IP адресам, мы обычно не добавляем номер порта вручную, потому что портом веб-приложения по умолчанию являются 80 или 443 (HTTPS). Большинство браузеров автоматически используют эти стандартные порты. Однако для некоторых специальных портов, таких как React по умолчанию 3000 и требуемый Zeabur 8080, мы должны добавить `:3000` или `:8080` после адреса, чтобы получить доступ к соответствующему содержимому.

#### Что означает "прослушивающий порт"?

"Прослушивающий порт" означает, что определённая программа активно "открывает и мониторит" порт на устройстве. Когда приложение устанавливает прослушивающий порт, это в сущности говорит операционной системе: "я буду постоянно ждать сетевых запросов на этом порте — как только запрос поступит, пожалуйста, перенаправьте его мне".

Еще образно понимая: предположим, ваш компьютер — это офисное здание. IP адрес — это адрес здания. В здании открыто много компаний или отделов. Они соответственно занимают разные комнаты. Номера комнат — это номера портов.

Когда запускается сервер разработки React по умолчанию, он "открывает" некоторую комнату и нанимает "администратора" для дежурства у дверей. Номер комнаты — это его прослушивающий порт — 3000.

Одновременно программа React скажет "управлению" здания (операционной системе): "я в комнате 3000. Пожалуйста, перенаправьте все письма (сетевые запросы), отправленные на 3000, мне."

Таким образом, когда вы получаете доступ к веб-сайту React, запрос сначала поступает в здание; управление видит, что запрос должен быть отправлен в комнату 3000 и сразу же передаёт запрос "администратору" React для обработки и возврата результата — это процесс доступа к приложению React.

Когда вы выполняете `npm start` локально (команда по умолчанию для локального запуска сервера разработки React, вы также можете выполнить её в боковой панели Agent Vibe Coding), сервер разработки React автоматически установит прослушивающий порт на 3000.  
Однако архитектура платформы Zeabur определяет, что она будет "распознавать" только приложения, прослушивающие порт 8080. Если ваше приложение React всё ещё использует порт 3000 по умолчанию, Zeabur не сможет правильно перенаправить запросы вашему приложению, что в конце концов приведет к неудаче развертывания.

#### Модификация порта прослушивания по умолчанию

Есть много способов изменить порт прослушивания React по умолчанию (3000) на требуемый Zeabur 8080. Самый простой способ — это просто в Trae дать Agent указание: "пожалуйста, помоги мне изменить порт прослушивания по умолчанию этого проекта React на 8080." Trae поможет вам модифицировать соответствующие файлы конфигурации проекта. После модификации вам просто нужно пересобрать проект и загрузить его на Zeabur по приведённому выше способу.

В параметрах сети указать адрес доступа, способ примерно такой же, как при развертывании проекта HTML. Вы сможете запустить версию React сервиса.

Для других программ, которые требуют изменения номера порта, вы также можете применить ту же идею: сначала измените порт по умолчанию, затем загрузите на Zeabur для развертывания. К этому моменту вы уже овладели основными навыками развертывания обычных веб-приложений на сервер.

Вы можете попробовать позволить Trae помочь вам построить различные типы приложений и развернуть их на стандартном сервере Zeabur. В последующих уроках мы также научимся тому, как развернуть приложение на облачном сервере, который вы купили самостоятельно.

# ⚠️ Как остановить и удалить проект (Zeabur)

Поскольку включение ресурсов сервера приводит к затратам, мы должны развить привычку "вовремя закрывать неиспользуемые сервисы", чтобы избежать исчерпания бесплатного объёма каждый месяц.

Если вы хотите найти вход управления проектом, сначала нажмите опцию "Settings" в проекте.

После входа на страницу параметров прокрутите страницу вниз. Вы увидите аналогичный интерфейс ниже:

Вы можете нажать "Suspend All Services" для приостановки всех сервисов с целью снижения затрат; если сервис имеет проблемы, вы можете нажать "Restart All Services" для перезагрузки всех сервисов. Если вы уверены, что этот проект больше не нужен, вы можете нажать "Delete Project" для полного удаления проекта.

# Заключение

В этом уроке мы представили четыре распространенные платформы развертывания веб-приложений:

1. **Tencent Cloud CloudBase**: подходит для пользователей в стране, быстрая скорость доступа, хорошая интеграция с экосистемой WeChat
2. **Vercel**: подходит для проектов современных фронтенд фреймворков, плотная интеграция с GitHub, ускорение глобальным CDN
3. **Netlify**: полные функции, поддержка обработки форм и аутентификации, подходит для статических веб-сайтов, требующих продвинутых функций
4. **Zeabur**: подходит для сложных проектов, богатые шаблоны служб, поддержка различных способов развертывания

Выбор платформы зависит от ваших конкретных требований:
- Если основные пользователи находятся в стране, рекомендуется **CloudBase**
- Если используются фреймворки React/Next.js и т.д., рекомендуется **Vercel** или **Netlify**
- Если требуется обработка форм, аутентификация и другие продвинутые функции, рекомендуется **Netlify**
- Если требуется развертывание Dify, n8n и других сервисов, рекомендуется **Zeabur**

Независимо от выбранной платформы, основной процесс развертывания одинаков: подготовка кода → выбор платформы → конфигурирование параметров сборки → развертывание в сети. Овладев этими навыками, вы сможете поделиться приложением, разработанным вами, со всем миром!
