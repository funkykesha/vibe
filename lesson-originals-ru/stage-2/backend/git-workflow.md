# Git и GitHub рабочие процессы

На предыдущих уроках мы научились писать код, используя веб-инструмент vibe coding. Каждое обсуждение создает новую версию кода. Но давайте подумаем о проблеме: если мы хотим вернуться к предыдущей версии, существует ли удобный способ? Существует ли инструмент, который может записывать наш код на разных этапах, позволяя нам переключаться и изменять различные версии в любое время?

Для удовлетворения этой потребности была создана программа версионного контроля. В этой статье мы представим самую известную программу версионного контроля — Git — и лучшую платформу хостинга кода — GitHub. Мы научимся управлять кодом с помощью Git, получать код других людей с GitHub, загружать собственный код и сотрудничать с другими людьми в больших проектах.

Будь то отслеживание версий в личных проектах, синхронизация кода в командной работе или участие в вкладе в сообщество открытого исходного кода, Git и GitHub являются необходимыми инструментами для современных разработчиков. Овладев ими, вы сможете более эффективно управлять кодом, создавать контрольные точки по мере необходимости, свободно переключаться между различными этапами кода и легко справляться со всем — от изменения одного файла до разработки крупного проекта — делая каждую итерацию кода контролируемой и отслеживаемой.

## Инициализация Git

После установки Git вам сначала нужно настроить информацию о пользователе — это основной шаг для использования Git в версионном контроле. Выполните следующие команды в терминале (замените содержимое в скобках на вашу информацию):

```bash
# Установить глобальное имя пользователя (будет отображаться в истории коммитов)
git config --global user.name "Your Name"

# Установить глобальную почту (рекомендуется использовать почту, зарегистрированную на GitHub/GitLab)
git config --global user.email "your.email@example.com"
```

Git встроит эту информацию в каждый коммит как "информацию об авторе" каждого изменения. При просмотре истории версий (например, используя git log), вы можете ясно видеть, кто изменил каждую строку кода, облегчая отслеживание ответственности и общение. В проектах совместной работы единая информация об идентичности позволяет членам команды быстро определить, кто внес какие изменения, тем самым повышая эффективность сотрудничества (например, найдя соответствующего разработчика через историю коммитов для обсуждения проблемы).

Вы можете просмотреть информацию о текущей конфигурации Git, введя `git config --list` в командную строку, чтобы убедиться, что настройка выполнена успешно.

# Что такое GitHub

GitHub — это платформа хостинга кода на основе Git. Она не только предоставляет удаленное хранилище для репозиториев Git, но также включает инструменты совместной работы (такие как Issues, Pull Requests, Projects), что облегчает разработчикам обмен кодом и сотрудничество. Проще говоря, Git — это локальный инструмент версионного контроля, а GitHub — это удаленный "облачный диск для репозитория кода + сообщество сотрудничества".

GitHub — это не только самая крупная платформа хостинга кода в мире, но и наиболее активное и влиятельное сообщество открытого исходного кода в глобальном масштабе. Ядро идеи "открытого исходного кода" здесь состоит в том, что каждый может загружать и запускать исходный код программного обеспечения. Этот подход позволяет людям со всего мира проверять чужой код и вносить изменения, или создавать новые проекты на его основе. Например, вы можете найти различные учебные материалы на GitHub, а также полный исходный код фреймворков, используемых для обучения моделей GPT (таких как PyTorch). Каждый день бесчисленные люди по всему миру сотрудничают в рецензировании и улучшении кода.

![GitHub interface](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/backend/git-workflow/images/image9.png)

Многие крупные компании публикуют свои программы или учебные материалы с открытым исходным кодом на GitHub, чтобы получить конкурентное преимущество в отрасли — это также можно рассматривать как форму рекламы. В сообществе GitHub количество "звезд (stars)", полученных проектом, является основным показателем его ценности; чем больше звезд у проекта или организации, тем больше его надежность и влияние.

![GitHub star system](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/backend/git-workflow/images/image10.png)

В нашем курсе вспомогательные материалы и задания также будут загружены в специальный репозиторий GitHub. Благодаря процессу загрузки заданий вы постепенно ознакомитесь с GitHub и освоите его использование, установив прочную основу для версионного контроля в будущей разработке приложений.

## Привязка локального SSH

В GitHub "привязка SSH протокола" по сути означает связать SSH открытый ключ вашего локального устройства с вашей учетной записью GitHub, позволяя GitHub распознать ваше устройство через протокол SSH. Это позволяет вам безопасно работать с удаленными репозиториями без пароля (например, clone, push или pull кода).

Проще говоря: это похоже на предоставление вашему устройству "пропуска доступа на GitHub". После привязки, когда ваше устройство получает доступ к репозиторию GitHub через протокол SSH, GitHub проверяет этот "пропуск доступа" (ваш SSH открытый ключ). После подтверждения как авторизованного устройства вы можете напрямую выполнять операции — без необходимости вводить пароль учетной записи каждый раз.

> **Что такое SSH**

### Почему нужна привязка SSH протокола?

GitHub поддерживает два основных протокола для операций репозитория: протокол HTTPS и протокол SSH:

- Протокол HTTPS: каждая операция (например, push) требует ввода пароля учетной записи GitHub (или личного токена доступа PAT). Процесс проверки утомительный и существует риск утечки пароля.
- Протокол SSH: аутентификация выполняется через "пары ключей", поэтому не требуется повторный ввод пароля и передача данных более безопасна в виде зашифрованной.

"Привязка SSH протокола" является предварительным шагом для включения аутентификации GitHub SSH — только после привязки локального SSH открытого ключа к учетной записи GitHub GitHub может распознать ваше устройство и разрешить SSH операции с репозиториями.

### Основная логика "привязки": роль SSH пары ключей

Аутентификация SSH зависит от пары ключей (открытый ключ + закрытый ключ), которые являются совпадающими зашифрованными файлами. После создания вам нужно предоставить "открытый ключ" GitHub ("привязка"), а "закрытый ключ" оставить на локальном устройстве:

1. Закрытый ключ: хранится в указанной папке на локальном устройстве (например, компьютер) (обычно это ~/.ssh/), функционирует как "ваш исключительный ключ" и никогда не должен быть поделен с кем-либо.
2. Открытый ключ: это "замок", который можно публично поделиться — вам нужно скопировать его в "SSH keys list" вашей учетной записи GitHub ("операция привязки").

Когда вы выполняете операции с репозиторием GitHub через SSH (например, git push git@github.com:xxx/xxx.git):

- ваше локальное устройство использует закрытый ключ для шифрования "запроса операции" и отправки его на GitHub;
- после получения запроса, GitHub пытается расшифровать его с помощью ранее привязанного открытого ключа;
- если расшифровка успешна, ваше устройство подтверждается как авторизованное, операция разрешена; в противном случае доступ запрещен.

### Конкретные шаги "привязки" (основной процесс)

После того как вы поняли принцип, фактическая операция очень проста — основное это "генерировать пару ключей → загрузить открытый ключ на GitHub":

1. Локальное создание пары SSH ключей
   1. Использование Trae для получения открытого ключа (рекомендуется)
      Подсказка: `Help me create the SSH key needed for GitHub login. My email is your_email@gmail.com , Please return the public key for me to copy`

   ![Trae SSH key generation](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/backend/git-workflow/images/image18.png)

   После ввода подсказки вам также нужно нажать Enter в левом терминале, иначе команда будет ждать и не выполняться. Поскольку Trae не может помочь вам выполнить никакие условные суждения, мы просто продолжаем нажимать Enter.

   В конце вы увидите, что Trae справа вернул открытый ключ, который он прочитал. Вам просто нужно скопировать его и подготовить для вставки на следующем шаге.

   ![Trae SSH key output](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/backend/git-workflow/images/image19.png)

2. Ручное получение открытого ключа
   Откройте локальный терминал (используйте Git Bash или PowerShell на Windows; используйте Terminal на macOS/Linux), введите следующую команду (замените your_email@example.com на адрес электронной почты, который вы использовали при регистрации учетной записи GitHub):

   ```bash
   ssh-keygen -t ed25519 -C "your_email@example.com"
   ```

   1. Нажмите Enter для принятия значений по умолчанию (путь к файлу по умолчанию, без пароля или установленный по мере необходимости). Это создаст два файла в папке ~/.ssh/:
      - id_ed25519: закрытый ключ (сохранять локально, **никогда не делиться**);
      - id_ed25519.pub: открытый ключ (требуется загрузить на GitHub).

2. "Привязать" открытый ключ к вашей учетной записи GitHub

Это основной шаг привязки — добавить локальный открытый ключ в "SSH keys list" учетной записи GitHub:

1. Скопируйте содержимое открытого ключа:
   1. Trae:
   2. Windows: откройте C:\Users\<your>\.ssh\id_ed25519.pub в Блокноте и скопируйте все его содержимое;

3. Проверка успешности привязки

Введите следующую команду в терминал (**Trae также может выполнить следующую операцию**) для тестирования того, распознает ли GitHub ваше устройство:

```bash
ssh -T git@github.com
```

- Если вы видите что-то похожее на Hi [your GitHub username]! You've successfully authenticated..., это означает, что вы успешно привязали ключ;
- Если встречается ошибка, обычно это происходит потому, что копирование открытого ключа неполное, разрешения закрытого ключа слишком высокие (ваша локальная папка ~/.ssh/ должна быть доступна для чтения и записи только вами) и т.д. Проверьте эти проблемы по мере необходимости.

### Важные замечания

Если у вас несколько устройств (например, ноутбук и настольный компьютер), вам нужно создать отдельную пару SSH ключей для каждого устройства и привязать каждый открытый ключ к одной и той же учетной записи GitHub — у каждого устройства есть свой "пропуск доступа".

Никогда не делитесь вашим закрытым ключом (не загружайте на GitHub или не делитесь с другими), иначе кто-то может выдать себя за вас и работать с вашим репозиторием. Если закрытый ключ скомпрометирован, немедленно удалите соответствующий открытый ключ с GitHub и создайте новую пару ключей.

После привязки SSH используйте адрес репозитория в формате SSH (например, git@github.com:username/repository.git) для операций, а не формат HTTPS (например, https://github.com/username/repository.git). Если вы ранее клонировали репозиторий с помощью HTTPS, вы можете использовать git remote set-url origin `<new>` для переключения протокола.

# Использование Trae для операций GitHub

Мы объяснили, что такое Git, что такое GitHub, что такое SSH и как его настроить. Теперь вы можете свободно использовать Trae для выполнения операций Git. Сначала давайте научимся клонировать удаленный репозиторий на локальный компьютер.

## Git clone: загрузка существующего репозитория

Вы можете прямо сказать ему адрес репозитория, который вы хотите клонировать

![Git clone example](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/backend/git-workflow/images/image24.png)

## Git pull: получение обновлений из удаленного репозитория

Перед каждым обновлением репозитория, поскольку его может поддерживать несколько человек, вам нужно сначала получить последние изменения. После этого вы можете изменить и загрузить файлы.

**Помните, что нужно включить имя папки и относительный или абсолютный путь к ней, чтобы избежать загрузки в неправильный репозиторий.**

Подсказка: `Help me pull this repository AIID-TEST in ./AIID-TEST.`

## Git commit & Git push: промежуточное сохранение обновлений и загрузка на GitHub

После всех подготовок вы можете попробовать изменить локальный файл, добавить или удалить элементы в папке. Затем попросите Trae обнаружить изменения и помочь вам загрузить на GitHub.

Подсказка: `I finished. Commit and push to the repository AIID-TEST in ./AIID-TEST.`
