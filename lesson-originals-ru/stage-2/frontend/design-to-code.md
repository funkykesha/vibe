# От прототипа к коду проекта

> **Как превратить прототип из инструмента дизайна в реально работающий фронтенд-код?**

---

## 1. Три пути от прототипа к коду

После завершения дизайна интерфейса в Figma, MasterGo и других инструментах дизайна появляется естественный практический вопрос: как превратить эти выглядящие структурированными макеты в реально запускаемый в браузере фронтенд-код?

В целом, переход от прототипа к коду имеет три типичных маршрута:

| Маршрут | Метод | Особенности | Сценарий применения |
|--------|--------|--------|--------|
| **Маршрут 1** | Использовать многомодальную большую модель для прямого восстановления кода из изображения | Гибкий, не требует специального инструмента | Быстрая проверка прототипа, простые страницы |
| **Маршрут 2** | Через встроенные функции платформы или плагины экспортировать используемый код | Высокая точность восстановления, сильная редактируемость | Пользователи Figma/MasterGo |
| **Маршрут 3** | Платформа в комбинации с MCP экспортирует используемый код | Высокая степень автоматизации, настраиваемо | Требует глубокой интеграции рабочего процесса |

Этот раздел подробно представит конкретные методы реализации этих трёх маршрутов, помогая вам выбрать наиболее подходящий рабочий процесс в зависимости от требований проекта.

> **Предварительные знания**
> Перед началом этого раздела рекомендуется сначала изучить [Figma и MasterGo для начинающих](https://github.com/datawhalechina/easy-vibe/blob/main/docs/zh-cn/stage-2/frontend/figma-mastergo/index.md), овладеть базовыми операциями инструментов дизайна.

## 2. Маршрут 1: многомодальный AI для прямого восстановления кода

Большие модели с визуальными способностями изначально имеют способность превращать изображение в код. Нам нужно только направить скриншот макета прямо в диалоговое окно, затем дать большую модель для генерации полного результирующего кода.

### 2.1 Рабочий процесс операции

1. **Снять скриншот макета**
   - В Figma или MasterGo экспортируйте спроектированную страницу в PNG или JPG
   - Убедитесь, что скриншот содержит полный макет страницы

2. **Выберите многомодальную модель AI**
   - Можете использовать Gemini, Qwen, Claude и другие модели, поддерживающие ввод изображения
   - Здесь Gemini используется в качестве примера демонстрации

3. **Напишите подсказку**
   ```
   Пожалуйста, сгенерируйте соответствующий HTML/CSS код на основе этого макета.
   Требования:
   - Используйте современную CSS вёрстку (Flexbox/Grid)
   - Адаптивный дизайн, подходит для разных размеров экрана
   - Включите все видимые UI элементы
   - Цвета и размеры шрифта максимально соответствуют макету
   ```

![Пример AI](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/frontend/design-to-code/images/image42.png)

4. **Получите и сохраните код**
   - Попросите модель вернуть полный HTML код
   - Сохраните как один `.html` файл, удобно для локального тестирования
   - После этого можете в локальном IDE превратить в React и другие фреймворки

### 2.2 Распространённые проблемы и решения

Генерация страницы не простая задача, в процессе вы можете столкнуться со множеством проблем:

| Проблема | Решение |
|---------|---------|
| Неравномерная вёрстка интерфейса | Описать конкретную проблему вёрстки для AI, попросить отрегулировать margin/padding в CSS |
| Интерфейс не полностью отображается | Проверить правильную настройку viewport, попросить добавить адаптивные точки разлома |
| Неточное восстановление цветов | Использовать инструмент выбора цвета для получения точных значений цветов, передать AI |
| Несоответствие шрифтов | Указать конкретное название шрифта или попросить использовать Google Fonts подстановку |

> **Маленький совет**
> Рекомендуется сначала сгенерировать HTML код, после получения использовать локальный IDE для преобразования в React фреймворк. Так можно получить несколько независимых HTML файлов и единовременно преобразовать фреймворк.

### 2.3 Генерация страницы MasterGo AI

MasterGo также предоставляет мощную функцию генерации страницы AI, может прямо из реферейс изображения сгенерировать используемый веб-код.

#### Найти входную точку функции AI

В верхней панели инструментов интерфейса редактирования MasterGo можно найти кнопку инструмента AI:

#### Процесс генерации

1. **Загрузить реферейс изображение**
   - Используйте тот же способ, что и многомодальный AI, чтобы загрузить реферейс дизайна
   - Добавить описание требований текстом

2. **Посмотреть результат генерации**

![Результат 1](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/frontend/design-to-code/images/image48.png)

![Результат 2](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/frontend/design-to-code/images/image49.png)

3. **Получить код**
   - Щёлкнуть синюю кнопку "Insert to canvas", можно прямо редактировать сгенерированный веб-сайт
   - Или щёлкнуть кнопку "Code" справа, скопировать содержание кода в локальное хранилище

## 3. Маршрут 2: встроенные функции платформы или экспорт кода плагинами

### 3.1 Генерация кода Figma Make

Figma Make — это официальный инструмент AI Figma, способный согласно введённой пользователем подсказке или реферейс изображению с высокой точностью восстановить веб-прототип UI интерфейса.

#### Особенности функции

- **Высокая точность восстановления**: по сравнению с нативной генерацией AI кода результат лучше
- **Редактируемость**: результат генерации можно преобразовать в отредактируемый Figma Design файл
- **Интеграция GitHub**: поддерживает прямую синхронизацию кода в GitHub

> **Объяснение прав доступа**
> Использование полной функции Figma Make требует прав доступа Pro пользователя, студенты могут через сертификацию образования получить Pro права бесплатно.

#### Шаги операции

1. **Войти в Figma Make**
   - На главной странице Figma щёлкнуть кнопку Make
   - Или посетить [Figma Make](https://www.figma.com/make)

2. **Загрузить реферейс изображение**
   - Загрузить макет, который хотите восстановить, в диалоговое окно
   - Добавить подсказку описания требования

![Загрузка](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/frontend/design-to-code/images/image43.png)

3. **Посмотреть результат генерации**
   - Немного подождать, потом посмотреть результат рендеринга
   - Щёлкнуть кнопку воспроизведения в правом верхнем углу для полноэкранного предпросмотра

![Предпросмотр](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/frontend/design-to-code/images/image44.png)

4. **Деталь регулировки**
   - Щёлкнуть иконку редактора в правом верхнем углу (иконка мышки и линейки)
   - Вернуться в знакомый интерфейс Figma Editor для детальной регулировки

![Редактирование](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/frontend/design-to-code/images/image45.png)

5. **Экспорт кода**
   - После регулировки удовлетворённого результата выбрать экспорт кода
   - Можно напрямую подключиться к GitHub сохранить код

![Экспорт](https://raw.githubusercontent.com/datawhalechina/easy-vibe/main/docs/zh-cn/stage-2/frontend/design-to-code/images/image46.png)

### 3.2 Экспорт кода плагинами

Кроме встроенных функций AI платформы, Figma и MasterGo оба поддерживают экспорт кода через плагины:

**Распространённые Figma плагины:**
- **Figma to Code**: превращает макет в React, Vue, HTML и др. код
- **Anima**: генерация высокоточного кода, поддерживает эффекты взаимодействия
- **Locofy**: управляемый AI инструмент превращения дизайна в код

**Шаги использования:**
1. Открыть панель плагина в Figma (Plugins)
2. Найти и установить нужный плагин экспорта кода
3. Выбрать элементы дизайна которые нужно экспортировать
4. Запустить плагин, выбрать целевой фреймворк и формат кода
5. Скопировать или загрузить сгенерированный код

## 4. Маршрут 3: экспорт кода платформой в комбинации с MCP

### 4.1 Что такое MCP?

MCP (Model Context Protocol, протокол контекста модели) — это открытый стандартный протокол, позволяющий модели AI безопасно и контролируемо получать доступ к внешним инструментам и источникам данных. В сценарии инструментов дизайна фронтенда MCP позволяет большой модели напрямую читать структуру, стили и информацию компонентов файла дизайна, что дальше точнее генерирует код.

### 4.2 Принцип работы MCP

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   Модель AI │ ←→  │  Сервер MCP │ ←→  │  Инструмент │
│  (Claude)   │     │  (адаптер)  │     │  дизайна    │
└─────────────┘     └─────────────┘     └─────────────┘
```

**Рабочий процесс:**
1. Модель AI через протокол MCP отправляет запрос инструменту дизайна
2. Инструмент дизайна возвращает структурированные данные дизайна (слои, стили, компоненты и т.д.)
3. Модель AI понимает структуру дизайна и генерирует соответствующий код
4. Код может быть прямо экспортирован или синхронизирован в окружение разработки

### 4.3 实战：Figma + MCP

#### Подготовка окружения

1. **Установить сервер MCP**
   ```bash
   # Используйте npx для установки Figma MCP сервера
   npx figma-mcp-server
   ```

2. **Настроить Claude Desktop или другой инструмент поддерживающий MCP**
   ```json
   {
     "mcpServers": {
       "figma": {
         "command": "npx",
         "args": ["figma-mcp-server"],
         "env": {
           "FIGMA_ACCESS_TOKEN": "your-figma-token"
         }
       }
     }
   }
   ```

3. **Получить Figma Access Token**
   - Войти в Figma → Settings → Personal Access Tokens
   - Сгенерировать новый Token и сохранить

#### Рабочий процесс использования

1. **Включить MCP соединение в инструменте AI**
   - Открыть Claude Code или другой IDE поддерживающий MCP
   - Убедиться, что сервер MCP подключен

2. **Передать ссылку файла дизайна**
   ```
   Пользователь: Пожалуйста помогите мне превратить этот Figma дизайн в React код
   Ссылка: https://www.figma.com/file/xxxxx
   
   AI: Я подключился к Figma через MCP, считываю структуру файла дизайна...
   ```

3. **AI автоматически анализирует и генерирует код**
   - Сервер MCP получает дерево слоёв файла дизайна
   - AI понимает структуру компонентов и атрибуты стиля
   - Генерирует React/Vue компоненты с правильным названием и структурой

4. **Итеративная оптимизация**
   ```
   Пользователь: Пожалуйста, выделите компонент кнопки как отдельный переиспользуемый компонент
   
   AI: Хорошо, я через MCP идентифицировал компонент Button в системе дизайна,
       генерирую React компонент с интерфейсом props...
   ```

### 4.4 Преимущества MCP

| Особенность | Традиционный способ | Способ MCP |
|---------|---------|---------|
| **Точность данных** | Опирается на скриншот, может потерять детали | Прямой доступ к исходным данным дизайна |
| **Идентификация компонента** | AI нужно угадать границы компонента | Точное получение определения компонента |
| **Восстановление стиля** | На основе пиксельных оценок | Получение точных дизайн-token |
| **Эффективность итерации** | Каждое изменение нужно переснять скриншот | Синхронизация изменений дизайна в реальном времени |
| **Степень автоматизации** | Ручное копирование и вставка | Можно прямо писать в файлы проекта |

### 4.5 Доступные в настоящий момент MCP инструменты

**MCP для инструментов дизайна:**
- **Figma MCP Server**: официальная поддержка MCP реализация
- **MasterGo MCP**: адаптер MasterGo разработанный сообществом

**MCP для окружения разработки:**
- **Claude Code**: родная поддержка протокола MCP
- **Cline**: VS Code плагин, поддерживает соединение MCP
- **Trae**: может через настройку включить функцию MCP

> **Будущее развитие**
> Протокол MCP быстро развивается, в будущем интеграция инструментов дизайна и окружения разработки будет более плотной. Прогнозируется появление решений с одной кнопкой синхронизации дизайна в код, дальнейшее сокращение дистанции между дизайном и разработкой.

## 5. Работа после экспорта кода

### 5.1 Локальное тестирование

После получения кода выполните тестирование в локальном IDE:

1. **Создание нового проекта**
   ```bash
   # Если это HTML файл, напрямую откройте в браузере
   open index.html
   
   # Если это React/Vue проект
   npm install
   npm run dev
   ```

2. **Сотрудничество с AI IDE**
   - Импортируйте сгенерированный код в Trae или другой AI IDE
   - Дайте AI помочь исправить проблемы вёрстки, добавить функции взаимодействия

### 5.2 Обработка распространённых проблем

| Стадия | Проблема | Решение |
|--------|---------|---------|
| Вёрстка | Неправильное расположение элементов | Проверить атрибуты display и position в CSS |
| Стили | Неточное восстановление цветов | Использовать браузер инструменты разработчика проверить применяемые значения цветов |
| Адаптивность | Ошибка отображения на мобильном | Добавить точки разлома media query |
| Взаимодействие | Кнопка не реагирует | Проверить привязку событий JavaScript |

## 6. Сравнение и предложения по выбору трёх маршрутов

### 6.1 Сравнение маршрутов

| Измерение | Маршрут 1: многомодальный AI | Маршрут 2: встроенные функции платформы | Маршрут 3: MCP |
|--------|---------|---------|---------|
| **Сложность начинания** | ⭐ Легко | ⭐⭐ Средне | ⭐⭐⭐ Сложно |
| **Точность восстановления** | ⭐⭐⭐ Средняя | ⭐⭐⭐⭐ Высокая | ⭐⭐⭐⭐⭐ Максимальная |
| **Гибкость** | ⭐⭐⭐⭐⭐ Высокая | ⭐⭐⭐ Средняя | ⭐⭐⭐⭐ Довольно высокая |
| **Степень автоматизации** | ⭐⭐ Низкая | ⭐⭐⭐ Средняя | ⭐⭐⭐⭐⭐ Высокая |
| **Стоимость** | Низкая (по использованию API) | Средняя (может требоваться Pro версия) | Низкая (открытые инструменты) |

### 6.2 Предложения по выбору

**Выбирайте Маршрут 1 (многомодальный AI) если:**
- Нужна быстрая проверка идеи
- Инструменты дизайна не фиксированы, часто переключаетесь
- Требования к точности восстановления не высокие
- Бюджет ограничен

**Выбирайте Маршрут 2 (встроенные функции платформы) если:**
- Команда в основном использует Figma или MasterGo
- Нужна высокая точность восстановления кода
- Дизайнеры и разработчики часто сотрудничают
- Готовы инвестировать в Pro версию

**Выбирайте Маршрут 3 (MCP) если:**
- Ищите максимальную степень автоматизации
- Есть технические навыки для настройки MCP окружения
- Проект требует частой итерации дизайна в код
- Хотите создать стандартизированный рабочий процесс дизайн-разработки

## 7. Итоги

Через изучение этого раздела вы овладели тремя основными маршрутами превращения прототипа в код:

1. **Многомодальный AI для прямого преобразования**: гибкий и быстрый, подходит для проверки прототипа
2. **Встроенные функции платформы**: высокая точность, подходит для профессионального рабочего процесса дизайна
3. **Интеграция MCP**: максимальная степень автоматизации, представляет будущее тенденцию

> **Лучшие практики**
> - **Для новичков**: начните с Маршрута 1 (многомодальный AI), быстро приступите
> - **Командная работа**: используйте Маршрут 2 (встроенные функции), обеспечьте консистентность дизайна
> - **Приоритет эффективности**: попробуйте Маршрут 3 (MCP), создайте автоматизированный рабочий процесс
> - **Смешанное использование**: по этапам проекта гибко переключайтесь между маршрутами
